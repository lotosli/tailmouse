## Why

TailMouse currently has an engineering harness and accepted high-level specifications but no product implementation. PRD v1.0 defines a complete P0 product: a single native `tailmouse` executable, a static mobile-first PWA, a Tailcat-backed encrypted byte stream, the TMOUSE/1 session protocol, the `escape` game, the `leash` PTY controller, and cross-platform release evidence. Implementing those pieces as one traceable change makes the PRD the delivery baseline and prevents milestone-by-milestone reinterpretation.

The measurable outcome is a PRD-conformance matrix with every P0 requirement linked to passing unit, integration, browser, impairment, security, build, or manual acceptance evidence on its applicable platforms.

## What Changes

- Build the native Go CLI with the exact PRD commands, configuration precedence, exit behavior, invitation/QR flow, structured logging, session lifecycle, and embedded Tailcat server adapter.
- Compile the single read-only Tailcat submodule revision into both the native executable and the browser Go/Wasm transport. Do not invoke or ship the upstream Tailcat CLI.
- Define and implement MouseCard v1 and TMOUSE/1 in Go and TypeScript with strict limits, version negotiation, shared golden fixtures, fuzzing, flow control, reconnect behavior, and secret redaction.
- Build the static Preact/Vite PWA with in-memory invitation handling, Tailcat Wasm loading, capability policy, CSP, offline static assets, mobile accessibility, and a narrow `ByteStream` adapter around `tailcatDial`.
- Implement `escape` as a host-authoritative 30 Hz game with five deterministic solvable maps, bounded 20 Hz input, 10 Hz snapshots, RTT-shaped scent pursuit, touch/tilt controls, prediction/reconciliation, terminal spectator output, and the PRD's win/loss/reconnect rules.
- Implement `leash` with one explicitly launched command, Unix PTY and Windows ConPTY/Job Object boundaries, local terminal mirroring, bounded output/scrollback, xterm browser rendering, ordered input, resize, readonly, interrupt, terminate, restart, reconnect, and reliable cleanup.
- Add hermetic Tailcat/DERP integration, browser end-to-end, network impairment, security, cross-platform, packaging, checksum, SBOM, and PRD-conformance verification.
- Deliver in the PRD order M0 transport spike, M1 protocol/session, M2 escape, M3 Unix leash, M4 Windows leash, and M5 release hardening. A milestone closes only when its tasks and required current-scope evidence pass, or when an owner-deferred environment leg is explicitly recorded as unverified without creating a platform runtime claim.

Material decisions:

- **Tailcat upstream compatibility monitor:** A separate weekly/manual Linux workflow tests the latest Tailcat `main` in its disposable CI checkout without changing the parent gitlink. It runs upstream module verification, tidy diff, vet, tests, native build and Web/Wasm distribution build, then derives disposable module metadata from the tracked files and compile-checks the complete TailMouse CLI package tree against that candidate in readonly mode. The tracked module files and parent gitlink must remain unchanged. Read-only repository permissions, detached checkout, fail-fast shell execution and absence of publication/update steps keep this a compatibility signal rather than an automatic dependency update. The ordinary release gate continues to require the exact recorded gitlink. This satisfies PRD risk R1 without a bot, updater, compatibility layer, new dependency or Tailcat source change.

- **Owner-directed verification scope, 2026-09-06:** Native macOS is the only host-runtime acceptance required for the current v1 development cycle. Linux and Windows implementation remains in product scope and must retain cross-compilation, static-analysis, packaging, and explicit platform-specific tests, but native execution is deferred until the owner provides matching environments. Current completion records those legs as `deferred / not verified`; it neither blocks macOS-scoped software completion nor claims a Linux or Windows runtime pass. Official multi-platform release acceptance still requires the deferred evidence before making those platform claims.

- The Leash network probe applies a three-second test-only backoff after visible `SESSION_BUSY`, while retaining its 60-second total recovery window, 80-attempt safety bound and the product's unchanged 30-second peer-liveness and ten-second handshake limits. Under the 80 ms RTT / 64 Kbit/s profile, the prior one-second loop reproduced fresh-stream timeouts twice with 17-18 busy results; an instrumentation-only rerun narrowly passed after 20. Those repeated Tailcat handshakes share the constrained relay and can delay packets already scheduled for the fenced owner. Backoff is the smallest correction because `SESSION_BUSY` proves the previous owner is still authoritative; malformed, terminal and unexpected failures still stop immediately, and handshake timeouts retain their existing explicit retry. The corrected exact profile passes twice in 52.04 and 51.74 seconds with six busy results each. No automatic product retry, product deadline, dependency, Tailcat source or Host authority rule changes.

The complete smoke suite's aggregate test-process budget increases from three to four minutes because the first integrated run passed in 169.352 seconds after adding the 20-second case; every product and individual-scenario deadline, fail-fast boundary and network assertion remains unchanged.

No Web runtime dependency, new workspace, Tailcat edit or protocol change is introduced. This removes one release inventory gap, not all license obligations or the owner's separate project-license decision.

- The owner-approved transport-truncation correction distinguishes an interrupted established stream from a complete invalid frame. The decoder still rejects every incomplete header, envelope or payload without dispatch and retains the existing strict handshake failure. After successful HELLO/WELCOME only, the session treats a decoder-observed EOF or transport read failure within a frame as connection loss: close that stream, discard partial bytes and connection-local input, release its lease, and permit a user-initiated fresh-stream handshake under the unchanged TTL, grace and capability rules. Browser invitation material may remain only in the existing in-memory retry path. No automatic retry, old-input replay, longer deadline, new wire error, dependency or Tailcat change is introduced. Complete malformed frames, invalid routes, oversized declarations and peer protocol errors remain terminal. Keeping all truncation terminal was rejected because the existing native write deadline can legitimately end a blocked terminal-output frame; making every BAD_FRAME retryable would weaken validation. The distinction is local decoder provenance, never a peer-controlled retry hint or error-message match.

- The Windows process waiter also observes the owned job after root exit. Only an empty job permits normal pseudoconsole closure; the output reader continues draining until EOF. This breaks ConPTY's documented handle-lifetime cycle without killing still-running descendants or requiring Windows 11 24H2's newer ReleasePseudoConsole API. - Windows explicit Interrupt uses a fixed Win32-input-mode Ctrl+Break press/release sequence on the owned ConPTY input channel. ConPTY dispatches it as a native control event even when the child disables processed input; a child may handle and ignore that event without being terminated or retried. Ordinary local Ctrl+C remains byte `0x03`, preserving the child's processed/raw input mode and the owner's existing two-interrupt policy. A cancellable single-writer token prevents a control sequence from interleaving with a pump chunk and cancels queued writers on final Close. Explicit control delivery has a two-second bound, including writer admission; a blocked pipe fails visibly rather than silently converting Interrupt into Terminate. Direct `GenerateConsoleCtrlEvent` cannot address a separate console, and AttachConsole/helper-process approaches add unnecessary global state or processes. No output parsing, Windows API code copying, wire field, dependency or new public option is required.
- After successful explicit interrupt delivery, the CLI returns a surviving process generation to `running`, as PRD 9.11 requires. If its `interrupting` acknowledgment has not yet left the existing state slot, the concrete session binding retains one immutable acknowledgment snapshot ahead of the latest coalesced state. A frame already selected by the sole sender needs no extra retention; stream order preserves it. New generation/pump snapshots, stream replacement and detach discard the retained acknowledgment. The browser's current pending-control rules remain strict: an arbitrary running frame may predate the request and cannot acknowledge it. This fixes the prior indefinitely interrupting presentation without losing the confirmation boundary, adding a general queue, changing wire fields, or adding a timer, worker or dependency.
- Queued process controls recheck the current process state as well as lease and generation immediately before execution. - The Windows local Leash console preserves native keyboard records through ConPTY's existing Win32-input-mode encoding, including UTF-16 units, modifiers, releases and repeat counts. - Windows local I/O uses non-inheritable duplicate handles so cleanup and any overlapped-I/O deadlines belong to TailMouse, without closing the caller's streams. Private overlapped handles instead use their own deadlines. Go's existing console writer preserves split UTF-8 and performs native Unicode output, avoiding a second decoder or global codepage changes. - Unix process ownership covers the original session-leader group and every separate foreground job group observed through its controlling PTY. Interrupt still uses `TIOCSIG` so the kernel resolves the current target atomically; it also remembers the already session-validated group for later cleanup. Terminate captures the current foreground group, sends SIGTERM to remembered jobs before the leader group, observes every group for at most five seconds, then sends SIGKILL and waits for both the original child result and group disappearance before closing the PTY master. A group that outlives its leader remains owned; a numeric ID that reappears in another session is rejected. This fixes the ordinary interactive-shell job-control gap without a process-table scanner, supervisor, helper process, dependency or new option. A descendant that deliberately creates an unrelated session is outside the portable PTY/process-group boundary selected by the PRD's Unix mechanism.
- Unix forced cleanup retains the PTY master until the original child's bounded wait and remembered-group observation complete, then closes the descriptor. A native race regression observed SIGHUP (129) winning when master closure immediately followed an asynchronous SIGKILL. ## Simplicity Budget

- **SBOM verification:** Emit CycloneDX 1.7 from the verified compiled-module inventories and inspect native archives with Go's standard archive readers. Pin the official CycloneDX CLI 0.33.1 as a release-only schema validator; its embedded schemas avoid another JavaScript validation framework or a vendored schema tree. It adds no product runtime dependency, service, signing or publication. Per-artifact identities, file hashes and explicitly scoped relationships are checked independently of schema validity; unknown internal dependency edges are not represented as empty dependency lists. The archive reader does not extract files and bounds entry count, names and decompressed bytes.
- **Workspace:** No new workspace. `apps/cli` remains the Go composition root and `apps/web` remains the only JavaScript workspace; the alternative of splitting modes or protocol packages into publishable workspaces has no current deployment consumer.
- **Tailcat dependency:** Existing read-only submodule and Go workspace; required for every connection scenario. Reimplementation or an external executable would violate single-install and browser requirements.
- **Native release tool:** PRD 18.1 already requires GoReleaser; pin its verified current stable 2.18.0 CLI in tooling metadata, outside product Go dependencies. Its standard builder and archive pipeline own the six-target matrix. The Node wrapper reuses existing source/gitlink identity checks, verifies emitted binary metadata and native-host version output, and restricts the local command to non-publishing snapshots. It does not implement an archiver or publishing framework. Snapshot evidence does not waive clean-source, SBOM, license, native-device or publication requirements; see `docs/development/gates.md`.
- **CBOR libraries:** One Go and one browser decoder/encoder are required for MouseCard interoperability. A handwritten general CBOR implementation is less safe; only the fixed schema surface will be exposed.
- **QR encoder:** One native Go dependency is required for the terminal invitation. Hand-authoring QR error correction is out of scope and unsafe.
- **PTY/platform packages:** One Unix PTY dependency plus official Go platform packages are required by the real TUI and cross-platform cleanup scenarios. Shell pipes cannot satisfy terminal emulation, resize, signals, or process-tree behavior.
- **xterm packages:** The terminal renderer and only the PRD-required fit/canvas facilities are required for ANSI/TUI browser acceptance. Building a terminal emulator is not a simpler alternative.
- **Browser component coverage:** Add only the official `@vitest/browser-playwright` provider matching Vitest 4.1.11 and an explicit peer on the already-used Playwright 1.62.1 engine, as development dependencies. Real Canvas/DOM/permission controls in tasks 3.6-3.7 need covered component tests, not mocked Preact hooks or a handwritten DOM. Node suites and one headless Chromium component project share the existing Vitest coverage thresholds; the existing five-profile Playwright suite still checks the built product. A separate DOM emulator, renderer test framework or test service adds no necessary consumer.
- **Configuration surface:** Only documented CLI flags, environment variables, TOML fields, MouseCard, TMOUSE/1, and static build metadata. No generic configuration framework.
- **Abstractions:** Tailcat server/byte-stream adapters, the OS PTY boundary, and language-neutral protocol fixtures are justified volatile, security, and platform boundaries. Mode logic otherwise uses concrete functions and state.
