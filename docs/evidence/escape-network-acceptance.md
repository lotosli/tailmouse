# Escape network acceptance

Status: **heartbeat-aware complete suite passed**, verified on 2026-09-04. The full gate includes all 109 profiles, three outages, fresh-stream reconnect and actual DERP socket closure. Later shared-fixture edits still require regression verification. Physical-device and cross-platform acceptance remain separate release requirements.

## Method

- **Observed, 2026-09-03:** The test starts the real native Tailcat adapter and production Escape host against an upstream loopback DERP server, then loads the built PWA and recorded Tailcat Wasm in isolated Chromium. Invitations travel only through child stdin and in-memory browser navigation; no trace, screenshot, argument, report or diagnostic records them.
- A build-tagged fixture shapes complete encrypted `FrameSendPacket` payloads in both directions, using the upstream DERP codec/server. It does not mock `tailcatDial`, drop bytes from a TCP stream, modify Tailcat or change machine-wide networking.
- RTT is added round-trip propagation delay. Each direction adds half that value plus deterministic variation within half the configured jitter, clamped at zero. Loss discards the configured fraction of complete packets; outages also discard packets already waiting for delivery. Bandwidth is decimal Kbit/s per direction, with serialization independent of propagation delay. Each queue is bounded to 128 frames and overflow fails the connection. Counts, drops and actual delivery delays prove that both directions use the fixture.
- Measured app-level RTT includes the real TLS/WebSocket/WireGuard/inner TCP path, retransmission, serialization and scheduling. It is not asserted to equal the configured propagation delay, particularly at 64 Kbit/s with loss.
- The matrix covers all 108 combinations of RTT 20/80/150/300 ms, jitter 0/20/60 ms, loss 0/1/5%, and bandwidth 64/256/1024 Kbit/s, plus the explicit 150/30 profile. It rotates through all five maps. Every case checks rendered mouse feedback within 150 ms, a held intent reaching host authority, three measured steady-state traffic windows below 20 KiB/s including TMOUSE framing, bounded queues, valid host collision cells, reachable map goals, live RTT, protocol health and explicit exit.
- Held-movement delivery has a ten-second test liveness bound and its actual latency is recorded. This includes reliable-stream recovery and the post-gap PONG boundary; it is not a product responsiveness guarantee or the PRD's three-second host input-silence deadline. Local feedback and separate host stop/pause/grace checks retain their existing bounds.
- Separate real-stream cases cover 300 ms and 3 s outages, a 31 s outage crossing the 30 s input-silence boundary, and user-initiated reconnect on a fresh stream. The long-outage case asserts the Host's unchanged connection_lost deadline separately from network recovery. PRD 7.4 can close the silent stream before result delivery; the browser must expose loss, discard movement controls and receive EXPIRED on a fresh handshake. The still-valid invitation cannot revive the ended round. This is distinct from the later default reconnect grace on sessions whose mode has not already ended.
- A separate DERP-disconnect case closes both established underlying transports, keeps the relay listener available, and requires each side's connection counter to advance before accepting resumed packets, heartbeats and fresh user input as recovery. It preserves round/map identity and records whether recovery retained the application stream or used the visible one-shot Retry action. It neither mocks a stream error nor substitutes packet loss for socket closure; a fixture test independently proves peer EOF and joined packet workers.
- Impaired shutdown tests distinguish acknowledged application completion from delivery of the final TCP ACK. The PRD requires a bounded two-second `DrainTCP` followed by `Server.Close`; it does not guarantee loss-free ACK delivery. An exact reported `ErrDrain` is an exercised failure path, not hidden graceful success: the test still requires the backend close to succeed within the bound, the address to become inaccessible and repeated close to preserve the same error. Browser exit likewise requires bounded completion with either success or an explicit close-failure message, and no retained invitation, retry or mode controls. Unimpaired hermetic tests continue to require successful immediate drain.
- With deliberate packet loss, the native application's final CLOSE/EOF can also miss its existing two-second deadline. Only the exact reported `session.ErrShutdown` is an expected impaired failure path, and only when loss is configured. The fixture separately requires bounded return, revoked authority/capabilities and unchanged repeated-close outcome before transport cleanup. Loss-free cases remain strict. Deterministic host tests with a blocked CLOSE write or missing acknowledgement prove the two-second failure, joined workers, erased identity, closed peer, refusal of new connections and preservation of the first outcome.

## Regressions discovered

**Observed, 2026-09-03:** The first real 300 ms outage replayed an old direction after recovery. The browser's latest-only pending queue was not sufficient because successful writes could still be buffered inside TCP.

The native Escape binding now uses the existing regular PING/PONG as a post-gap ordered-stream boundary. Stale movement cannot refresh input age; stale dash requests receive explicit rejection. Validated PONG drains prior input but does not postpone stop, pause or grace. A drain confirmation expires after 150 ms without new input so that a second outage cannot reuse it. This changes neither the wire format nor the one-hertz cadence. Fake-time/race tests cover old and malformed PONGs, stale movement/dash, receipt deadlines, fresh resumption, repeated gaps and fresh connections.

**Observed, 2026-09-03:** A transport close failure was incorrectly classified as retryable even after explicit browser exit. Exit intent now overrides retry classification while preserving the safe failure message. Five-profile browser tests prove invitation disposal, removal of retry/movement controls and no credential recovery after reload.

**Observed, 2026-09-03:** A later full gate failed the original three-second held-movement delivery assertion at RTT 300 ms, 5% loss and 64 Kbit/s. Repeated isolated runs reproduced it. A diagnostic run retained the three-second failure and observed the same held intent arriving at 4.095 seconds, with browser focus intact and measured application RTT about 1.87 seconds. The test had conflated end-to-end liveness with the PRD's host receipt-silence clock. Only that test wait changes to ten seconds, with measured latency and bounded timeout diagnostics. No production timer, input-freshness rule or impairment profile changes; the required full rerun subsequently passed as recorded below.

## Reproduction

Run `pnpm test:escape-network` for the complete suite. `pnpm gate:quick` includes scheduler tests and the 150/30 real-chain smoke case; `pnpm gate` additionally requires the complete network suite. To inspect per-profile measurements, build first and run `go test -tags=tailcatintegration -count=1 -failfast -timeout=35m -v -run=TestEscapeNetwork ./apps/cli/internal/transport/tailcat`.
