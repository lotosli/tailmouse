## 1. 产品结论与范围

### 1.1 一句话定位

**TailMouse 是基于 Tailcat 的临时资源分享工具：分享端执行一条命令，访问者打开一个链接，就能在浏览器里操作指定终端、使用指定 Web 应用、向指定目录上传文件，或在同一个开发会话中组合使用这些能力。**

产品坚持零注册、分享端单边安装、访问端浏览器零安装。用户不需要加入 Tailnet、部署完整 VPN、配置路由器端口转发或管理一套账号体系。

“一条命令、一条链接”描述主要使用流程；用户仍需具备目标资源的访问权限，分享端需要持续运行，双方网络需要允许访问前端与所选 DERP。不可宣传为任何网络下都能连接。

### 1.2 固定的四项能力

| 命令 | 分享的资源 | 浏览器可做的事 | 核心边界 |
|---|---|---|---|
| `cli` | 一个明确启动的 CLI 程序 | 查看终端输出；经授权发送输入 | 程序以分享者的系统权限运行，默认不提供沙箱 |
| `web` | 一个明确指定的 HTTP(S) 上游 | 在支持范围内使用 Web 应用 | 不提供任意内网地址输入框，不成为通用出口代理 |
| `receive` | 一个明确指定的接收目录 | 选择或拖入文件，上传至该目录 | 单向上传；无目录浏览、已有文件读取或删除权限 |
| `dev` | CLI、Web、Receive 中至少两项 | 在同一会话内切换终端、预览和上传 | 复用前三项能力，不引入新的传输协议或账号体系 |

`dev` 是重点展示的组合入口，另外三个命令可以独立使用。四个命令均进入 v1.0 产品范围，不把 `dev` 留成没有交互和验收定义的占位功能。

### 1.3 产品原则

- **分享具体资源。** 启动时明确程序、上游地址、接收目录；没有隐式整机访问或自动扫描。
- **按任务建立会话。** 默认临时、可撤销、具有明确的结束状态，不做常驻设备管理。
- **统一通道和体验。** 四个命令共用 Tailcat、会话认证、连接状态、错误体系和前端组件。
- **授权在分享端执行。** 页面隐藏按钮不能替代权限校验；浏览器声明的权限不可信。
- **兼容性诚实。** Web Bridge 按验证等级发布，不承诺任意网页、任意网络或任意浏览器完全兼容。
- **先验证任务收益。** 功能完整、使用 Tailcat、零注册均不能直接作为独有竞争优势。

### 1.4 明确不做

v1.0 不提供账号、组织、RBAC 企业控制台、远程桌面、全盘文件管理、长期设备发现、任意 TCP/UDP 浏览器代理、云端文件仓库、公网反向代理 SaaS、AI Agent 自身的规划执行系统。

不保留早期 `escape` / `leash` 命令，不加入游戏入口。不为了差异化增加第五个产品命令。

不把纯 WebRTC 或公网明文 HTTP Gateway 作为默认路线或自动兜底。WebRTC 仅作为未来 Tailcat 浏览器传输适配的研究方向，见第 21 节。

### 2.6 品牌表达约束

可以使用猫与鼠的轻量品牌元素，但不使用游戏化流程承载授权、断线或文件校验等关键状态。工具界面保持克制，错误信息优先清楚。

不使用以下承诺：`Always P2P`、`Works on every network`、`Unlimited transfer`、`100% anonymous`、`Secure sandbox`、`Share any website perfectly`、`No servers required`。

“Encrypted”必须指明浏览器到分享端的边界。分享端转发至远程 HTTP 上游时，该后续网络段没有自动获得 HTTPS 加密。前端分发的信任边界见第 15 节。

## 3. 目标用户、场景与竞争假设

### 3.1 目标用户

主要面向个人开发者、需要临时协作的开发团队成员、平台工程与技术支持人员。AI Coding 用户是自然适用人群，但产品不绑定某一款 Agent 或模型。

接收者可以是开发者、测试人员、设计师或业务同事；不要求他们理解 VPN、SSH、端口映射或 Tailcat。

### 3.2 首要场景：临时开发协作

分享者启动 CLI 与开发服务，给同事一个链接。同事打开页面验证问题，把复现所需的数据文件上传至约定目录；分享者或获授权的同事操作终端，修改或处理数据，然后继续通过同一预览页面验证。协作结束后，分享者撤销整个会话。

完整任务的成败优先于单个功能的存在。重点减少环境准备、找文件路径、切换多个工具、重复建立连接等操作。

### 3.3 独立使用场景

| 用户故事 | 对应命令 | 完成标志 |
|---|---|---|
| 我希望在手机上继续操作电脑上的指定 CLI | `cli` | 手机可输入必要按键、看到输出，断线后不会重复启动程序 |
| 我希望让同事查看本机或内网开发服务 | `web` | 对方能完成真实页面操作，而非只看到首页截图 |
| 我希望临时从对方设备收取日志或测试数据 | `receive` | 文件校验完成并安全写入指定目录，对方不能浏览其他文件 |
| 我希望围绕同一个问题同时使用终端、预览和上传 | `dev` | 三项资源共享会话与状态；上传完成后能够方便地引用文件 |

### 3.4 竞争事实与假设

BitBang 的公开文档已经列出浏览器终端、Web 代理、文件上传以及运行中 tmux 会话分享等能力。因此不能将这些能力本身或浏览器零安装称为 TailMouse 独有优势。[S09]

TailMouse 当前的竞争假设是：**在特定的临时开发协作任务中，提供更少的准备步骤、更清楚的资源边界和更顺畅的终端—预览—上传联动。** 这些是待验证的目标，不是已经证明的结论。

Tailcat 是技术约束与生态选择，不能单凭使用它推导性能、安全性或可用性优于其他实现。

## 4. 四个命令与命令行规范

### 4.1 主要用法

```bash
# 分享指定 CLI：只启动一次，后续浏览器接入同一个会话。
tailmouse cli -- codex

tailmouse cli -- htop

tailmouse cli -- bash

# 分享本机 Web 服务。
tailmouse web 8080

tailmouse web localhost:8080

# 非本机上游需要明确授权。
tailmouse web --allow-remote 192.168.1.10:8080

tailmouse web --allow-remote https://app.example.com:8443/admin

# 浏览器向指定目录上传；目录需已存在。
tailmouse receive ./uploads

# 组合终端、Web 和上传。-- 后是 CLI 的完整 argv。
tailmouse dev --web 5173 --receive ./uploads -- codex

# 仅需无参数程序时的简写。
tailmouse dev --cli codex --web localhost:5173 --receive ./uploads

# Web + 上传也是合法组合，不会隐式启动 shell。
tailmouse dev --web 8080 --receive ./uploads
```

`--cli <executable>` 仅表示一个程序名或路径，不解析 shell 字符串。需要程序参数时使用 `-- <program> <arg...>`。两种形式互斥。

`dev` 必须启用至少两项资源；只有一项时提示对应独立命令。v1.0 每个会话最多一个 CLI、一个 Web 上游、一个 Receive 目录。多 Web 上游留到 P2。

### 4.2 公共参数

以下参数均为 TailMouse 设计，具体上游 Tailcat 配置由适配层转换。

| 参数 | 默认值 | 语义 |
|---|---|---|
| `--ttl <duration>` | `1h` | 会话从启动成功起的绝对有效期；`0` 表示显式选择持续至主动结束 |
| `--title <text>` | 按命令生成 | 浏览器展示的会话名称，按纯文本处理 |
| `--approval auto\|manual` | `auto` | 有效链接自动接入，或由分享端逐次批准新访问者 |
| `--max-clients <n>` | `1` | 同时有效的浏览器成员上限；v1.0 范围为 1–4 |
| `--open` | 关闭 | 启动后在分享端打开分享链接；不自动授予管理权限 |
| `--json` | 关闭 | 输出结构化事件；不得与本地交互式 PTY 输入模式混用 |
| `--derp-map <path-or-https-url>` | 使用锁定 Tailcat 版本的默认配置 | 指定自建 DERP map；本地配置由 CLI 解析，不能要求浏览器读取本机路径 |
| `--derp-region <id>` | 自动选择 | 在所选 map 中指定区域 |
| `--verbose` | 关闭 | 输出脱敏诊断；不得打印正文、按键或凭据 |

示例：

```bash
tailmouse cli --ttl 30m --approval manual -- codex

tailmouse receive --ttl 15m --max-file-size 100MiB ./uploads

tailmouse dev --cwd ./my-app --web 5173 --receive ./uploads -- codex
```

### 4.3 各命令参数

| 命令 | 参数 | 说明 |
|---|---|---|
| `cli` | `--cwd <directory>` | 子进程工作目录，默认当前目录 |
| `cli` | `--read-only` | 所有访客只能查看终端；分享者本地仍可操作 |
| `web` | `--allow-remote` | 允许明确指定的非 loopback 上游，不扩大到任意地址 |
| `web` | `--ca-file <path>` | 为该 HTTPS 上游增加信任根，不关闭证书校验 |
| `receive` | `--max-file-size <size>` | 单文件上限，默认 `256MiB` |
| `receive` | `--max-total-size <size>` | 本次会话上传预算，默认 `1GiB`，取消与失败不会无限补回已消费流量预算 |
| `receive` | `--max-files <n>` | 会话内文件创建尝试上限，默认 `100` |
| `dev` | `--cli <executable>` | 无参数程序简写，与 `-- <argv...>` 互斥 |
| `dev` | `--web <target>` | Web 上游，解析规则与 `web` 相同 |
| `dev` | `--receive <directory>` | 接收目录，相对路径以 `--cwd` 为基准 |
| `dev` | `--cwd <directory>` | CLI 工作目录及相对接收路径基准 |
| `dev` | `--cli-read-only` | 仅限制终端访客输入，不代表 Web 或上传只读 |
| `dev` | Web / Receive 对应参数 | 复用 `--allow-remote`、`--ca-file`、上传限制等，不产生另一套语义 |

容量单位须严格解析：支持明确的 `KiB/MiB/GiB` 和 `KB/MB/GB`，输出统一使用 IEC 单位，不能混用数值。

不提供默认跳过 TLS 验证的开关；自签名场景使用明确的信任根。高级认证、更多目标重写参数进入后续兼容需求评审。

### 4.4 参数与进程安全

所有参数必须在创建公开邀请前完成静态校验。运行命令使用 argv 数组，默认不经过 `sh -c`。需要 shell 语义的用户必须显式执行，例如 `tailmouse cli -- bash -lc '...'`。

启动时检查程序存在、目录可访问、目标 URL 合法、证书配置合法、限制参数有效。检查不得产生自动扫描、任意目录创建或未经用户声明的网络访问。

`web` 的连通性预检只做解析和 TCP/TLS 建连，不能为了检测可用性自动执行可能带副作用的 HTTP 请求。

### 4.5 标准输出

```text
TailMouse · Dev session

Terminal  codex
Web       http://127.0.0.1:5173
Receive   ./uploads · 256 MiB/file · 1 GiB/session
Access    Link holders · 1 browser · terminal control enabled
Expires   In 1 hour
Transport Tailcat · browser traffic via DERP

Share     https://s-<session-id>.tailmouse.example/#tm=<invite>

Anyone with this link can use the listed resources.
Local controls: Ctrl+] for session actions.
```

二维码包含完整分享链接，不上传到外部二维码服务生成。非 TTY 输出默认不绘制二维码或 ANSI 装饰。

分享链接是唯一允许显式展示秘密的用户输出；后续状态、日志与诊断只能显示脱敏形式。`--json` 的首条 `share.created` 事件包含链接，使用者需按敏感输出管理；其他事件不得重复输出。

## 5. 统一会话、链接与授权

### 5.1 会话模型

每次命令创建一个 Session。Session 包含资源清单、生命周期、访问策略、邀请凭据和 Tailcat 监听端；浏览器是该 Session 的 Member。

一个产品会话可以包含多条 Tailcat 应用数据流。“同一条通道”是统一 Tailcat 连接与会话语义，不要求把终端、上传和所有 HTTP 请求挤入同一条 TCP 字节流。

### 5.2 分享链接

```text
https://s-<random-session-id>.tailmouse.example/#tm=<base64url-envelope>
```

建议的邀请封装内容：

```json
{
  "v": 1,
  "session": "<random-session-id>",
  "tailcat": "<secret-tailcat-address>",
  "invite": "<256-bit-random-invitation-token>",
  "frontend_major": 1
}
```

此结构是 TailMouse 自定义应用封装，不修改 Tailcat 地址格式。不得把 Tailcat 节点私钥放入链接。当前 Tailcat 地址可能包含预共享密钥，完整地址同样必须按秘密处理。[S02]

公网域名只定位前端与隔离空间；访客权限由分享端持有的会话状态决定。仅知道随机域名不能访问资源。Fragment 避免凭据进入普通 HTTP 请求，但不能阻止持有链接的脚本、浏览器扩展、聊天平台或截图获得凭据。

### 5.3 连接流程

1. 浏览器加载版本匹配的可信前端，执行能力检查。
2. 解析邀请，仅向可信运行时传递；建立 Tailcat 连接。
3. 向分享端提交邀请认证。分享端验证会话、邀请代次、有效期、成员数量和可选人工批准。
4. 分享端返回权威资源清单与成员授权；客户端不能通过修改链接提高权限。
5. 浏览器按资源启动终端、Web Bridge、上传面板。
6. 建立心跳与状态同步，后台持续执行过期、撤销和额度检查。

未认证时不返回资源真实路径、命令参数、目标地址、终端输出或文件状态。

### 5.4 默认权限

| 会话类型 | 访客默认权限 | 明确不包含 |
|---|---|---|
| CLI | 终端输出 + 单一远程控制席位 | 本地会话管理、改变启动命令、自动新增服务 |
| CLI 只读 | 终端输出 | 输入、resize 控制权、信号、执行程序 |
| Web | 使用指定上游的应用能力 | 修改上游目标、任意网络代理、尾随扫描 |
| Receive | 向指定目录新建上传文件 | 列目录、读取既有文件、覆盖、删除、执行 |
| Dev | 已声明资源对应权限的组合 | 未声明资源、会话管理、自动执行上传内容 |

权限边界指 TailMouse 直接授予的接口能力。一个 CLI 或 Web 应用自身可能拥有进一步访问文件、网络或执行代码的功能；不能据此声称完成了整机权限隔离。

### 5.5 控制与撤销

本地管理入口由分享端掌握，不包含在访客分享链接中。TTY 模式通过 `Ctrl+]` 打开本地动作菜单，提供暂停接入、批准访客、收回远程输入权、轮换邀请、结束会话。控制转义键再次输入时可发送给子程序，行为需在帮助中说明。

轮换邀请时递增邀请代次，立即断开现有成员，废止全部派生授权，生成新邀请。旧链接即使还能到达 Tailcat 传输端，也不能通过应用认证。

结束会话必须关闭所有授权、活动流和 Tailcat 监听。撤销不能依赖前端隐藏按钮、浏览器本地时间或只关闭邀请页面。

### 5.6 临时会话与重连

默认绝对 TTL 为一小时，不因访问、刷新或心跳自动续期；到期前五分钟提示。显式设置 `--ttl 0` 时持续到分享端退出或主动结束，并在输出中突出显示。

浏览器短暂离线不终止资源。自动重连使用带抖动的退避，最多自动尝试 60 秒，随后保留手动重连入口。重连不能重复启动 CLI、重复提交 HTTP 写请求或重复创建已完成上传。

同一标签页的短期恢复可以把邀请保存在可信 origin 的 `sessionStorage`，完成读取后用 `history.replaceState` 清理地址栏 Fragment；不写入 `localStorage`、IndexedDB 或服务端日志。会话结束时清理本地邀请与恢复信息。此机制不能对抗可信 origin 自身的 XSS。

## 6. CLI：分享交互式终端

### 6.1 目标

让一个显式指定的交互式命令行程序，在本地和浏览器中保持同一个会话。支持 Codex、Claude Code、vim、htop、bash 等具备终端界面的程序；这些是兼容性测试目标，不表示所有版本已验证。

### 6.2 必须实现

| 编号 | 需求 | 验收要点 |
|---|---|---|
| CLI-01 | 在 PTY 中启动指定 argv，仅启动一次 | 多次浏览器接入与刷新不会重复创建子进程 |
| CLI-02 | 支持颜色、UTF-8、中英文输入、常见 ANSI/VT 行为 | CLI golden tests 与 TUI 场景通过 |
| CLI-03 | 输入、输出、窗口尺寸独立控制 | 旁观者不能改变终端尺寸或注入输入 |
| CLI-04 | 最多一个远程控制者 | 抢占、断线、超时均产生明确事件 |
| CLI-05 | 支持只读模式，分享端校验 | 构造 INPUT/RESIZE/SIGNAL 消息仍被拒绝 |
| CLI-06 | 浏览器断线后子进程继续运行至会话结束 | 重连恢复同一进程，PID 不变 |
| CLI-07 | 明确显示运行、退出、断线状态 | 程序退出码可见，不把正常退出显示成连接错误 |
| CLI-08 | 移动端提供必要辅助按键 | Esc、Tab、Ctrl、方向键、Ctrl-C 均可完成操作 |
| CLI-09 | 本地与远程输入仲裁 | 本地接管会撤销远程输入席位；不会无提示混合输入 |
| CLI-10 | 输出缓冲有界，恢复语义正确 | 不通过无限保留输出“解决”重连 |

### 6.3 本地与远程交互

TTY 模式下分享者可以在本地继续使用该 PTY。首个获得控制授权的远程成员占用远程控制席位；本地需要重新输入时优先收回远程席位，并通知浏览器。重新交还控制通过本地动作菜单完成。

只读访客继续看到输出，但其尺寸变化不影响实际 PTY。没有远程控制者时使用本地终端尺寸；进入纯远程或非 TTY 模式时使用当前控制者尺寸。

浏览器断线后不能自动重发最后一批未确认按键。传输恢复最多恢复输出与明确确认的状态，不承诺“恰好执行一次”的命令语义。

### 6.4 输出恢复

会话保存有界终端屏幕状态与增量输出，原始输出预算默认 4 MiB。完整 TUI 重连必须使用经过验证的 VT 状态快照或应用重绘机制；不能从任意字节边界重放截断日志，假定一定能还原 vim/htop 屏幕。

P0 必须确定并验证恢复实现。v1.0 至少覆盖普通交互 shell、持续日志、vim 和 htop 的重连。无法恢复时显示明确的重绘提示，不伪造完整历史。

### 6.5 进程生命周期

`cli` 由 TailMouse 创建并管理的子进程在会话停止或 TTL 到期时执行有界优雅终止，默认五秒后清理其进程组；平台差异须测试。正常退出后允许浏览器查看最终输出 60 秒，再关闭单独 CLI 会话。

在 `dev` 中，CLI 自然退出只改变终端资源状态，Web 与 Receive 仍按 Session TTL 存续。除非分享者显式重新启动，否则浏览器不能重启已退出程序。

v1.0 不宣称可以接管任意已运行进程。已有 tmux 会话接入列为 P2；届时停止“分享”不得终止不归 TailMouse 所有的 tmux 会话。

### 6.6 安全提示

`tailmouse cli -- vim` 或 `-- codex` 不构成沙箱：被分享程序可能通过自身功能读写文件、执行子进程、访问凭据或网络。工作目录也不等于文件系统根目录。

启动时须显示“访客将以该程序现有系统权限进行操作”。不要求 root，不自动提权，不绕开操作系统或 Agent 原有确认机制。终端页不得加载广告、分析脚本或不必要的第三方代码。[S08]

## 7. Web：分享指定 HTTP(S) 服务

### 7.1 目标与承诺边界

浏览器通过 Tailcat 加密应用通道访问分享端能够连接的指定 Web 上游。产品首版聚焦开发服务与经过验证的 Web 应用。

生成的链接是 **需要运行 JavaScript/WASM 的浏览器访问入口**，不等同于一个可供任意 HTTP 客户端访问的普通公网反向代理地址。v1.0 不支持把它交给 `curl`、第三方 Webhook、搜索爬虫或 OAuth 提供方当通用服务端回调地址。

### 7.2 Target 解析规则

| 输入 | 规范化目标 | 说明 |
|---|---|---|
| `8080` | `http://127.0.0.1:8080/` | 端口范围 1–65535 |
| `localhost:8080` | `http://localhost:8080/` | 解析结果须符合 loopback 策略 |
| `192.168.1.10:8080` | `http://192.168.1.10:8080/` | 需要 `--allow-remote` |
| `203.0.113.10:8080` | `http://203.0.113.10:8080/` | 示例公网地址；需要 `--allow-remote` |
| `[::1]:8080` | `http://[::1]:8080/` | IPv6 地址必须符合 URI 括号规则 |
| `https://app.example.com:8443` | 原协议、主机、端口 | 正常 TLS 校验，需要 `--allow-remote` |
| `http://localhost:8080/admin?tab=1` | 同源目标 + 初始路径和查询 | 初次导航打开 `/admin?tab=1` |

目标中的 Fragment 只用于预览页面初始前端路由，不作为 HTTP 请求的一部分发送上游。URL userinfo（`user:password@host`）禁止使用，避免意外泄漏凭据。

禁止 `file:`、`ftp:`、`gopher:` 等非 HTTP(S) 协议，禁止将通配监听地址 `0.0.0.0` / `::` 作为远端目标。用户可使用明确的 loopback 地址。

**URL 路径是初始打开位置，默认授权范围为该指定上游 origin。** 输入 `/admin` 不意味着只授权 `/admin` 子树。启动摘要必须写明这一点；v1.0 不提供容易造成虚假安全感的“目录式 Web 沙箱”。

### 7.3 地址与网络边界

目标由分享端解析和连接，浏览器不需要能够访问其 LAN IP。启动时解析并冻结本次 Session 允许的地址集合，保持原始主机名用于 Host 与 TLS SNI；DNS 变化需要分享者重新确认并重新建立会话。

`--allow-remote` 只放行该明确配置的目标。浏览器提交的 `resource_id` 必须映射至分享端本地配置，不能携带任意目标 URL 覆盖连接地址。

默认禁用 HTTP 客户端自动使用环境代理，防止意外经第三方代理发送内网请求。明确禁止 HTTP CONNECT、目标改写、自动扫描和通用 exit-node 能力。

### 7.4 HTTP 必须能力

| 编号 | 需求 |
|---|---|
| WEB-01 | HTML、CSS、JavaScript、图片、字体等同源资源正常加载 |
| WEB-02 | GET、HEAD、POST、PUT、PATCH、DELETE、OPTIONS 及请求体正确处理 |
| WEB-03 | 表单与 multipart 上传、JSON API 可用；保留内容类型及语义 |
| WEB-04 | 返回状态码、重复响应头和流式 Body；不能把所有响应统一改成 200 |
| WEB-05 | 可取消请求，上游 context 随浏览器取消或会话撤销而结束 |
| WEB-06 | SSE 以增量方式到达，不等待完整响应结束 |
| WEB-07 | 同源导航、相对路径、history 路由刷新、查询和 hash 路由可用 |
| WEB-08 | 处理指定目标内的 HTTP 重定向；跨目标重定向须拒绝或明确引导，不自动转发凭据 |
| WEB-09 | 支持经过验证的服务端会话 Cookie；访客之间隔离 |
| WEB-10 | 支持经过验证的页面主线程 WebSocket/HMR 路径，明确兼容边界 |
| WEB-11 | 正确处理缓存校验、空 Body、Range 与下载；不将私有响应写入公网缓存 |
| WEB-12 | 上游不可用时展示目标离线状态，支持重新探测，不改变目标 |

对 HEAD、204、304 等场景遵守无响应体要求。对压缩内容与 HTML 注入，必须同步调整编码、长度与缓存校验元数据，禁止重复解压或返回错误的 `Content-Length`。

v1.0 不自动重试请求。连接中断且执行结果未知时，显示“请求结果未确认”，由用户或原应用决定重试，避免重复写入。

### 7.5 Cookie 与身份

不复用分享者本机浏览器的 Cookie 或登录态；不读取浏览器配置目录。访客需要通过被分享应用自身的正常流程登录。

上游 Cookie 默认由分享端的隔离 Cookie Jar 管理，键至少包含 Session、Member、Web Resource。`HttpOnly` Cookie 不发送给代理页面脚本。退出会话后清理对应 Jar。

前端构造一个带 `Set-Cookie` 的 Response 不能被当成浏览器会自动保存 Cookie 的实现方案。Fetch 对相关响应头具有专门限制。[S05]

首版支持服务端表单会话、服务端 Cookie 认证等选定测试用例；依赖 `document.cookie`、复杂 SameSite/跨站流程或第三方登录的应用，须专项适配后才能宣称兼容。不通过忽略 Secure/SameSite 等约束换取“看起来可用”。

### 7.6 WebSocket、HMR 与 Web 兼容等级

Service Worker 不能透明接管原生 WebSocket 握手；WebSocket 标准为该请求指定跳过 Service Worker。[S04] v1.0 采用限定作用域的 WebSocket Shim + 应用消息桥接，优先验证开发预览中的主线程 HMR。

| 等级 | 内容 | 发布要求 |
|---|---|---|
| W1 基础 Web | 同源资源、API、导航、表单、普通流式响应 | v1.0 必须通过 |
| W2 开发预览 | 指定框架的 HMR、主线程 WebSocket、选定服务端登录用例 | v1.0 必须给出明确通过名单及版本 |
| W3 复杂应用 | JS Cookie、复杂 SSO、多个上游 origin、自有 Service Worker、Worker 内 WebSocket 等 | P2，逐应用验证，不作通用保证 |

不能为了使 Shim 生效而默认删除 CSP、X-Frame-Options、COOP/COEP 或关闭跨域安全策略。无法在安全边界内适配时，应报告不兼容。

v1.0 的代理业务请求仅面向已配置的上游；跨 origin 业务资源默认阻断并说明原因。P2 可通过显式多上游映射扩展，但不得让浏览器输入任意内网 URL。

## 8. Receive：浏览器向分享端发送文件

### 8.1 方向与边界

```text
访客浏览器选择文件 → Tailcat 加密传输 → 分享端指定目录
```

`tailmouse receive ./uploads` 创建的是一个临时收件入口。访问者不能浏览该目录、读取已有文件、覆盖文件、删除文件、创建可执行任务或获取任意服务器路径。

它不提供云盘、双向同步或文件管理器。Web 应用自身的 multipart 上传属于 `web`；Receive 面板上传属于独立的受控接收协议，两者配额与目标不混用。

### 8.2 核心功能

| 编号 | 需求 | 验收要点 |
|---|---|---|
| RCV-01 | 拖放、点击选择、多文件上传 | 桌面与移动端系统文件选择器可用 |
| RCV-02 | 逐文件显示排队、上传、校验、完成、失败 | 不能在校验和提交前显示完成 |
| RCV-03 | 分块传输与流式落盘 | 内存不随文件总大小线性增长 |
| RCV-04 | 上传前检查声明大小，传输中检查实际字节 | 伪造大小或分块越界不能突破上限 |
| RCV-05 | 接收目录严格约束 | 路径穿越、符号链接和并发替换攻击测试通过 |
| RCV-06 | 默认不覆盖，最终提交使用不覆盖语义 | 同名文件、并发冲突不破坏已有文件 |
| RCV-07 | 完成后核验大小与 SHA-256 | 不一致时不产生成功文件 |
| RCV-08 | 单文件取消、失败重试 | 取消停止读取本地文件与服务器写入 |
| RCV-09 | 服务端返回已提交的实际文件名 | 因安全命名变化而不同于原名时清楚告知 |
| RCV-10 | 文件完成状态可查询 | 最终确认丢失时可确认结果，不盲目重复创建 |

v1.0 只支持文件，不自动递归上传目录；目录选择、暂停后持久化续传与跨浏览器恢复列为 P2。短暂断线后允许重试整个未完成文件，不以“支持分块”冒充“支持断点续传”。

### 8.3 上传流程

1. 浏览器先显示接收方设定的大小、数量、并发和会话剩余额度。
2. 用户主动选择文件；前端提交名称、大小及类型提示，类型提示不作为安全依据。
3. 分享端检查授权、配额、磁盘条件，生成 `upload_id` 与安全目标名。
4. 浏览器分块读取；服务端写入受控临时文件并计算增量摘要。
5. 浏览器发送最终长度与摘要；服务端验证完整性，执行不覆盖的原子提交。
6. 返回 `committed` 状态及安全文件名。前端此时才显示完成。

SHA-256 用于内容一致性验证，不等于病毒扫描、来源认证或内容安全证明。浏览器应使用经过审查的增量摘要实现，不能为了调用一次全量 digest 把大文件全部载入内存。

### 8.4 命名与路径

分享端以已打开的目录句柄为根执行操作，采用 `os.Root` 或同等抗路径穿越机制；不能仅靠字符串前缀判断路径是否在目标目录内。Go 官方说明了目录约束 API 与符号链接竞态等相关问题。[S07]

v1.0 不接受子路径：拒绝 `/`、`\\`、NUL、控制字符、`.`、`..`、隐藏文件前缀及保留设备名；规范化 Unicode，文件名 UTF-8 长度默认不超过 180 字节。非法名称给出可理解的错误，不能静默落到其他路径。

默认采用 `<原文件主名>-<随机后缀>.<扩展名>` 的安全唯一名。扩展名不可信，不自动打开、解压或执行。不能通过错误信息或冲突处理暴露目录中其他文件是否存在。

接收根目录必须存在且可写，不自动创建整个目录树。禁止直接将系统根目录或用户主目录本身作为 v1.0 接收根；使用专门的子目录。

### 8.5 临时文件、提交与清理

临时文件写入接收目录下受控的 `.tailmouse-partials/<session-id>/`，使用严格的创建权限；POSIX 默认文件 `0600`、临时目录 `0700`。临时文件名来自服务器生成的 ID，不采用访客路径。

完成提交前检查摘要与实际大小；最终重命名必须具有原子“不替换”效果。不能先检查目标不存在，再进行可能覆盖目标的普通 rename。

取消、超时、校验失败或会话结束后清理未完成文件。异常退出留下的临时数据在后续启动时按可识别的内部清单清理，不能递归删除不属于 TailMouse 的目录或文件。

完成文件不会因停止分享而删除。产品界面应明确“关闭链接结束访问，已上传文件保留”。

### 8.6 默认限制

| 项目 | v1.0 默认值 |
|---|---|
| 单文件上限 | 256 MiB |
| 会话上传流量预算 | 1 GiB |
| 文件创建尝试次数 | 100 |
| 同时传输文件数 | 整个 Session 最多 2 个 |
| 应用层逻辑块大小 | 256 KiB，可拆为更小的传输帧 |
| 每条上传流未确认窗口 | 不超过 1 MiB |
| 收件服务权限 | 仅新建，不覆盖、不读取、不删除 |

声明大小需要做配额预留，实际收到的字节持续计入流量预算。磁盘预算与流量预算分开统计；取消后可释放临时磁盘，但已消费流量不归零，避免通过重复取消绕过限制。

不得宣传公共 DERP 上的大文件高速传输；测试与持续大流量使用自建或明确获准的中继。

## 9. Dev：组合开发会话

### 9.1 目标

把 CLI、Web、Receive 的组合组织成一个可完成任务的浏览器工作区。访问者无需复制三个链接、重新连接三次或猜测各项资源是否属于同一个任务。

`dev` 不自动扫描端口、不猜测要分享哪个程序、不读取 Agent 历史、不分析终端内容以判断“任务完成”，也不自动启动 `npm run dev` 等未明确给出的命令。

### 9.2 资源组合

支持 CLI + Web、CLI + Receive、Web + Receive、CLI + Web + Receive。未启用的功能不展示空入口，也不能通过协议调用。

启动时使用同一 Session ID、同一邀请、同一 TTL、同一连接状态与独立的资源权限。CLI 进程、Web 上游与接收目录的实际路径和行为沿用各自规范。

### 9.3 核心交互

| 编号 | 需求 | 用户价值 |
|---|---|---|
| DEV-01 | 一条链接进入组合界面 | 无需分别建立三个连接 |
| DEV-02 | 终端与预览可并排，上传为可展开面板 | 处理问题时减少窗口切换 |
| DEV-03 | 上传完成后显示可引用的实际相对路径 | 不需要在聊天里反复确认文件落在哪里 |
| DEV-04 | 提供“复制路径”操作 | 默认只复制，不向终端自动输入 |
| DEV-05 | 控制者可选择“插入终端输入区” | 必须由用户点击确认；不追加换行、不自动执行 |
| DEV-06 | Web 暂时离线只影响预览面板 | 开发服务器重启不导致终端和上传一同失效 |
| DEV-07 | CLI 退出保留明确终态 | 预览与上传仍可继续 |
| DEV-08 | 各面板统一展示会话失效与撤销 | 关闭会话后不会遗留仍可访问的资源 |
| DEV-09 | 文件传输不无限占用调度队列 | 终端交互和控制事件保持可用 |
| DEV-10 | 上传与预览内容不能触发管理动作 | 阻断由不可信内容跨到终端或会话管理的权限跃迁 |

如果接收目录位于 CLI 工作目录内，显示例如 `uploads/sample-a13f.csv`。位于工作目录外时只展示配置的目录标签与实际文件名，不默认泄漏完整系统路径；分享者本地可查看绝对路径。

### 9.4 明确排除的“智能联动”

上传文件不自动执行、不自动解压，不根据扩展名运行命令；不自动把文件内容送给 Codex、Claude Code 或其他 Agent；不根据终端输出自动批准操作、点击网页或修改代码。

预览页面发来的事件仅能请求其已绑定的 Web 资源，不能伪造 `file.committed` 以诱导终端输入。可引用路径必须来自分享端确认的上传完成记录。

### 9.5 端到端任务验收

准备一个开发应用、一个交互 CLI 和一个专用上传目录。第二台设备仅用浏览器打开链接，完成预览操作、上传 CSV、复制实际路径、在终端中显式使用该文件并重新查看预览。过程中不安装软件、不注册账号、不手工配置代理、不重新生成链接。

在上传期间重启开发服务，终端仍可交互；断开浏览器网络并恢复，不产生第二个 CLI 进程；最后撤销会话，所有面板均停止继续访问。

## 10. 浏览器信息架构与交互规范

### 10.1 全局页面

首页只承担连接与资源呈现，不增加注册页或营销遮挡。主要状态：加载运行时、连接中、等待批准、资源可用、正在重连、已到期、被撤销、能力不支持。

顶部固定显示会话标题、资源类型、连接状态、剩余时间与自身权限。传输详情按需展开：Tailcat、DERP 区域、可观测的 RTT 和流量；没有获得真实状态时显示“未知”，不猜测 Direct。

### 10.2 单资源布局

CLI 以终端为主，工具条只保留控制权、辅助按键、复制/粘贴、字号和连接状态。Web 以预览为主，保留返回、前进、刷新、打开路径和错误详情。Receive 以拖放区与上传队列为主，不出现文件树。

只有有权操作的成员显示对应按钮；即使按钮隐藏，分享端仍必须再次校验权限。

### 10.3 Dev 布局

桌面宽屏默认终端和预览并排，用户可拖动分隔；上传通过下方抽屉打开。窄屏采用 Terminal / Preview / Upload 标签切换，只显示已启用的标签。

切换标签不能重启 CLI、重置 Web 页面或取消上传。背景面板可降低渲染频率，但不依赖浏览器后台持续运行来保证可靠性。

### 10.4 文件状态用语

固定使用：等待上传 → 上传中 → 校验中 → 已完成。失败需说明发生于连接、配额、写入、校验还是提交阶段；不得仅显示“发生错误”。

上传区必须明确写出“文件将发送到分享者的指定目录；你无法浏览其已有文件”。临时目录名称与敏感绝对路径不暴露给访客。

### 10.5 移动端与无障碍

触控目标至少 44 CSS px，状态不能只用颜色表达。终端辅助键支持单次修饰键与明确的锁定状态；中文 IME 组合过程中不逐字提交未完成文本。支持键盘导航、可读焦点和屏幕阅读器状态提示。

手机后台、锁屏和页面被系统回收时，连接可能挂起；前台恢复后执行重连流程。不能承诺锁屏后继续上传或持续可控。

### 10.6 错误呈现

错误信息包含：发生了什么、是否影响其他资源、用户可以采取什么动作、脱敏错误码。内部堆栈放到本地诊断，不能把程序环境、访问令牌或服务端路径直接返回浏览器。

## 11. 技术架构与 Tailcat 集成

### 11.1 总体结构

```text
                      公网静态前端与版本化资源
                           │ HTTPS
                           ▼
访客浏览器 ┌────────────────────────────────────────────────┐
           │ 可信 Session UI                               │
           │   ├─ Terminal / Receive / Dev UI              │
           │   └─ Dedicated Worker + Tailcat WASM          │
           │                  ▲                            │
           │                  │ 限权 MessageChannel        │
           │ 隔离内容域       │                            │
           │   Web Bridge + Service Worker + App iframe   │
           └──────────────────┬─────────────────────────────┘
                              │ Tailcat / WireGuard
                              │ 当前浏览器路径：DERP
                              ▼
分享端     ┌────────────────────────────────────────────────┐
           │ 单个 TailMouse Go 进程                         │
           │ Session / Auth / Tailcat Adapter / Scheduler  │
           │   ├─ PTY Adapter ───────── 指定 CLI 子进程      │
           │   ├─ HTTP Adapter ──────── 指定 HTTP(S) 上游    │
           │   └─ Receive Adapter ───── 指定目录            │
           └────────────────────────────────────────────────┘
```

业务明文在浏览器和分享端处理。静态站点不承担 HTTP 业务反向代理；DERP 转发加密的 Tailcat 流量。

### 11.2 已核实的上游能力与限制

Tailcat 提供 Go 包及 CLI，可建立基于 WireGuard 的加密连接，不需要 Tailscale 账号；原生端具备 NAT 穿透与 DERP 路径能力。[S01]

官方浏览器 Demo 仍说明浏览器流量通过 DERP，浏览器直接连接依赖后续 WebRTC 支持。故本 PRD 不将浏览器 P2P 列为 v1.0 已有能力。[S03]

公共 DERP 有限速，不能作为商业级无限带宽承诺的依据。[S01] 产品必须支持自建 DERP 配置，不自动绕过公共服务限制。

### 11.3 原生端实现边界

原生端使用 Go，嵌入锁定版本或 commit 的 Tailcat Library。Session Manager、权限、PTY、HTTP、文件接收、事件与调度先放在一个进程，不拆微服务。

Tailcat 原始服务端配置不得启用通用 `exit-node`、全端口转发、默认无认证 Shell 或通用文件目录服务。TailMouse 只开放受控的应用协议监听，由应用层授权后派发资源请求。

当前 Tailcat API 提供监听与连接相关接口，具体签名以锁定源码为准。[S02] 工程不得照抄旧回答或旧文档中的过期 API，必须编译验证原生端与浏览器绑定。

### 11.4 浏览器运行时

可信 UI 使用 TypeScript；终端采用 xterm.js。Tailcat WASM 在受可信页面管理的 Dedicated Worker 内运行，避免占用主线程。

Service Worker 负责请求接管，不作为永不结束的连接守护进程。其生命周期与事件相关，浏览器可以终止空闲或异常的 Service Worker。[S06] 连接、成员身份与复用状态由可信页面和 Worker 管理；SW 被重新唤醒后重新绑定消息通道。

标签页被系统回收会导致连接丢失，分享端资源可继续存续，浏览器恢复后重新认证。不能通过 PWA 安装或扩展作为必选条件。

### 11.5 依赖与协议边界

所有业务流量统一经过 Tailcat；应用层定义 TailMouse 的终端、HTTP 和上传协议。Tailcat 原生工具不因此自动理解 TailMouse 应用协议，v1.0 不承诺直接用原生 `tailcat` CLI 获得全部交互能力。

不先增加第二套多路复用库。优先复用同一 Tailcat Peer 下的多条独立应用连接，建立明确的总量、并发与调度约束。

## 12. 浏览器 Web Bridge 设计

### 12.1 信任分区

使用两个不同的可注册域体系：

```text
可信控制界面： https://s-<session-id>.tailmouse.example
不可信应用：   https://a-<session-id>-<resource-id>.tailmouse-content.example
```

每个 Session 与 Web Resource 使用新的隔离 origin，不复用旧会话 origin。控制 UI、终端与邀请秘密不得和代理应用放在同一 origin。仅用不同 URL 路径不能替代 origin 隔离。

内容域只持有访问绑定 Web Resource 所需的受限消息通道；不持有完整邀请、Tailcat 地址、CLI 输入凭据、上传或本地管理权限。

### 12.2 选定的页面结构

可信父页面维护 Tailcat Worker。Web 面板加载独立内容域的持久 Bridge Frame，Bridge Frame 内承载被代理的 App Frame。Service Worker 接管 App Frame 的导航与请求，通过持久 Bridge Frame 的 MessageChannel 转给可信 Worker。

该结构允许 App Frame 导航与刷新而不摧毁整个 Tailcat 运行时。Bridge Frame 与代理应用可能处于同一内容 origin，因此必须将这个区域整体视为不可信；安全性来自分享端的资源绑定与可信父页面的最小接口，不能依赖隐藏 JS 变量。

如果浏览器阻止所需的 frame / SW 能力，应显示不兼容信息；不得悄悄让 HTTP 业务流量改走公网 Gateway。

### 12.3 请求路径

1. 首次打开先加载受信的内容域 bootstrap，完成 SW 注册与控制状态确认。
2. 仅在 Bridge Ready 后加载目标页面，避免首访请求落到错误的静态服务器。
3. SW 接管 HTTP 请求，将方法、相对路径、允许的头及流式 Body 交给绑定资源通道。
4. 可信父页面按已建立的 frame 身份绑定资源，不接受页面自行选择 `resource_id`。
5. 分享端依据本地资源配置构造上游请求，完成地址、方法、权限与额度校验。
6. 响应经相同 Tailcat 路径返回，SW 构造浏览器 Response。

SW 请求接管受其控制客户端与浏览器机制影响，不能写成“全浏览器代理”。初始控制、导航、子资源、跨 origin 请求与 SW 生命周期都必须分别测试。[S06][S10]

### 12.4 消息安全

所有 `postMessage` 使用精确 origin，验证 `event.source` 与绑定 frame；不以 `*` 传递能力。MessageChannel 在握手完成后绑定固定 Web Resource，不能通过消息内容提升权限。

所有请求最终在分享端再次校验。内容域代码即使恶意构造消息，也最多使用已授权 Web 上游能力，不能发出终端输入、读取上传根目录或停止整个会话。

预览区域不允许顶层导航劫持、任意弹窗或访问可信父页面 DOM。Sandbox 选项与 SW 所需同源能力必须共同验证，不能通过不兼容的 sandbox 属性组合假定已实现隔离。

### 12.5 HTTP 语义策略

上游 Host 根据声明目标设置，TLS SNI 与证书身份保持一致。清理逐跳头，不把 TailMouse 自身 Cookie、授权 token、来源密钥转发给上游。

Origin / Referer 映射只针对已绑定的代理应用上下文，不能盲目信任访客传来的任意头。请求的 credentials 行为、Cookie 选择与重定向目标按同一逻辑上游身份处理。

重定向在适配层逐跳处理，限制十次；每一跳重新校验目标范围。跨 origin 重定向默认阻止，不携带原上游凭据到新目标。

Range/ETag/Last-Modified 等按实际响应和内容变换一致处理。HTML 注入或重写发生后，原有内容校验标签可能不再有效；必须重算或移除相关元数据，不能原样保留制造错误缓存。

### 12.6 Cookie 与 WebSocket 实现限制

Cookie Jar 是兼容层，不能声称它自动等价于浏览器完整 Cookie 安全模型。隔离、Secure、HttpOnly、路径、过期与支持的 SameSite 用例都有专门测试；未覆盖的跨站行为进入 W3。

WebSocket Shim 必须在支持页面的应用脚本前安装，仅支持绑定资源内的允许路径。实现 OPEN/MESSAGE/CLOSE/ERROR、文本/二进制、子协议、状态与背压语义；控制帧由原生上游 WebSocket 实现处理。

Worker、嵌套 frame、严格 CSP 或页面保存原生 WebSocket 引用等情况可能无法被可靠覆盖，不能将主线程 Shim 当成通用透明代理。[S04]

### 12.7 缓存与残留

公网可缓存版本化静态 JS/WASM，不能缓存业务响应。业务内容默认不写入 Cache Storage；上游登录态仅存本次会话的隔离 Jar。

结束会话时尽力清理该 origin 的临时存储、SW 和消息绑定；浏览器未在线时不能保证立即物理清理。因此安全撤销必须由分享端拒绝旧凭据完成，不能依赖客户端删除成功。

静态内容域保留的 `/.tailmouse/` 路由不得被上游替换；非法 SW 脚本注册、保留路径覆盖与跨会话残留都进入安全测试。

## 13. 应用协议与流量调度

### 13.1 协议定位

定义版本化的 `tailmouse/1` 应用协议，运行于 Tailcat 提供的加密连接之上。此节给出接口语义与限制；二进制字段编号应在 P0 的协议 RFC 中冻结，不假定 Tailcat 已提供这些业务消息。

优先采用长度前缀元数据与二进制 Payload，不将文件或 HTTP Body 转为 Base64，不设计新的加密算法。

### 13.2 连接划分

| 连接 / 流 | 作用 | 生命周期 |
|---|---|---|
| Control | 认证、资源清单、权限、心跳、状态、撤销事件 | 每个 Member 一条 |
| Terminal | PTY 输出、输入、resize 与控制席位相关信息 | 每个终端订阅独立维护 |
| HTTP | 单个请求与响应的流式转发 | 每请求一条；连接池优化须保持隔离与取消语义 |
| WebSocket | 双向应用消息转发 | 每个上游 WebSocket 一条 |
| Upload | 分块与上传确认 | 每个活动文件一条 |

所有新连接先通过认证并绑定 Session、Member、Resource。不要只在 Control 连接鉴权，而让其他端口成为绕过入口。

### 13.3 握手与权限

初次 Control 认证提交邀请 token，分享端与本地存储的高熵 token 摘要做常量时间比较。认证成功后生成短期成员授权，并绑定传输层已验证的客户端身份与邀请代次。

后续业务连接携带成员授权，分享端检查权限、期限和传输身份。不能只相信客户端消息中的 peer key。若锁定 Tailcat API 无法直接提供所需的可信身份信息，必须在 P0 明确兼容方案并评审。

派生授权最长不超过一小时或 Session 剩余有效期。长会话可通过有效 Control 连接续发，但续发不能越过被撤销的邀请代次，也不能自动扩大权限。

### 13.4 核心消息

| 消息组 | 示例类型 | 要求 |
|---|---|---|
| 会话 | `HELLO`、`AUTH`、`READY`、`PING`、`PONG`、`SESSION_CLOSED` | 版本与能力协商，未知必需能力须拒绝 |
| 资源 | `RESOURCE_STATUS`、`ACCESS_DENIED` | 仅返回成员有权知道的信息 |
| 终端 | `TERM_OUTPUT`、`TERM_INPUT`、`TERM_RESIZE`、`TERM_EXIT` | 输入必须校验控制席位 |
| HTTP | `HTTP_OPEN`、`HTTP_HEADERS`、`HTTP_BODY`、`HTTP_END`、`HTTP_CANCEL` | 保留状态与流式语义 |
| WebSocket | `WS_OPEN`、`WS_MESSAGE`、`WS_CLOSE` | 有界队列、独立关闭，不影响整个会话 |
| 上传 | `UPLOAD_CREATE`、`UPLOAD_CHUNK`、`UPLOAD_ACK`、`UPLOAD_FINISH`、`UPLOAD_STATUS`、`UPLOAD_CANCEL` | 明确 offset、提交状态和错误 |
| 控制 | `CONTROL_GRANTED`、`CONTROL_REVOKED`、`INVITE_ROTATED` | 本地管理授权不下发给访客 |

认证后的资源清单示例：

```json
{
  "protocol": "tailmouse/1",
  "session_id": "s_example",
  "mode": "dev",
  "expires_at": "2026-10-16T05:00:00Z",
  "member_id": "m_example",
  "resources": [
    {"id": "cli_1", "kind": "terminal", "rights": ["view", "request_control"]},
    {"id": "web_1", "kind": "web", "label": "Preview", "rights": ["use"]},
    {"id": "recv_1", "kind": "receive", "label": "uploads", "rights": ["upload"]}
  ],
  "limits": {"max_file_bytes": "268435456", "max_active_uploads": 2}
}
```

示例不包含真实系统路径、程序环境变量或邀请秘密。可能超过 JavaScript 安全整数范围的计数、offset 与尺寸字段统一采用十进制字符串编码。

### 13.5 限制与背压

协议元数据上限 64 KiB，单帧二进制 Payload 上限 64 KiB，单个逻辑上传块可以拆为多帧。禁止相信来自对端的长度字段直接分配任意大小内存。

每个 Member 最多 16 个并行 HTTP 请求；Session 总业务流上限 64，上传活动文件总上限 2。所有队列有界，取消必须传播至磁盘读写与上游连接。

调度优先级为：会话控制 / 撤销 → 终端输入与小型输出 → 交互 HTTP / SSE → 大型响应与文件上传。采用公平调度与背压，禁止单个上传无限向底层发送队列堆积。

即使拆分应用流，浏览器 DERP 连接仍可能共享底层瓶颈。优先级不能完全消除链路拥塞和队头阻塞，应通过受控测试量化，而非声称终端绝不受上传影响。

### 13.6 重试和幂等性

Control 心跳与状态读取可重试。终端输入、HTTP 写操作不自动重放。上传提交使用服务器生成的 `upload_id` 和状态查询避免确认丢失后的重复文件；相同 ID 的重复完成消息返回既有结果。

v1.0 不承诺主机进程重启后的上传幂等性或会话恢复。重启生成新 Session 与邀请；已完成文件保留，未完成文件按清理规则处理。

## 14. 数据模型、状态与生命周期

### 14.1 存储原则

v1.0 不依赖云端数据库、Redis 或账号服务。默认状态在分享端进程内存中维护；必须落盘的数据仅包括用户接收文件、内部临时上传清单、显式保存的部署配置和用户主动导出的脱敏诊断。

邀请秘密、Cookie、终端屏幕和业务正文默认不持久化。跨进程恢复不属于 v1.0 承诺。

### 14.2 核心实体

| 实体 | 关键字段 | 存储与清理 |
|---|---|---|
| Session | `id, mode, created_at, expires_at, state, invite_generation, limits` | 内存；结束后清理 |
| Resource | `id, session_id, kind, config, state, ownership` | 内存；config 不全量发送访客 |
| Invite | `token_digest, generation, expires_at, rights, revoked_at` | 仅摘要；轮换失效旧代次 |
| Member | `id, transport_peer_identity, grant_digest, rights, connected_at, last_seen` | 内存；断线保留短期恢复窗口 |
| ControlLease | `resource_id, member_id, granted_at, state` | 内存；本地接管 / 断线 / 撤销时释放 |
| Upload | `id, resource_id, member_id, safe_name, declared_size, received_size, digest, state` | 内存 + 最小临时清单 |
| HTTP Context | `request_id, member_id, resource_id, cancellation, deadline` | 请求生命周期内 |
| Cookie Jar | `session_id, member_id, resource_id, logical_origin` | 内存；会话或成员清理时销毁 |
| Terminal State | `resource_id, screen_state, bounded_output, process_id, exit_code` | 内存；不默认录屏或持久日志 |

### 14.3 资源所有权

- TailMouse 创建的 CLI 子进程归本会话管理，结束时按既定规则终止。
- 用户原有的 Web 服务只被访问，不归 TailMouse 管理，停止分享不能杀死它。
- 已提交的 Receive 文件归接收者保留，停止分享不删除。
- 未来接入已有 tmux 会话时，所有权必须标记为外部，撤销分享只解除访问。

### 14.4 状态机

```text
Session:
VALIDATING → STARTING → READY → CLOSING → CLOSED
                  └──→ FAILED
READY → EXPIRED → CLOSING
READY → REVOKED → CLOSING

Member:
CONNECTING → AUTHENTICATING → [WAITING_APPROVAL] → ACTIVE
ACTIVE → DISCONNECTED → RECONNECTING → ACTIVE
任意有效状态 → REVOKED / EXPIRED / CLOSED

Upload:
OFFERED → ACCEPTED → TRANSFERRING → VERIFYING → COMMITTING → COMPLETED
                       └────────→ CANCELLED / FAILED
```

Session READY 表示传输与授权可用，不保证所有 Web 上游始终在线。每个 Resource 有独立的 STARTING / READY / UNAVAILABLE / EXITED / FAILED 状态。

程序不存在、目录不可写、URL 非法、DNS 无法建立目标允许集合等配置错误直接启动失败。Web TCP 连接被拒绝可以把该资源标为 UNAVAILABLE 并保留 Session，方便用户启动开发服务；TLS 校验失败必须阻断该资源，不能自动降级 HTTP。

### 14.5 时钟、心跳和结束

TTL 由分享端时间计算，配合单调计时防止本地时钟回拨延长授权。浏览器倒计时仅作展示。心跳默认五秒，无响应十五秒后标记断线并撤销远程输入席位；恢复需要重新确认有效授权。

会话关闭先拒绝新操作并撤销权限，再取消活动流和清理拥有的资源。到期时不继续接收剩余上传；应显示中止原因，不以“等文件传完”为由延长已过期权限。

## 15. 安全与隐私要求

### 15.1 威胁模型

| 对象 / 威胁 | TailMouse 的防护目标 | 不作出的保证 |
|---|---|---|
| 被动网络观察者与 DERP 中继 | 不获得 Tailcat 业务明文 | 不隐藏连接 IP、时间、流量大小等元数据 |
| 偶然得到域名但没有完整邀请的人 | 不能通过应用认证获取资源 | 不把域名随机性作为唯一访问控制 |
| 获得有效链接的访客 | 权限限制在会话声明的接口范围 | 无账号情况下不证明访客真实身份 |
| 恶意代理 Web 页面 | 不能读取邀请、操作终端或取得上传/管理能力 | 被授权 Web 应用本身的功能仍可被使用 |
| 恶意上传文件或文件名 | 不能越界写入、覆盖或触发 TailMouse 自动执行 | 不提供内容无害、无病毒或无提示词注入保证 |
| 前端分发或依赖被篡改 | 尽力降低供应链与 XSS 风险 | 无法保证恶意客户端代码不窃取其可见明文 |
| 分享端机器已失陷 | 不扩大默认权限或额外持久化秘密 | 不能保护已被控制的端点 |

### 15.2 必须落实的安全项

**SEC-01 高熵邀请与保密。** 会话 ID 至少 128 bit 随机，邀请 token 至少 256 bit 随机。生成使用系统密码学随机源；摘要比较使用常量时间。完整邀请、Tailcat 地址、预共享密钥与节点私钥不得写入日志或分析系统。

**SEC-02 逐流授权。** 所有终端、HTTP、WebSocket、上传流都须在分享端检查成员、资源、权限、代次与有效期；活动流同样受撤销和 TTL 约束。

**SEC-03 默认最小暴露。** 不开启所有端口、全部内网、系统 Shell 服务或通用文件读取。没有声明的 Resource 在路由表与协议中均不存在。

**SEC-04 信任分区。** 不可信上游页面放在独立内容域；完整邀请、Tailcat Worker、终端 UI 留在可信域。访客消息不能指定其他资源或管理动作。

**SEC-05 目标锁定。** 上游由分享端配置并绑定，防止浏览器篡改、重定向跳转、DNS 重绑定和代理环境变量使请求离开授权目标。

**SEC-06 文件安全。** 使用目录约束 API、随机临时文件名、独占创建和不替换提交。设置资源上限，拒绝特殊路径及危险目录选择。

**SEC-07 不执行上传。** TailMouse 不自动打开、解压、运行或输入上传内容。被上传目录中的其他程序可能自行执行文件，分享者需选择合适的接收目录；产品应提示避免直接上传到启动目录、自动执行目录或敏感配置目录。

**SEC-08 终端最小信任。** 不默认提权，不视指定程序为沙箱；禁用自动剪贴板写入等高风险终端扩展，终端超链接需明确用户操作且不得自动打开本地资源。

**SEC-09 防滥用限制。** 未认证连接、握手、队列、文件数、磁盘、内存与并发都有限额。失败重试不能让服务器持续无限分配内存或文件句柄。

**SEC-10 失败关闭。** 协议版本不匹配、认证失败、origin 绑定不明或证书失败时拒绝操作，不降低加密或权限要求以“自动修复”。

### 15.3 权限组合的实际效果

Receive 的“只上传”只描述 Receive API。如果同一访客同时拥有可以读取文件的 CLI 控制权，或被分享 Web 应用本身暴露该目录，他可能通过其他已授权能力读取或修改文件。

因此 `dev` 的权限说明必须显示资源组合的实际风险，不能声称“打开完整终端后依然无法读取接收目录”。真正需要只收文件时，应使用独立 `receive` 会话，或不授予可绕过该边界的其他能力。

同理，允许用户操作具有管理权限的 Web 应用，其后果受该应用本身权限影响；TailMouse 的目标地址白名单不等于应用内权限系统。

### 15.4 浏览器分发信任

端到端加密不消除 Web 前端的信任要求。托管方若向浏览器交付恶意脚本，可能在数据加密前或解密后读取内容。前端发布应使用严格 CSP、固定依赖、可复现构建、静态资源完整性与独立安全审查。[S08]

资源哈希和 SRI 有助于防止部分供应链问题，但不能独立防御同时被替换的入口 HTML。提供可自行托管的前端与 DERP；不将“中继看不到明文”扩写为“任何平台运营者在任何情况下都无法读取”。

### 15.5 加密边界

```text
浏览器 ───── Tailcat / WireGuard 加密 ───── 分享端
                                               │
                                               ├─ 本地 PTY / 本地文件
                                               │
                                               └─ HTTP(S) 上游
                                                    HTTPS：另行 TLS 校验
                                                    HTTP：该网络段为明文
```

仅把 WireGuard 端点间的加密称为 TailMouse 的端到端传输。上游 HTTPS 校验在分享端完成；不能把浏览器地址栏的 HTTPS 锁标志视为所有后续链路已加密。

### 15.6 日志与敏感信息

默认不记录终端正文、按键、HTTP 请求或响应 Body、Cookie、Authorization、上传内容、完整上游 URL 查询或完整分享链接。没有默认云端遥测、会话录制和访问画像。

允许记录的本地元数据包括临时 Session ID、事件种类、脱敏资源 ID、状态码、错误码、字节计数与持续时间。二维码、剪贴板、终端滚屏和 `share.created` 输出包含邀请时仍需用户保密，产品应明确提示。

### 15.7 无账号授权的限制

默认有效链接持有者即拥有对应能力。转发链接等于转授权限；无法通过“记住浏览器”确保只属于某个真实的人。需要更强确认时使用 `--approval manual`，通过带外沟通确认访客。

人工批准模式必须有可用的本地批准入口；无 TTY 且没有可用本地管理通道时，启动即报告不支持该组合，不能悄悄改为自动批准。

## 16. 部署、分发与运维

### 16.1 最小运行组件

| 组件 | 必需性 | 持有业务明文 | 说明 |
|---|---|---|---|
| TailMouse Native CLI | 必需 | 是，端点之一 | 用户设备上的单个进程 |
| 可信静态前端 | 必需 | 正常托管请求不接收会话正文 | 分发 UI、JS、WASM；其代码供应链属于信任边界 |
| 隔离内容域 bootstrap | Web/Dev 必需 | 不作为业务代理服务 | 分发 Bridge 与 SW；提供独立 origin |
| DERP | 当前浏览器路径必需 | 不读取 WireGuard 业务明文 | 可使用适合的默认配置或自行部署 |
| Session 注册数据库 | v1.0 不需要 | — | 邀请包含连接信息，授权由分享端维护 |
| 公网 HTTP Gateway | 不引入 | — | 不作为兼容性或故障自动回退 |
| TURN / WebRTC 信令 | v1.0 不需要 | — | 留待传输适配研究 |

“无账号”不代表“没有基础设施”。默认浏览器会下载运行时，并通过 DERP 建立业务连接。

### 16.2 域名与 HTTPS

默认部署需要可信前端与隔离内容域的通配 DNS、HTTPS 证书和静态路由配置。域名按随机 Session/Resource 派生，不要求每次分享创建 DNS 记录或建立服务端 Session 映射。

页面元信息不包含真实目标、命令、文件名或邀请。聊天软件预览只能得到通用 TailMouse 介绍。

二维码在本地生成。过长邀请无法生成易扫描二维码时保留复制链接入口，明确提示；不调用第三方短链或二维码生成服务。

### 16.3 自托管

必须提供统一部署配置，包含前端基础域、内容基础域、DERP map、版本化静态资源路径和允许的 origin 模板。CLI 参数优先于环境变量与本地配置，配置优先级固定并写入帮助。

自建 DERP 必须验证浏览器所需的安全 WebSocket/HTTPS 路径、TLS、域名解析与跨网络可达性。不能因为原生 Tailcat 可用就假定浏览器可用。

自托管不引入账号系统，也不要求用户加入 Tailscale Tailnet。公共入口与自托管入口使用同一前端、协议和安全测试。

### 16.4 发布与版本

Native、WASM、UI、Bridge、SW 必须锁定并记录相互兼容的版本，发布清单包含构建 commit、依赖锁文件、校验值和兼容协议范围。运行时不能混用未经验证的任意 `main` 版本。

进入会话前进行 major 版本协商；不兼容时提示升级，不静默修改已建立会话的协议或自动替换运行中的 Native。

Web 静态资源按内容哈希缓存。SW 更新不能在活动会话中强制刷新全部页面或丢弃现有邀请；升级过程需要兼容性测试。

### 16.5 安装和分发目标

v1.0 提供 macOS arm64/amd64 与 Linux arm64/amd64 的原生发布产物；Homebrew 等安装渠道以实际打包验证为发布条件，不在文档中把尚未发布的包命令写成已可安装。

分享端无需另外安装 Tailcat、Tailscale 客户端或浏览器扩展，依赖封装在产品中。原生 Windows 分享端列为 P2；Windows 设备使用受支持浏览器作为访客不受此限制。

### 16.6 运行约束

保持分享端进程、网络及设备唤醒是会话可用的前提。v1.0 不自动修改系统休眠策略，也不安装开机守护服务；设备休眠后展示离线与重连状态。

公共 DERP 仅用于符合上游约束的使用场景；大流量、压力测试和性能基线使用自建中继。不得用大量并发绕过公共中继限速。[S01]

## 17. 非功能需求与兼容范围

### 17.1 性能指标的解释

以下是初始验收目标，全部需要实测。不能把尚未测得的目标写进官网作为现有性能。P0 建立基线后，任何调整必须记录原因、测量环境和版本，不能通过悄悄降低阈值判定通过。

受控环境基线：分享端四核、8 GiB 内存、SSD；访客现代桌面浏览器；自建 DERP；有效链路 RTT 不超过 80 ms；独立记录无丢包与 1% 丢包两组结果。公网真实网络另外统计，不能混为同一组。

| 编号 | 指标 | 初始验收目标 |
|---|---|---|
| NFR-01 | 有效配置到输出邀请 | 网络发现正常时 P95 ≤ 5 秒，不含人工批准 |
| NFR-02 | 暖缓存浏览器打开到可交互 | P95 ≤ 5 秒，不含应用自身启动时间 |
| NFR-03 | 冷启动浏览器打开到可交互 | 100 Mbps 下载条件下 P95 ≤ 15 秒；记录 JS/WASM 大小与编译耗时 |
| NFR-04 | 终端输入至回显 | 空载受控环境 P95 ≤ 200 ms |
| NFR-05 | 上传并行时的终端增量延迟 | 在规定的上传限流负载下，P95 增量 ≤ 200 ms |
| NFR-06 | 文件上传效率 | 同环境同版本 Tailcat WASM 基准吞吐的至少 70% |
| NFR-07 | 大文件内存 | 传输 1 GiB 文件时，Native 相对基线增量 ≤ 128 MiB，浏览器增量 ≤ 64 MiB |
| NFR-08 | 会话撤销 | 分享端授权立即失效；本地拒绝新操作目标 ≤ 1 秒，远端提示延迟单独记录 |
| NFR-09 | 无泄漏连续运行 | 八小时受控会话中无单调资源泄漏，文件句柄与 goroutine 可回收 |
| NFR-10 | 重连安全 | 100 次断线恢复测试中无重复 CLI、重复 HTTP 写入或错误的上传完成状态 |

1 GiB 测试须显式提高默认单文件限制。浏览器内存测量要计入 WASM、Blob、ArrayBuffer、消息队列和上传摘要，不只统计 JavaScript 堆。

吞吐与延迟分别测量，必须同时记录传输路径、DERP、网络整形和文件大小。不得在公共中继上执行该压力基准。

### 17.2 可用性

启动失败的退出状态必须稳定可自动化；活动会话单资源失败不触发其他资源无条件退出。磁盘满、上游挂起、网络切换、页面刷新、认证过期必须有明确终态。

不设置未经测量的互联网连接成功率保证。发布前至少在家庭宽带、移动热点、常见办公网络和自建 DERP 环境执行人工验证，并公开已知限制。

### 17.3 浏览器支持策略

| 环境 | v1.0 目标 | 限制 |
|---|---|---|
| 桌面 Chrome / Edge | CLI、Receive、Dev，Web W1/W2 测试名单 | 发布时锁定测试版本 |
| 桌面 Firefox | CLI、Receive、Dev，Web W1/W2 测试名单 | SW、流式 Body、Shim 逐项验证 |
| 桌面 Safari | CLI、Receive、Dev，Web W1/W2 测试名单 | 跨 origin frame、SW 与存储策略重点验证 |
| iOS Safari / Android Chrome | 前台 CLI、上传、移动 Dev；Web 按实测名单 | 后台、锁屏、长期上传不保证 |
| 内嵌浏览器 / 受限 WebView | 不作为首版保证范围 | 提示使用系统浏览器 |

测试最近两个稳定版本是发布流程目标，不等于在本文编写时已经通过。首屏通过能力检测确认 WASM、Worker、Streams、SW 与必要的存储可用性；不只通过 User-Agent 字符串判断。

### 17.4 安全发布门槛

不得存在未解决的跨 origin 凭据泄漏、终端输入越权、任意目标代理、目录穿越、已有文件覆盖、撤销失效或无限资源分配问题。任一此类缺陷阻止 v1.0 发布。

## 18. 产品验证与度量

### 18.1 核心产品指标

核心指标是 **一次被分享的任务能否成功完成**。CLI 成功意味着确实完成必要交互；Web 成功意味着完成页面操作；Receive 成功意味着服务端已提交并校验文件；Dev 成功意味着跨资源任务完整完成。

连接次数、二维码生成次数和 GitHub Star 可以观察，但不能替代上述结果。

### 18.2 本地事件

默认仅本地聚合，不自动上报云端。允许用户主动导出一次会话的脱敏报告。

| 事件 | 允许字段示例 |
|---|---|
| `session.created` | 临时 Session ID、模式、资源种类、TTL |
| `connection.ready` | 协议版本、路径类型、耗时、浏览器能力摘要 |
| `resource.ready` | 资源种类、状态、耗时 |
| `upload.completed` | 字节数、耗时、是否校验成功，不含文件名或内容 |
| `resource.error` | 资源种类、错误码、阶段 |
| `session.closed` | 原因、时长、聚合流量、资源成功/失败计数 |

不使用持久设备指纹衡量留存，不采集终端输入、项目名、私有 IP、文件名或完整 URL。

### 18.3 与竞品的任务对照

以 BitBang 为首要体验基准，使用相同设备和网络，锁定两者版本并记录配置。P2P 路径与 DERP 路径不同造成的差异需单独解释，不能全部归因于 UI。

找约十位有真实需求的参与者，以交叉顺序完成同一任务：启动分享 → 浏览器接入 → 操作预览 → 上传测试数据 → 使用终端 → 结束分享。记录首次成功时间、求助次数、错误、完成率以及下一次任务时的自主选择。

该样本用于寻找方向，不用于证明市场占有率或统计显著优势。继续投入的理由应来自可复现的收益，例如减少环境配置、路径确认或跨工具操作；“也支持四项功能”不足以构成结论。

### 18.4 继续投入与收敛条件

当相同任务的关键步骤明显减少、完成更稳定，并出现真实重复使用时，继续打磨对应工作流。若没有明显改善，将 TailMouse 保持为精致的 Tailcat 开源伴生工具，不通过追加新的功能类别解释竞争力。

## 19. 版本计划与发布门槛

### 19.1 P0：技术与安全验证

P0 不作为公开可依赖产品发布。必须先完成四类风险最高的验证：

| 验证项 | 产出 | 失败时处理 |
|---|---|---|
| Native ↔ Browser Tailcat | 加密双向流、自建 DERP、断线重连样例 | 修正依赖/绑定，不更换为隐式 Gateway |
| PTY 与控制权 | 单进程交互、只读、断线/TUI 恢复测试 | 缩减承诺或修复，不能假称任意 CLI 已兼容 |
| Web Bridge | 独立 origin、首访控制、流式响应、Cookie 测试、选定 HMR | 明确不兼容范围；安全失败阻断发布 |
| Receive | 1 GiB 流式传输、路径竞态、摘要、原子提交 | 修复安全与内存问题后进入 P1 |
| 综合 Dev | 上传负载下终端与预览同时可用 | 调整调度、缓冲和限制，记录基线 |

P0 同时冻结 Tailcat revision、前端绑定、应用协议 major、信任分区与测试装置。不能仅演示一个 HTML 页面就宣称完成 Web 可行性验证。

### 19.2 P1：v1.0 公开版本

四个命令全部交付。包含统一邀请、TTL、撤销、可选人工批准、终端只读与单控制席位、指定上游限制、W1 与明确 W2 名单、单向文件接收、Dev 联动、移动布局、自建 DERP 配置和脱敏诊断。

P1 必须通过安全门槛与关键验收测试；兼容名单之外的应用明确标识，不使用“任意 Web 服务完美兼容”宣传。

### 19.3 P2：四个命令内完善

可迭代已有 tmux 接续、Windows 原生分享端、上传断点续传、目录上传、显式多上游、更多 Cookie/SSO/Worker 场景与更细的受限邀请。不增加第五个产品入口，不将它们全部设为 v1.0 前置条件。

任何对权限模型、资源数量或持久化范围的扩展，都需更新威胁模型和验收用例。

### 19.4 传输研究分支

WebRTC 直连适配作为单独研究分支，不阻塞四个核心命令。目标是保留 Tailcat 的应用与身份边界，评估是否能以浏览器允许的传输获得直连收益；不是立即将业务协议迁移到纯 WebRTC。

研究必须包括端点身份绑定、MTU/分片、背压、拥塞控制、可靠性叠加、跨网络成功率和回退语义。WebRTC 自有安全机制也需要正确认证信令与端点，不能把“用了 DTLS”视为全部安全问题已解决。[S11][S12]

## 21. 风险登记与架构决策

### 21.1 风险登记

| 风险 | 影响 | 对策与触发条件 |
|---|---|---|
| 浏览器 Tailcat 依赖 DERP | 延迟、吞吐与中继资源受限 | 展示真实路径；自建 DERP 基准；不宣传当前直连 |
| WASM 体积与启动开销 | 首次打开体验差 | P0 测冷/暖启动，按需加载资源 UI，固定版本缓存 |
| Web 兼容性不可通用 | 页面可见但登录/HMR/上传失败 | 发布 W1/W2 名单，W3 单独适配，安全限制不静默移除 |
| SW 生命周期与浏览器限制 | 导航、后台、恢复不稳定 | 持久可信 Worker + scoped bridge；能力检测与故障状态 |
| 网页内容与终端同域 | 凭据和主机控制权泄漏 | 不同可注册域，后端逐资源授权，安全测试为硬门槛 |
| CLI 被误认为沙箱 | 访客获得分享者级别的系统能力 | 明确风险、只读模式、人工批准；不自动提权 |
| 收件目录被其他程序自动执行 | 上传间接触发代码或配置加载 | 专用目录、无自动执行、文档提示；不承诺完整系统沙箱 |
| 组合权限互相扩大影响 | Receive 只写承诺被 CLI 功能绕过 | 展示组合能力真实效果，必要时使用独立会话 |
| 邀请复制或转发 | 未预期的访客接入 | 高熵邀请、TTL、人工批准、轮换；承认 bearer 模型限制 |
| 上游依赖/API 变化 | 编译或安全行为变化 | 固定 revision、兼容测试、依赖升级评审 |
| 同类工具覆盖相同能力 | 产品收益不足 | 同任务对照，不用功能堆叠代替验证 |

### 21.2 已确定决策

| 决策 | 内容 | 原因 |
|---|---|---|
| ADR-01 | 固定四个命令 | 清晰边界，避免扩成远程管理平台 |
| ADR-02 | Tailcat 为唯一默认会话传输 | 保留项目原始技术路线 |
| ADR-03 | 单进程 Native + 浏览器客户端 | 减少部署与运维复杂度 |
| ADR-04 | 默认无账号、临时邀请 | 适配临时分享，避免引入中心身份系统 |
| ADR-05 | v1.0 无 Session 注册数据库 | 邀请自包含，权威状态在分享端 |
| ADR-06 | 业务协议逐资源授权 | Tailcat 隧道连接成功不等于拥有全部业务权限 |
| ADR-07 | 独立不可信内容域 | 防止代理网页取得终端/上传/邀请权限 |
| ADR-08 | Web 采用兼容等级 | 浏览器桥接无法假定等价于完整反向代理 |
| ADR-09 | Receive 单向、无覆盖、无执行 | 控制最初的文件访问与误操作范围 |
| ADR-10 | 默认 TTL 一小时 | 让临时访问有明确期限 |
| ADR-11 | Dev 是组合任务入口 | 在固定范围内优化整体使用流程 |
| ADR-12 | WebRTC 是研究项，不做隐式替换 | 避免改变加密、身份和基础设施模型 |

### 21.3 P0 必须冻结的工程细节

以下是实施前的技术验证任务，不是产品范围悬而未决：Tailcat revision 与 WASM 导出层、可信 peer 身份读取方式、VT 状态恢复实现、SW/Bridge 的跨浏览器控制流程、Cookie 兼容子集、原子不覆盖提交的跨平台实现，以及应用帧格式与流量基准。

这些事项需要实验结果；本文不把尚未运行的设计包装为已经验证的代码。对应验证结果应以 ADR、协议 RFC 和测试报告附在仓库，而非继续扩展产品命令。

### 22.2 退出状态与错误契约

进程退出采用稳定分类：`0` 正常完成或正常结束会话；`2` 参数/配置错误；`3` 资源初始化失败；`4` 传输启动失败；`5` 安全或策略拒绝；`6` 内部错误。常规 SIGINT/SIGTERM 由平台约定记录，自动化使用结构化结束原因区分。

应用错误码至少包含：

```text
INVALID_ARGUMENT       TARGET_NOT_ALLOWED       TARGET_UNREACHABLE
TLS_VERIFICATION_FAILED INVITE_INVALID          INVITE_EXPIRED
INVITE_REVOKED         APPROVAL_REQUIRED        MEMBER_LIMIT_REACHED
PERMISSION_DENIED      CONTROL_IN_USE           RESOURCE_UNAVAILABLE
WEB_FEATURE_UNSUPPORTED BROWSER_UNSUPPORTED     PROTOCOL_MISMATCH
FILE_TOO_LARGE         QUOTA_EXCEEDED           INVALID_FILENAME
DISK_WRITE_FAILED      HASH_MISMATCH            UPLOAD_CANCELLED
SESSION_CLOSED         REQUEST_RESULT_UNKNOWN   TRANSPORT_UNAVAILABLE
```

每个错误码要有用户文案、可重试性、影响范围和是否包含内部诊断字段的规范。不能让错误详情成为泄漏秘密与绝对路径的旁路。

### 22.3 仓库文档

必须交付 README、四命令使用说明、能力/兼容矩阵、威胁模型、安全报告入口、自托管指南、依赖/版本清单、协议文档、发布检查表和可复现性能报告。

README 第一屏直接展示四命令与推荐口号。明确写出访问端无需安装、分享端仍需运行；Web 链接依赖浏览器运行时；指定 CLI 不构成沙箱；浏览器当前路径依赖 DERP。

### 22.4 最终完成定义

**只有当一个没有安装 TailMouse 的访客，能够用支持的浏览器打开链接，在声明的权限范围内完成终端、Web、上传或组合任务，并且分享者可以可靠地结束访问，才视为产品能力完成。**

API 存在、页面能够显示、单次演示成功或使用了 Tailcat 都不足以替代完整验收。

项目范围至此固定为：

```text
tailmouse cli
    Share an interactive terminal.

tailmouse web
    Share a selected web service.

tailmouse receive
    Receive files from a browser.

tailmouse dev
    Bring them together in one live dev session.
```
