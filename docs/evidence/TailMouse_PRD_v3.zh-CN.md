## 1. 产品目标

接收方可以选择最合适的入口：手机或临时设备打开浏览器；已安装 TailMouse 的电脑直接在自己的终端里操作远端任务。两种入口访问同一个 Host、同一个任务和同一套权限。

Native 接收端使用 Tailcat 已有的原生网络能力，在网络允许时通过加密 UDP 直连传输，无法直连时使用 DERP。它不依赖浏览器 Wasm，也不等待 Tailcat 的浏览器 WebRTC 支持。

原生接入的产品承诺：

- 运行一条接入命令，在隐藏输入界面粘贴原邀请，再按 Host 的访问模式完成认证。
- 目标程序继续在 Host 的原目录和环境运行，接收方无需安装目标 CLI。
- 在接收方熟悉的终端中使用 Shell、全屏 TUI 和 CLI，支持键盘、粘贴和尺寸变化。
- 离开后任务按原规则继续运行；稍后可以从 Native 或 Browser 接回。
- 直连能力和当前实际路径分别表达，不把“Native”显示成“已直连”。

浏览器免安装入口继续存在。Native 是增加一种接收方式，不要求现有浏览器用户安装软件。

## 3. 范围

### 3.1 必须交付

1. 同一个 `tailmouse` 可执行文件中的 Native Leash 接收命令。
2. 完整邀请与独立访问码的交互式隐藏输入。
3. 与 Browser 相同的 Host 认证、权限、启动策略和唯一远端名额。
4. Native 终端输入、输出、尺寸同步、只读查看和现有进程控制。
5. 明确的本地离开操作、终端恢复、再次接入和最终结果展示。
6. Native ↔ Native 的真实直连、DERP 回退和路径变化验证。
7. Browser 与 Native 之间先离开、再接入的切换。
8. 跨平台构建、真实运行、协议一致性和凭据保护验收。

### 3.2 平台与角色

| 角色                 | 本阶段支持范围                                              |
| -------------------- | ----------------------------------------------------------- |
| Native Host          | 沿用 macOS 13+、Linux glibc、Windows 11，均覆盖 amd64/arm64 |
| Native Client        | 同一桌面平台及架构矩阵，使用受支持的交互终端                |
| Browser Client       | 保留已交付浏览器范围，包括 iOS Safari 与 Android Chrome     |
| Native Escape 接收端 | 不新增；原有 Escape Host 与浏览器体验保持                   |

本稿的 Native 指原生 CLI 接收端。iOS/Android 原生 App、Electron/Tauri 桌面壳不属于首发范围。将网页安装为 PWA 仍属于 Browser Client。

### 3.3 不包含

不新增账号、云端会话列表、后台守护进程、多任务管理、多人同时接入、强制踢人接管、文件传输、远程桌面、任意附加已有进程、完整历史落盘或跨 Host 重启恢复。

不建立本机 HTTP/WebSocket 网关，不要求浏览器通过本机代理获得直连。不自行实现 WebRTC、DERP、WireGuard 或 NAT 穿透，不为本阶段引入 Rust/Wasm 重写或 cgo 性能分支。

Native Client 不创建目标程序的副本，不接受本地输入来替换 Host 保存的启动命令、cwd 或环境。用户需要连续执行任意命令时，仍应由 Host 明确共享一个交互式 Shell。

## 4. 用户场景

### U3-01：从另一台电脑接手 Shell

电脑 A 使用 `tailmouse leash -- bash` 共享 Shell。电脑 B 已安装 TailMouse，在本机终端进入 Native 接入流程，粘贴邀请并输入访问码。认证后看到 A 的终端，输入命令仍在 A 执行。

### U3-02：手机离开后切换到电脑

用户先用手机浏览器查看任务，主动离开后在电脑 Native Client 接入。任务身份、代次、权限和最近输出不变，不重新启动目标程序。反向切换也成立。

### U3-03：网络允许时直接传输

两台电脑先通过 DERP 建立加密连接。Tailcat 确认直连路径后，终端流量改走直连。用户无需输入公网 IP、手工映射端口或理解打洞参数。

### U3-04：企业网络无法直连

网络阻止直接 UDP 连接时，Native Client 通过 DERP 继续使用，并明确显示中继状态。中继本身不可达时，连接在有限等待后失败，任务不会因此被误报为退出。

### U3-05：回来查看已经结束的任务

用户离开 Native Client，任务随后结束。Host 仍保留共享时，用户用原邀请和同一访问码再次接入，看到实际结果和最近输出，不自动重启任务。

## 5. CLI 与首次体验

以下是 **V3 拟新增的命令形态，当前版本尚不支持**：

```sh
# On the host: existing command shape.
tailmouse leash -- bash

# On the receiving computer: proposed V3 command.
tailmouse connect
```

`tailmouse connect` 的首发流程：

1. 检查本地交互终端能力。
2. 提示粘贴完整 TailMouse 邀请，输入不回显。
3. 在内存中校验邀请，再建立加密连接并确认 Host 的访问模式。
4. 默认模式下提示输入独立访问码，输入不回显；显式无密码共享显示第二阶段要求的警告。
5. Host 认证、准入及必要初始化成功后，进入远程终端。
6. 离开或连接结束后恢复本地终端，显示不含凭据的结果。

不提供把完整邀请或访问码放入位置参数、命令行选项、环境变量、配置文件或自动历史记录的入口。示例不得让用户把凭据粘贴进 Shell 命令。接收端不自动读取剪贴板，也不自动保存最近邀请。

首发只承诺交互式终端接入。没有可用交互终端、stdin/stdout 被重定向等场景应在联网前给出明确错误，不偷偷切换为脚本、日志导出或凭据文件模式。

安装完成且已持有合法邀请时，Native 接入不需要打开 `link.tailmouse.com`、请求邀请对应网页或下载 Wasm；仍需满足 Host 与必要网络服务的可达性条件。现有自托管浏览器邀请也应按相同邀请规则解析。

## 6. 核心行为要求

### N3-01：同一 Host、两种接收端

- Host 同时接受符合兼容要求的 Browser 或 Native 接入尝试，不为 Native 生成另一类任务。
- 原始完整邀请可以用于两种接收端；客户端类型不作为授权依据。
- Native 只接受明确支持的 Leash 邀请。收到 Escape 或未知模式邀请时，在取得终端控制权前拒绝并提示使用相应入口，不回显完整邀请。
- 目标程序、PTY/ConPTY、输出缓存和任务结果均由 Host 持有。Client 不创建远端进程的本地副本。

### N3-02：统一认证与准入

- Native 与 Browser 遵守第二阶段 P2-11/P2-12 的相同访问模式。
- 默认每条新网络流都由 Host 验证独立访问码；直连、已知客户端身份、曾接入过或使用 Native 均不免认证。
- 认证和准入完成前，不发送终端历史、实时输出、标题、PID、任务状态或结果，不触发远端启动和控制。
- 认证失败预算按同一共享累计，切换 Browser/Native 或更换连接不能重置；未认证资源保持有界。
- 只有 Host 启动时明确选择的 `--no-password` 可以省略访问码。Native Client 不新增绕过开关，旧版本能力缺失不能解释为无密码共享。
- 默认启动策略仍为 `connect-or-enter`；任一获准接收端可以成为首次远端启动触发者，但最多启动一次。

### N3-03：唯一活跃远端

- 同一共享的 Browser 和 Native 合计最多一个活跃远端，只读连接也占用名额。
- 一个已认证远端正在使用时，另一个收到忙碌提示，不自动驱逐旧连接。
- 本地 Host 的终端操作能力继续保留，不占远端名额。
- 半断开连接必须在有限检测与清理后释放名额；具体期限沿用或同步修订已交付协议，不新增永久占用状态。
- 切换接收端时，旧连接未执行的输入、resize、控制请求不得在新连接中补发。

### N3-04：真实终端交互

- Native Client 使用本地终端显示远端 UTF-8、ANSI、光标定位、颜色和 alternate-screen TUI；受第 N3-08 条本机安全边界约束。
- 支持常用键盘控制、Esc/Tab/方向键、Ctrl/Alt、中文输入、多行和括号粘贴。不得按目标 CLI 名称解析或改写文本。
- 输入保持单一有序发送路径；只读或未获准状态不发送用户输入。
- 本地尺寸变化沿用 Host 的范围与去抖规则。只读状态下的尺寸请求也受明确权限约束，不暗中获取控制权。
- Client 控制界面、网络提示和诊断不能与远端输出并发写入同一显示区域，破坏正在运行的 TUI。
- 目标兼容性必须以真实 Shell、Vim/其他全屏 TUI、长输出和目标 AI CLI 验证，不能仅以 echo 测试声称完成。

### N3-05：离开与进程控制分离

- 必须提供独立的本地离开操作，不能用退出远端 Shell 或杀死任务来实现断开。
- `Ctrl+C` 默认保持远端终端输入语义，不被 Client 当作本地退出快捷键吞掉；只读时不转发。
- 提供现有 Host 所允许的 Interrupt、Terminate、Restart 控制入口。Terminate 与 Restart 必须有明确的本地确认，且始终由 Host 再检查能力和当前代次。
- 本地控制入口必须有可发现的提示、发送字面快捷键的方法，并避免粘贴内容触发离开或控制。
- 建议使用一个本地 escape 前缀组织离开和控制；最终按键、超时、字面输入及控制界面恢复方式由 OpenSpec 定稿，不先加入可配置快捷键框架。
- 主动离开只结束当前接入，任务按既有生命周期及用户显式配置处理，包括已明确启用的断线终止策略。

### N3-06：终端恢复与结果表达

- 凭据输入阶段关闭回显；进入远程交互后正确管理 raw mode 和终端模式。
- 正常离开、错误、取消、可处理信号和 panic 清理路径都必须恢复 Client 修改的本地终端状态，并释放网络与输入读取资源。
- 未发送完的本地输入不得在退出后落入接收方 Shell，被当作命令执行；无法提供安全输入边界的终端不能标为支持。
- 连接断开不代表任务完成。只有收到 Host 的终态证据，才能显示具体任务结果。
- Windows 等平台的完整任务退出状态必须准确显示，不为迁就 Client 操作系统的退出码范围而截断显示值。
- 接入命令的本地退出码与远端任务结果分别定义；用户离开、认证失败、连接失败和已观察到任务退出不得混为同一种结果。数值映射在协议与 CLI 设计中确定。

### N3-07：有限输出与再次接入

- 继承第二阶段最近输出默认 1 MiB、范围 64 KiB 至 16 MiB、覆盖旧内容和结果保留规则，不增加第二份持久历史库。
- Native 获准接入后按协议接收 reset、有限历史、丢弃提示及实时输出，保持快照边界和任务代次一致。
- 大快照应有界消费，不因 Host 配置为 16 MiB 就在 Client 另建无限排队或重复历史副本。
- 原始字节尾部不能保证还原任意 TUI 完整屏幕；Native 与 Browser 必须一致表达截断事实，并验证后续交互仍然可用。
- Client 离开、崩溃或断网不清理 Host 的任务与结果；显式关闭策略除外。
- 新进程接入须重新提供邀请并按访问模式认证。同一个仍运行的 Client 可支持用户主动重试，但每条新流重新认证，重试有界、不重放旧输入。
- 不承诺后台自动重连、设备免认证、Host 重启恢复或自动接管。

### N3-08：凭据与本机终端安全

- 完整邀请、Tailcat 连接材料和访问码只在必要内存及授权交互中使用，不进入 Client 日志、错误、进程参数、环境、配置、崩溃采集、测试快照或历史列表。
- 无论邀请指向官方还是自托管网页，Client 都只解析邀请，不把完整 URL 当成 HTTP 请求发送。
- 接收方的真实终端会解释控制序列。Native 不新增远端读取或写入本机剪贴板、启动本机程序、自动打开链接或下载文件的能力。
- 必须有明确且经过验证的输出控制序列边界，至少阻止 OSC 52 剪贴板读取/写入；覆盖跨帧、跨快照、截断、异常终止和超长序列，处理缓冲有硬上限。
- 该边界只限制本机副作用，不修改 Host 保留的原始历史，不将普通终端文本统一转义成无法使用的 TUI。其他终端扩展及查询响应的允许范围在支持矩阵和 OpenSpec 中列明。
- 不宣称 Native 具有浏览器沙箱。目标终端自身自动记录、扩展或用户主动复制的行为须与 TailMouse 自身不持久化的承诺区分；不擅自修改用户终端全局设置。

### N3-09：直连、回退与路径状态

- Native Host 与 Native Client 使用 Tailcat 原生传输，先通过 DERP 完成发现与建连，再由 Tailcat 尝试 UDP 直连。
- 直连成功后，应用数据走已确认的直连路径；无法直连时继续使用允许的 DERP 中继，保持端到端加密和相同应用权限。
- DERP 回退是明确的网络策略，不是认证、加密或协议兼容降级。中继不可达且没有可用路径时应有界失败。
- 不承诺零中继依赖：即使数据已经直连，发现、路径协商或回退仍可能依赖 DERP；不承诺中继停机时首次接入必然成功。
- 对用户展示 `Direct`、`Relay` 或 `Unknown`，并与“正在连接/已连接/已断开”分开。状态必须有上游路径证据；不能按 RTT 较低、同一局域网或 Native 类型推断直连。
- 路径状态注明是当前观测还是最近探测，过期信息不能永久显示为当前直连。不为展示状态记录凭据或公开完整网络发现数据。
- 路径变化本身不创建新任务、扩大权限或重放输入。若底层流确实失效，按断线和新流认证规则处理；不把无法保持的流伪装成无损迁移。

### N3-10：统一中继与浏览器入口

- 继承 Host 的 official/custom-host/custom-map 选择和邀请包含的连接信息，接收方无需重复输入中继配置。
- 保留第二阶段官方浏览器入口 `https://link.tailmouse.com/` 及自托管能力。
- Browser 继续使用已验证的 Tailcat Go/Wasm 能力；当前为 DERP-only，不因 V3 增加 Native 就宣称浏览器直连。
- 上游未来支持浏览器 WebRTC 时，再通过独立升级、适配和验收接入，不作为 V3 已实现能力或交付条件。

### N3-11：同一协议与兼容性

- Native 通过 Tailcat 字节流实现 TMOUSE 客户端，不将终端字节直接接到未经握手的传输上。
- Host、Native Client 与 Browser 共享消息语义、权限、任务代次和黄金用例。Go 接收端必须按客户端方向处理消息，不能直接复用只接受服务端方向的解码策略。
- 采用最终已交付的第二阶段认证协议作为基础；Native 所需能力、版本协商及错误必须显式定义，不把产品 V3 当作协议版本号。
- 新旧版本是否兼容以明确协商及测试矩阵为准。缺少认证模式或必要能力时拒绝接入并提示升级，不静默回退到旧的仅链接模式。
- 正式同版发行的 Host/Native Client 和 Web 使用同一记录的 Tailcat gitlink，并保留 TailMouse 版本和支持的协议范围。

### N3-12：分发与安装

- 同一原生发行包同时包含 Host 与 Native Client 能力，使用已有 Go/GoReleaser 发布链；工具版本由工程配置锁定。
- 接收方不需要单独安装 Tailcat、Tailscale、目标 CLI、Go 工具链或浏览器 Wasm。
- 沿用六个 OS/架构产物、校验和、SBOM、许可证与第三方声明要求，不把交叉编译当成真实平台通过。
- Native 支持不要求新增 cgo、第二个常驻进程、新的工作区包或网络服务。若实际依赖边界迫使改变这些选择，先提交有证据的设计替代方案。

## 7. 性能与资源边界

| 项目                   | V3 要求                                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| 连接等待               | 沿用已交付的有限连接超时；当前基线为 60 秒，人工输入邀请/访问码的等待单独统计                   |
| 终端帧与输入预算       | 沿用最大 32 KiB 终端帧和 256 KiB 待发送输入上限，计入在途数据                                   |
| Host 最近输出          | 默认 1 MiB，配置范围 64 KiB 至 16 MiB，不随离线时长增长                                         |
| Native 待显示终端输出  | TailMouse 自有未消费输出预算不超过 1 MiB，包含在途块；快照分块消费                              |
| 慢接收端               | 不阻塞 Host 子进程，不无限增长 Client 内存；按已定义规则丢弃并提示或有界结束连接                |
| Native Client 空闲内存 | 以低于 150 MiB 为初始产品目标，包含本进程的 Go/Tailcat 运行时和所有缓存；本机终端模拟器单独记录 |
| 长时间稳定性           | 至少覆盖 8 小时连接/离开/重新接入和超过缓存十倍的输出，不随重连次数累计资源                     |
| 性能证据               | 分别记录发现、认证、首屏、可交互时间、RTT、吞吐、CPU、内存和当前路径；不承诺固定倍数提升        |

内存报告明确 OS、版本、架构、测量工具及 RSS/footprint 等实际指标，不互换口径。Native 路径不加载 Wasm，但这本身不是内存目标已达成的证据。

对比 Browser、Native 直连、Native 中继时使用同一 Host、任务和数据量，说明网络差异。直连减少了中继路径，但吞吐仍可能受终端解析、Host 输出及设备性能限制。

## 8. 接收端切换与状态

| 事件                           | Host 与任务                  | 接收端行为                                          |
| ------------------------------ | ---------------------------- | --------------------------------------------------- |
| Browser 正常离开后 Native 接入 | 同一共享、原任务或保留结果   | 新流认证，取得唯一名额，恢复有限输出                |
| Native 正常离开后 Browser 接入 | 同上                         | 使用原始完整邀请，重新输入访问码                    |
| Browser 与 Native 同时竞争     | 最多一个成功，不重复启动任务 | 另一个收到忙碌提示                                  |
| Direct 变为 Relay，原流仍有效  | 任务、认证和权限不变         | 更新有证据的路径状态，不重放输入                    |
| 路径故障导致原流失效           | 按显式进程策略保留任务或结果 | 清理本地终端，允许用户重新发起接入                  |
| 任务退出                       | 按第二阶段保留最终结果       | 显示真实结果，禁用普通输入；重启需明确操作          |
| Host 撤销或显式到期            | 邀请与已启用访问码失效       | 两类接收端同样断开，清理待执行输入                  |
| Native Client 被关闭或崩溃     | 不因客户端类型改变任务策略   | Host 有界清理失效连接，不声称可恢复已销毁的本地凭据 |

## 9. 实现边界与待定设计

本节描述后续实施约束，不建立新的已接受架构。

### 9.1 Native 接收端

- 优先扩展已有 `apps/cli` 组合入口，在现有 Tailcat 适配边界内增加原生拨号，向会话代码提供 TailMouse 自己的字节流接口。
- 复用 Go 协议编解码、邀请校验和可适用的终端平台能力；Host 与 Client 生命周期各自明确，不为两个角色建立通用框架。
- Native 是客户端语义的新增消费者，但不会自动共享 TypeScript 实现。TMOUSE 终端协议通过相同协议与用例保证一致性，不引入跨语言代码生成器；官网 API 类型生成见第 9.2 节。
- Native 输出控制序列处理属于新的本机安全边界；设计须说明为何需要、具体范围及更简单方案的不足，不能顺势重写终端模拟器。
- 不改变外部 Tailcat 源码或自动更新 gitlink。路径观测应优先使用已提供的公开 API；若观测不能证明业务流当前路径，显示 Unknown 或明确标为探测结果。

实施前 OpenSpec 必须解决：

1. `connect` 的完整 CLI 契约、本地退出码，以及与远端完整退出状态的映射。
2. 本地 escape 键位、确认界面、粘贴边界和 TUI 恢复方案。
3. 第二阶段最终认证协议、客户端能力和新旧版本兼容矩阵。
4. OSC 52 与其他终端扩展的有界处理、查询响应及真实终端支持清单。
5. 路径观测 API、信息有效期、断流判定、取消和资源预算的具体数值。

这些项目是实施设计工作，不是通过放宽产品要求跳过验收的理由。

### 9.2 官网技术栈

以下为用户于 **2026-09-04** 指定的官网选型（reported）。官网沿用第二阶段为 `tailmouse.com` 保留的产品站定位，浏览器终端入口仍为 `link.tailmouse.com`。本表记录 V3 规划，不表示已经迁移现有 `apps/web` 或安装这些依赖。

V2 的 `link.tailmouse.com/<六位 Base62>` 短链接、R2 静态产物和有界映射服务不属于官网技术栈迁移。V3 官网可以链接到浏览器入口，但不得复制邀请映射、保存访问码或把终端流量接入官网 API。

| 层次       | 选型                                 |
| ---------- | ------------------------------------ |
| UI 框架    | React 19.2                           |
| 语言       | TypeScript strict                    |
| 构建工具   | Vite 8                               |
| 路由       | TanStack Router，文件路由             |
| 服务端数据 | TanStack Query                       |
| 样式       | Tailwind CSS 4.3 + CSS Variables      |
| 交互组件   | Radix Primitives，按需使用            |
| 表单       | React Hook Form + Zod                 |
| 实时       | 原生 WebSocket + cursor 补拉          |
| API 类型   | Rust OpenAPI 自动生成                 |
| 全局状态   | 暂不上 Redux / Zustand               |
| 国际化     | react-i18next                        |
| PWA        | 先 Manifest，后 Service Worker        |
| 测试       | Vitest + Testing Library + Playwright |

官网 API 类型以 Rust 侧产出的 OpenAPI 描述为来源自动生成；具体 API 功能、生成工具和兼容策略由后续 OpenSpec 明确。官网实时更新采用原生 WebSocket，并通过 cursor 补拉缺失数据；事件顺序、去重、游标过期及有界重连/补拉规则也须在实施前定义。这些选型不替换 Tailcat/TMOUSE 终端通道，不要求重写 Go Host 或浏览器 Go/Wasm。

官网 PWA 按先 Manifest、后 Service Worker 的顺序推进；此顺序不改写现有 Browser Client 的静态资源缓存要求。引入 Service Worker 时明确缓存与更新范围，不缓存邀请、访问码、会话响应或终端数据。

实施前核验所列版本的可用性、依赖兼容性并锁定具体版本，在独立 OpenSpec 中说明官网构建/部署边界及每项新增依赖的实际用途；本次不增加账号、云端会话管理或其他未定义的服务功能。

## 12. 风险与评审重点

- **直连收益未知：** 需要真实路径和相同负载对比；公开 DERP 质量、NAT 和设备差异可能决定最终体验。
- **Native 本机副作用：** 系统终端与浏览器 xterm 的控制序列边界不同，不能把所有字节直接写入本机终端后宣称保护一致。
- **终端控制可用性：** 本地离开、确认操作和 TUI 输出隔离需要原型验证，避免为了 Native 增加一套完整终端模拟器。
- **跨端一致性：** 认证、只读、单远端、任务代次和断线清理必须由 Host 统一控制，不能在各 UI 独立决定。
- **依赖变化：** Tailcat 的拨号与路径观测接口仍需按具体 gitlink 验证；新增 Native 不授权修改外部子模块。
- **产品重心：** 保留浏览器入口，Native 明确为安装后的可选接收能力，不能让首次浏览器体验变复杂。
