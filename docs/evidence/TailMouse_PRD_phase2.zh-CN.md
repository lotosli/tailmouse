## 1. 产品目标

**Control any CLI from your browser.**

在已有机器上用 TailMouse 启动一个命令，把它变成可通过浏览器访问的终端会话。自己换设备，或者把邀请和独立的临时访问码交给协作者，对方打开链接、输入访问码并通过 Host 验证后，即可查看和操作原机器上的这个终端。目标程序继续使用原机器上的文件、工具和环境。

第二阶段把 Leash 作为产品主入口，面向通用 CLI、交互式 Shell 和 TUI；AI 编程 CLI 是重要示例。`link.tailmouse.com` 客户端接入页、帮助和 README 示例围绕“启动命令 → 打开链接 → 输入访问码 → 操作终端 → 离开后返回”展开。Escape 保留已有能力，产品主路径不要求用户先玩游戏。

用户可以关闭浏览器、锁屏或暂时离线，稍后使用原始分享链接和同一访问码查看最近输出，并继续操作同一个任务。任务在用户离开期间结束，也应能在 Host 仍运行时通过验证查看结果。

产品承诺：**一个命令生成浏览器入口；任务可以无人观看地继续运行；回来时接回原任务，看到最近输出或最终结果。**

“保持有效”的前提是同一个 TailMouse Host 仍然运行、未主动结束共享，且没有到达用户明确设置的截止时间。再次接入时需要 Host 网络可达。Host 重启后的恢复不属于本阶段。

### 1.1 要解决的用户障碍

- 接收方为了临时操作一个命令，还需要安装远控客户端、配置 SSH 或加入完整网络。
- 用户想从另一台设备接手原机器上的 CLI，又不希望重新准备工具、项目和执行环境。
- 用户需要多轮排障，却只能反复让对方执行命令并转发输出。
- 用户为了保住会话，被迫让手机浏览器一直在线。
- 用户离开超过断线宽限后，原链接失效，但本地任务可能仍在运行。
- 长任务遇到默认四小时截止，用户必须事先理解和修改参数。
- 任务完成十分钟后结果被清理，用户晚些回来无法查看。
- 用户不知道再次接入是否会重新启动任务，或者是否必须重新生成链接。
- 用户希望临时交出终端操作权限，但不希望仅因分享链接被转发或泄露，对方就能查看输出或控制任务。

### 1.2 成功的用户体验

以下为默认启用访问码的流程；显式无密码流程保留同样的邀请、连接、权限和生命周期规则。

1. 发起方安装 TailMouse，并在已有工作目录中启动目标命令。
2. Host 为本次共享自动生成随机临时访问码（临时密码）。使用官方入口的默认受保护 Leash 另生成区分大小写的六位 Base62 短链接，并与访问码分开展示；二维码只包含短链接。完整邀请由官方短链服务在有限租约内明文保存，但服务不接收访问码。默认使用官方 DERP，双方无需填写中继地址或配置路由器。
3. 发起方或协作者打开邀请，看到访问码输入界面。Host 验证成功后，浏览器才显示终端输出并开放获准的操作。接收方无需安装 TailMouse 或目标 CLI。
4. 用户离开浏览器，等待任务执行，稍后打开原始邀请并再次输入同一访问码，查看最近输出和任务状态，按需继续输入或查看结束结果。离开期间无需保持浏览器后台连接。
5. 发起方可在本地结束共享，立即撤销该共享的远端访问。帮助提示链接与访问码分开传递和保管；若两者一起泄露，仍可能被他人使用。

### 1.3 “any CLI”的具体含义

“any”表达不绑定某一家 Agent、工具或云端运行环境：凡通过标准终端输入输出交互、且位于已支持平台上的命令，都是目标兼容范围。它不表示所有程序已经逐一通过测试，也不包含原生桌面窗口、已在其他终端独立运行进程的任意附加，或程序自身不提供的恢复能力。

| 用户意图                        | 应启动的对象                                     | 完成后的行为                                        |
| ------------------------------- | ------------------------------------------------ | --------------------------------------------------- |
| 继续操作一个 AI 编程 CLI 或 TUI | 该 CLI 程序                                      | 程序运行时继续交互；退出后查看保留结果              |
| 运行一个构建、测试或脚本        | 该命令                                           | 命令退出后进入结果保留，不自动变成 Shell            |
| 与对方连续执行多条排障命令      | 交互式 Shell，如 `bash`、`zsh` 或已安装的 `pwsh` | 单条命令结束后回到原 Shell 提示符，可继续输入下一条 |

示例沿用现有 CLI 语法，要求目标程序已在 Host 安装。以下短命令以第二阶段官方网页默认值完成配置为前提：

```sh
tailmouse leash -- bash
tailmouse leash -- claude
tailmouse leash -- codex
tailmouse leash --start-on now -- make test
```

默认启动策略仍采用 `connect-or-enter`：先显示邀请与访问码，首次通过 Host 认证并获准接入的远端或本地 Enter 触发启动。启用访问码时，第二阶段明确把浏览器启动触发点从“有效握手”收紧为“认证成功且获准接入”；仅建立网络连接、发送 HELLO 或输入错误访问码不得启动任务。显式 `--no-password` 时，首次完成有效握手并获准接入即可触发，不要求不存在的访问码。本地 Enter 和现有 `--start-on now` 无需等待远端认证。这份 PRD 不引入 Agent 专用启动适配器。

## 3. 范围

### 3.1 本阶段必须交付

1. Leash 默认无固定总时长截止；支持用户主动设置时限。
2. 浏览器离开后共享保持可再次接入，后台任务继续执行。
3. 原始分享链接在同一 Host 会话中可重复使用。
4. 再次接入同一个进程、PTY/ConPTY 和任务代次，补发有限最近输出。
5. 无浏览器时持续读取任务输出，缓存满后覆盖最旧内容。
6. 任务退出后默认保留最后结果和有限输出，直到 Host 退出、主动结束共享或明确设置的时限到达。
7. 保持一个活跃远端，并正确清理旧连接及其未执行输入。
8. 清楚区分浏览器离开、任务完成、连接失败和共享结束。
9. 以通用 CLI 为中心的官方客户端接入页、帮助与 README，覆盖持续交互、短任务结果和连续 Shell 排障三类使用方式。
10. 可通过 `https://link.tailmouse.com/` 访问的浏览器客户端，以及默认使用官方 DERP 的完整接入路径。
11. Leash 默认要求独立临时访问码，由 Host 验证；覆盖首次接入、再次接入、只读查看及结果保留，提供防猜测与本地撤销。
12. 提供 `--no-password`，允许发起方明确选择本次共享仅凭邀请访问；CLI 必须警告，浏览器明确展示未启用密码的状态。
13. 官方默认受保护 Leash 使用 `https://link.tailmouse.com/<六位 Base62>`，二维码按实际短链接紧凑显示；映射具有有限租约、Host 续租和共享结束即时删除，且服务不接收访问码。

### 3.2 延续的产品边界

- 仍然围绕一个明确启动的终端命令及其进程树工作，保留现有启动和显式重启能力。
- 输出保留在 Host 内存中，容量有上限；本阶段没有完整任务历史库。
- Escape 的回合规则、默认 TTL 和断线结束规则不随 Leash 一起修改。
- 平台范围沿用当前版本最终交付的支持承诺；本阶段不借此删减现有终端、输入或进程控制能力。
- 核心命令、浏览器客户端和自托管路径保持开源。公开网页与官方免费 DERP 可作为初期体验入口；商业套餐、专属中继、团队管理和 SLA 不在本阶段定价或实现。

### 3.3 本阶段不包含

账号或云端会话列表、跨 Host 重启恢复、系统后台守护进程、完整日志落盘、多任务管理、多人同时观看或控制、文件传输、桌面或单窗口共享、Agent 专用协议与审批中心、通知推送、电脑唤醒和虚拟机管理。也不建设 TailMouse 自有终端中继服务或通用会话控制平面；唯一服务端例外是本阶段明确规定的受保护 Leash 短链接映射。

浏览器重启后自动找回邀请、记住访问码或信任设备、浏览器与 Host 都退出后继续查结果，也不属于本阶段的承诺。

## 4. 完整用户故事

US-01 至 US-10 采用默认访问码流程：通过浏览器查看或控制终端，均以持有有效邀请、通过本次共享的访问码验证并获准接入为前提。新页面需重新输入访问码；它在同一 Host 共享期间保持有效。本地操作不需要远端认证。显式无密码流程见 US-11。

### US-01：离开后继续操作长任务

用户在电脑上通过 Leash 启动一个交互式终端任务，用手机查看初始进度，然后锁屏离开。一个小时后，用户重新打开原始分享链接。

期望：手机接回同一个任务，显示当前状态和最近输出。若程序正在等待输入，用户可以继续回答。此次接入不创建新任务，也不重新执行启动命令。

### US-02：任务在离开期间结束

用户启动测试或构建后关闭浏览器。任务二十分钟后退出，用户两小时后回来，电脑上的 TailMouse Host 一直运行。

期望：显示“任务已结束”、原始退出码和保留的最后输出。任务不会因为用户回来而自动重启，结果不会因为无人查看而在十分钟后消失。

### US-03：输出很多，但只需要看最近情况

后台任务持续输出大量日志，无浏览器在线。输出总量远大于配置的缓存容量。

期望：任务继续执行，Host 只保留容量允许的最近输出。用户回来时看到最近内容，并获知更早输出已被丢弃。任务状态和退出码不随旧输出一起丢弃。

### US-04：从手机切换到另一台设备

用户先在手机上操作，随后离开该连接，再在另一台设备上打开同一原始分享链接。

期望：Host 确认旧连接已断开后，允许新设备接入同一个任务。如果旧设备仍然占用活跃连接，则明确提示已有连接，不擅自抢占。

### US-05：用户明确需要临时共享

用户做临时排障，明确设置一小时分享时限。期间关闭浏览器并重新接入数次。

期望：再次接入不会重置截止时间。一小时到达后共享结束。任务是否被终止继续遵循用户明确设置的进程策略。

### US-06：任务先运行，用户很晚才首次查看

用户通过现有立即启动选项运行长任务，暂时没有任何浏览器连接，超过四小时后才首次打开邀请。

期望：默认配置下仍能接入并看到当前任务或其保留结果。没有“必须及时首次连接”的隐藏时限；现有等待首次连接才启动的选项仍按用户选择生效。

### US-07：把交互式 Shell 交给协作者做多轮排障

用户在问题机器的工作目录中执行 `tailmouse leash -- bash`，把原始邀请与访问码分开交给协作者。对方通过验证后，在浏览器中依次检查环境、执行诊断命令、根据输出继续下一步，用户可在本地看见同一个终端的操作。

期望：单条诊断命令退出后返回原 Shell，可继续输入下一条；无需反复转发输出或重新创建共享。始终只有一个活跃远端。若用户最初只共享了一个会立即退出的命令，则展示该命令的结果，不宣称仍有可继续输入的 Shell。

### US-08：在手机上继续操作不同的 AI CLI

用户在自己的开发机上通过 TailMouse 启动已安装的 Claude CLI 或 Codex CLI，在本地开始任务。离开电脑后，用手机打开邀请，在终端中查看进度、回复程序提出的问题，或继续输入指令。

期望：仍操作原机器上的原 CLI，使用原来的项目和环境。浏览器呈现该 CLI 的终端界面；本阶段不增加专用对话界面、通知或结构化审批功能。是否兼容及适用版本以实测为准。

### US-09：链接被转发，但未交出访问码

用户把共享链接交给协作者，另外告知访问码。第三人意外获得链接，但没有访问码，尝试打开网页、反复连接或绕过网页直接发送请求。

期望：Host 不向该连接发送终端当前内容、历史、任务结果，也不接受控制或触发尚未启动的命令。失败尝试受跨连接的共享级限速和资源上限约束，不抢占正在工作的远端或结束本地任务。

### US-10：晚些回来，以及主动撤销共享

用户离开两小时后，在新页面打开原始邀请并输入原来的访问码；即使任务已经退出，只要同一 Host 仍保留共享，就可以查看结果。排障完成后，发起方在本地结束共享。

期望：访问码没有独立的五分钟或四小时隐藏期限。主动结束立即断开远端，旧邀请与旧访问码失效；重新启动 Host 创建新共享时生成新的访问码，旧凭据不能恢复共享。

### US-11：明确选择仅凭链接接入

用户为了临时、便捷地分享终端，显式运行 `tailmouse leash --no-password -- bash`。CLI 在展示邀请前警告：此共享没有独立密码，任何持有完整邀请的人都可按共享权限访问。用户将链接交给信任的协作者。

期望：不生成或要求输入访问码；接收方完成邀请校验与握手即可接入，浏览器始终标明“未启用访问密码”。`--quiet` 不隐藏警告，不额外要求用户输入确认。仅省去密码步骤，权限、一个活跃远端、加密、结果保留与主动撤销仍有效。下次启动不传此参数时，自动恢复默认访问码保护。

## 5. 核心行为要求

### P2-01：共享会话的生命周期独立于浏览器连接

- Leash 默认取消四小时总时长限制。
- 关闭网页、锁屏、网络中断、正常离开浏览器连接，不自动结束 Host 的共享会话。
- 三十秒断线宽限不再充当 Leash 会话的存活期限。连接清理或一次重试的截止时间不能使整个共享失效。
- 无浏览器时，Host 继续监听新的接入，并保持任务输出读取。
- 任务退出后进入结果保留状态；此时不因“子进程结束”直接销毁可供查看的共享会话。
- 主动结束共享、Host 退出、用户设置的时限到达，以及不可恢复的 Host 故障，可以结束会话。普通浏览器连接失败必须与 Host 故障区分。

### P2-02：复用原链接和原任务

- 在同一共享会话和短码租约仍有效的前提下，原始短链接或完整邀请与独立访问码可以多次使用；不因一次浏览器连接断开而轮换访问码或任务身份。
- 再次接入保留原任务代次、原进程和终端状态，不改变启动命令、工作目录或环境。
- 如果原进程已退出，再次接入只查看已记录结果；只有明确的重启操作可以创建新代次。
- 连接仍然健康时可以继续使用已获准接入的网络流。网络流已经断开、页面已销毁或用户换设备时，重新建立网络流、握手并按 Host 的本次访问模式完成准入；默认模式必须重新验证访问码。
- 不承诺复活已经断开的网络连接，也不要求浏览器为保持任务持续后台联网。
- Host 重启、邀请显式到期或共享结束后，旧邀请不能恢复已经结束的共享。

### P2-03：一个活跃远端与旧连接清理

- 任意时刻最多一个活跃远端；只读远端也占用这个名额。本地操作能力按现有规则保留。
- Host 确认旧连接关闭后释放名额，允许新的、已满足本次访问模式要求的连接接入。启用访问码时，未认证连接不占用活跃远端名额，也不能挤掉旧连接；显式无密码仍须完成有效握手与权限检查。半断开的连接沿用明确且有上限的失联检测与清理机制，不能永久占用名额。
- 并发接入时最多一个成功，其他连接收到明确的忙碌提示。
- 旧连接排队但尚未执行的输入、调整尺寸和控制请求不得在新连接中补发。任务已经执行的操作不回滚。
- 清理旧连接只释放该连接的资源；不能顺带释放仍在运行的任务、共享监听或结果缓存。

### P2-04：只保留有限的最近输出

- 默认保留最近 **1 MiB 原始终端输出**，沿用已有 **64 KiB 至 16 MiB** 的配置范围。
- 对用户表达为“最近输出”；不承诺固定行数。字节容量是硬上限，避免超长单行或终端反复改写同一行绕过限制。
- 有无浏览器都使用有上限的缓存。缓存满时覆盖最旧输出，不能为了保留历史阻塞任务，也不能按离线时长增加缓存。
- 再次接入满足本次访问模式要求并获准加入后，先恢复本次显示所需的初始状态，再发送保留的最近输出，随后接入实时输出；边界处不得产生未声明的重复、丢失或乱序。
- 如果更早输出已被覆盖，应明确显示截断提示和已知的丢弃量。用户不应误以为看到的是完整历史。
- 任务状态、代次和最终退出码独立于输出缓存保留。
- UTF-8、ANSI 和终端控制序列可能跨截断边界；验证必须覆盖这些情况，确保后续新输出和交互仍可正常处理。
- 本阶段不把原始字节尾部回放宣传为任意 TUI 的完整屏幕快照。完整历史已被覆盖时，不承诺还原被丢弃内容；现有已交付终端兼容能力仍需回归验证。

### P2-05：任务结束后的结果保留

- 默认保留最后任务状态、任务代次、准确退出码、已有信号信息和有限输出，直到 Host 退出或共享被主动结束。
- 用户显式设置总 TTL 或结果保留时间时，采用先到达的截止时间；新连接不会延长这些时间。
- 结果保留只持有查看与现有重启能力所需的内存状态。已经退出的进程和不再需要的 PTY/ConPTY、管道、句柄应及时释放。
- 任务已结束时禁用普通终端输入；显示任务结果及可用的现有操作。再次接入不得伪装成运行状态。
- 显式重启沿用原命令快照，进入新代次。缓存如何清空和添加重启标记沿用当前约定，不建立跨代次历史库。
- 用户必须能主动退出保留状态。TailMouse 为了保留结果继续运行应在本地显示清楚，不能表现为无提示地卡住。
- 非交互调用仍应能明确选择任务结束后立即退出，避免自动化脚本被默认结果保留阻塞。

### P2-06：重连失败是一次连接的失败

- MVP 提供用户主动发起的重新连接；允许用户稍后再试，不要求实现后台自动重连。
- 每次连接尝试有明确超时、取消和资源清理，沿用已交付连接超时约定。一次失败不能销毁 Host 上仍有效的共享。
- 若未来增加自动重试，必须有次数或时间上限及退避，预算耗尽后停在可见状态；不能以无限循环代替长期有效的共享。
- 浏览器无法连接时，显示连接状态；在没有 Host 结果的情况下，不推断任务已失败或退出。
- 页面销毁后可使用原始短链接或完整邀请重新接入。仅刷新已经清除短路径/邀请片段的地址或打开普通首页，不能自动恢复邀请。
- 沿用内存邀请处理方式。缺少邀请时提示“请重新打开原始分享链接”，不让用户误以为必须结束任务并重新创建共享。本阶段不新增邀请或终端内容的浏览器持久化。
- 启用访问码时，新页面必须重新输入访问码。同一页面的有限重试可复用内存中的访问码，但每条新网络流都重新向 Host 认证；关闭、销毁或主动离开页面时清除该码，不写入浏览器持久存储。显式无密码模式仍需每次完成邀请校验与握手。

### P2-07：主动结束、显式时限与进程策略

- 浏览器上的“离开”只离开当前连接；与“终止任务”“重启任务”等操作清楚区分。
- 本地用户仍可主动结束共享以撤销远端访问。结束后停止接入、断开所有远端连接、丢弃尚未执行的远端请求、清理缓存与会话资源，旧邀请与已启用的访问码同时失效。对仍在运行的子进程执行既有明确关闭策略，不把撤销等同于无条件杀死任务。
- 用户显式设置的正数总 TTL 从共享创建时计算，不因断线、重新连接或任务重启而重置。
- 现有明确选择的断线终止、到期终止策略继续得到尊重；其行为必须在帮助和验收中单独覆盖，不能与新的默认行为混淆。
- 连接离开本身不改写任务退出码；正常结果及 Host 故障的最终退出分类沿用已交付约定。

### P2-08：浏览器与本地状态表达

连接状态与任务状态分别显示，浏览器只有满足本次访问模式要求并获准接入后才能查看任务状态。推荐界面用语如下，具体中英文文案随现有界面统一：

| 情况                    | 应表达的内容                                       |
| ----------------------- | -------------------------------------------------- |
| 已持有邀请，尚未认证    | 请输入发起方提供的访问码；不展示终端内容或任务状态 |
| 访问码缺失或错误        | 无法通过验证，请检查访问码；不回显所输入的码       |
| 认证尝试过于频繁        | 尝试过多，请稍后再试；按 Host 给出的有限冷却提示   |
| Host 显式关闭密码       | 未启用访问密码；持有完整邀请的人可按共享权限访问   |
| 已连接，任务运行        | 已连接；任务运行中                                 |
| 浏览器连接断开          | 连接已断开，可以重新连接；不要无依据地声称任务失败 |
| Host 无浏览器连接       | 无远端连接；任务运行中或结果保留中                 |
| 接回已经结束的任务      | 任务已结束；显示实际退出码和最后输出               |
| 缓存发生覆盖            | 较早输出已丢弃，当前仅显示保留的最近输出           |
| 已有活跃远端            | 当前已有连接，请先离开原连接后再接入               |
| Host 明确报告共享已结束 | 共享已结束；原邀请不能再加入                       |
| 本页面已无邀请          | 请重新打开原始分享链接                             |

### P2-09：围绕一个命令的首次使用

- 对外主文案采用 “Control any CLI from your browser.”，说明“运行在你的机器上，用浏览器查看和操作”。
- 官方客户端接入页、帮助与 README 直接给出“共享一个程序”和“共享交互式 Shell”的示例，明确短命令结束与 Shell 继续等待输入的区别。
- 打开普通 `link.tailmouse.com` 首页时，说明如何在 Host 生成邀请，以及如何重新打开原始邀请；不让用户误以为首页已经连接了机器。
- 默认流程只要求 Host 安装 TailMouse 与目标程序，接收方打开支持的浏览器；不要求注册 TailMouse 账号、安装接收端、加入 tailnet、申请公网 IP 或配置端口映射。
- 默认接入步骤包含输入独立访问码；邀请展示、复制和二维码操作必须清楚区分链接与访问码，不提供默认合并两者的一键分享。
- 外部网络必须允许所需的 HTTPS/WebSocket 出站连接；连接失败应提供清楚的加载、连接或 Host 不可达状态，不承诺穿过所有网络限制。
- 延续本地与浏览器对同一 PTY 的操作能力，明确协作对象和只读状态；不通过广播输入实现多人控制。
- 发布记录分别验证 Shell、短任务、全屏 TUI、目标 AI CLI 的本地和浏览器行为。按实测列出支持情况与限制，不能用口号代替兼容性证据。

### P2-10：公共浏览器入口与官方中继

- 第二阶段官方 Web base URL 采用 `https://link.tailmouse.com/`。启动生成的邀请和二维码使用该地址，无需用户每次手动指定。继续支持现有自托管覆盖配置。
- 完整邀请继续采用 `https://link.tailmouse.com/#…`，连接材料仅放在 fragment 中。官方默认受保护 Leash 对用户展示 `https://link.tailmouse.com/<六位 Base62>`；路径只含区分大小写的定位码，服务在有限租约内明文保存对应完整邀请。访问码不进入 MouseCard、短码、HTTP 请求、服务端存储或日志。
- 六位短码约有 568 亿种组合，仅作为限速定位符，不能宣称具有密码强度。默认受保护 Leash 仍必须输入独立访问码并由 Host 验证。Escape、显式 `--no-password` 和非官方自托管入口继续使用完整 fragment，不以六位码作为唯一 bearer 凭据。
- `link.tailmouse.com` 提供 HTML、JavaScript、CSS、Wasm 和有界短链接 API。目标 CLI 在用户机器运行，终端流量经 Tailcat DERP 转发；短链接服务不处理认证、命令、终端输出或 TMOUSE 流量。
- 无 DERP 覆盖配置时继续使用官方模式，由 Tailcat 选择区域，邀请携带浏览器所需的完整区域信息。接收方无需手填节点，也无需另行配置官方 map 地址。
- 公开产品说明当前浏览器路径经过中继。WebRTC 直连跟踪上游进展，不作为本阶段完成条件；未来接入需单独进行适配和验证。
- 官方免费 DERP 适用于初期体验与验证。其限速、无 SLA 与可能撤回服务的公开边界应在运维说明中保留；对用户不承诺永久免费中继、固定性能或可付费保障。
- 网页/短链接服务与中继分别部署和验收。网站或短码可以打开，不等于 Host 在线、访问码正确或 DERP 路径可用。

### P2-11：默认使用链接与独立临时访问码

本条适用于默认启用访问码的共享。只有发起方显式使用 P2-12 的参数，才能省略独立访问码验证。

**生成与交付**

- 每次创建新的 Leash Host 共享时，使用密码学安全随机源生成独立访问码。它不从邀请、会话 ID、时间戳或公开信息派生，不由用户填写固定默认密码。
- 启动时在专门的本地邀请展示区域清楚列出“访问码”和“分享链接”。官方默认受保护 Leash 显示六位短链接和紧凑二维码；两者都不携带访问码，扫描后仍需输入访问码。复制链接与复制访问码应是明确分开的操作。
- 访问码仅在本次 Host 和正在使用的浏览器页面内存中持有，除明确的本地交付和用户主动复制外，不进入诊断日志、JSON 事件日志、错误、遥测、进程参数、环境变量、配置文件、落盘记录或浏览器持久存储。测试和文档只使用明确标记的合成材料，不采集真实邀请或访问码作为证据。

**Host 执行认证**

- 访问码验证在原生 Host 执行，通过已有 Tailcat 端到端加密连接完成。网页、短链接服务、DNS 和官方 DERP 不承担密码校验，也不增加 TailMouse 账号服务或密码数据库。短链接服务可以按本 PRD 的有限租约明文保存完整邀请，但不得接收、派生、验证、记录或保存访问码；访问码不得作为网页请求、HTTP 查询参数或明文中继载荷发送。
- 浏览器输入框只是交互入口。Host 在认证完成前只能交换必要的握手、版本和认证信息，不发送终端实时输出、缓存历史、标题、PID、任务状态或退出结果；不执行输入、尺寸调整、终止、重启或浏览器触发的首次启动。
- 认证成功后才允许竞争唯一活跃远端名额，并按既有权限发送数据、执行操作。每条新网络流必须重新认证，不能凭“曾连接过”、已知会话 ID 或有效 HELLO 跳过。只读邀请也必须认证，认证成功不扩大其只读权限。

**防猜测与资源边界**

- Host 按共享会话累计认证失败并执行限速、退避或有限冷却；重新建立连接或更换远端连接身份不能重置全部失败预算。不能只依赖 DERP 对端 IP 限流。
- 未认证连接具有数量、等待时长、输入大小和处理资源上限。超时、取消、格式错误或认证失败只清理当次连接；不得结束共享、触发断线杀进程策略，或驱逐已认证远端。
- 冷却必须可结束，不采用永久锁死整个共享的规则。页面明确提示可重试状态；本地操作和主动结束共享仍可使用。访问码长度、字符集、随机强度、失败预算和冷却参数必须在后续 OpenSpec 中给出可验证数值，结合长期共享的猜测风险确定，不能直接假定短数字码足够。

**有效期与撤销**

- “临时”表示仅属于这一次 Host 共享，不表示几分钟后过期。同一共享仍有效时，浏览器离开、长时间无人连接、子进程退出进入结果保留或明确重启子进程，都不轮换访问码。
- 新页面重新输入同一访问码；同一页面重试遵循 P2-06。浏览器不用保持后台连接，也不增加设备记住密码或免认证接入。
- 本地结束共享、Host 退出或显式时限到达后，邀请与访问码同时失效，现有远端访问立即撤销。新的 Host 使用新访问码。结果保留期间同样必须认证；已经交付给获准用户的输出无法通过撤销收回。

这项设计针对“仅链接泄露就能访问”的风险；链接本身已有随机连接凭据，并非可随意猜中的公开终端地址。若链接与访问码同时泄露，持有者仍可能取得该共享的权限；两者不是账号身份核验或多因素认证，也不提供受控命令的安全隔离。现有网页与 Host 的完整性要求仍然成立。产品帮助应提示分开交付与保管，不宣传绝对安全。

### P2-12：显式无密码参数与强制警告

Leash 参数 `--no-password` 仅在发起方本次启动时显式启用才关闭独立访问码。未传该参数时仍自动生成访问码；本阶段不增加可长期遗留在环境变量或配置文件中的关闭开关：

```sh
tailmouse leash --no-password -- bash
```

- 无密码模式不生成访问码、不显示虚假的密码输入框。Host 仍验证邀请、协议、有效期与权限，只有获准接入的连接才能占用活跃远端名额、接收输出或控制任务。完整邀请成为唯一接入凭据。
- CLI 必须在展示邀请之前输出醒目的 warning，说明“未启用访问密码，任何持有完整分享链接的人都可按本次共享权限查看或控制终端”。只读共享也必须警告，不能误称持有者获得写入权限。
- `--quiet` 不得隐藏此 warning。JSON 输出模式必须保留等价的结构化 warning，不包含邀请、访问码或终端内容。显式参数本身就是用户选择，不新增交互式确认、倒计时或强制输入 `yes`。
- 浏览器根据 Host 通过加密连接明确声明的访问模式，显示并保留“未启用访问密码”的提示。界面不能把无密码状态显示成已通过密码验证，也不要求用户重复确认才能操作。
- 访问模式由 Host 启动配置决定，在同一次共享中固定。浏览器、邀请的可编辑字段、认证失败或网络故障都不能把有密码共享切换为无密码。不得因旧端不支持认证而自动启用此参数的效果。
- 关闭密码不关闭端到端加密、邀请保护、只读限制、单个活跃远端、连接资源上限或本地撤销。仅凭完整链接即可使用本次权限的风险，由上述 warning 清楚告知。
- 在同一共享中再次接入仍无密码，保持原任务及结果保留规则。本地结束或显式到期后旧邀请失效；新的 Host 未再次显式传入该参数时恢复默认访问码保护。

## 6. 生命周期与优先级

这是产品层的状态划分；下一份 OpenSpec 再决定复用哪些现有实现状态。每次接入必须满足 Host 在启动时确定的访问模式：默认验证访问码，显式 `--no-password` 时验证完整邀请及其他握手条件。共享结束使邀请与已启用的访问码同时失效。

| 事件                       | 共享会话                         | 任务与结果                                     | 下次接入               |
| -------------------------- | -------------------------------- | ---------------------------------------------- | ---------------------- |
| 浏览器正常离开或连接失效   | 保持开放，清理当前连接           | 默认继续运行                                   | 原始邀请可再次使用     |
| 长时间没有任何浏览器       | 保持开放                         | 持续读取并限制输出缓存                         | 无隐藏的离线时长截止   |
| 任务退出                   | 进入结果保留                     | 记录结果，释放已完成任务的底层资源             | 查看结果，不自动重启   |
| 用户主动重启任务           | 保持同一共享会话                 | 创建新的明确任务代次                           | 查看新代次及其最近输出 |
| 显式结果保留期限到达       | 结束共享                         | 清理保留结果                                   | 旧邀请失效             |
| 显式总 TTL 到达            | 结束共享                         | 按显式进程策略处理                             | 旧邀请失效             |
| 本地主动结束或 Host 退出   | 结束共享                         | 按既有关闭策略清理                             | 旧邀请失效             |
| 单次连接尝试超时           | Host 会话不因此结束              | 不改变任务状态                                 | 用户可以稍后再试       |
| 访问码缺失、错误或认证超时 | 清理当次连接，保留共享级失败预算 | 不启动、控制或泄露任务与结果；不影响已认证远端 | 有限冷却后可重新验证   |

总 TTL、结果保留截止和本地主动结束均优先于“默认持续保留”。存在多个截止条件时以最先发生的为准。任何再次接入都不能把终态重新变成开放状态。

同一版本的 native/browser 配对必须通过完整场景。Leash 认证与无密码模式需要显式协议设计，不能将访问码直接塞进当前不接受该字段的 HELLO。新浏览器遇到无法确认本次访问模式的旧 Host，应拒绝进入并提示升级；新 Host 遇到不支持本阶段访问模式协议的旧浏览器也应拒绝接入。版本或能力不匹配时不得静默降级为仅链接访问，更不能把旧 Host 缺少认证能力解释为发起方选择了 `--no-password`。显式无密码是新 Host 的本地配置，不是兼容回退。Escape 的兼容与行为不受此 Leash 要求改写。

| AC-40 | 创建官方默认受保护 Leash，并检查链接、二维码和错误路径                            | 链接为六位区分大小写 Base62；QR 可扫描且按实际短 URL 紧凑渲染；创建失败时子进程未启动且不静默回退完整链接                 |
| AC-41 | 检查短链接服务的存储、日志、缓存和网络输入                                        | 服务仅明文保存有界邀请、定位码、租约和管理凭据校验值；不接收访问码，不缓存邀请，不在日志/错误/指标中输出敏感材料          |
| AC-42 | Host 正常结束、撤销、到期和异常崩溃                                               | 正常结束立即删除活动映射；崩溃或断网停止续租后最多在当前 15 分钟租约内可解析，到期由 alarm 清理；浏览器访问不续租；恢复副本边界见下文 |
| AC-43 | 并发创建、大小写错误、碰撞、枚举和删除/读取竞态                                   | 分配原子且不覆盖；大小写变体不存在独立分配的精确匹配时，与其他不可用码统一失败；请求与重试有界；删除先发生时后续读取不能返回邀请 |

时限边界应使用可控制时间的确定性测试；同时保留真实 Host、真实终端和浏览器的延迟再次接入验证。真实运行时长与模拟时间分别记录，不将模拟四小时写成四小时实机运行证据。

每个已声明支持的平台执行对应进程和生命周期验收。移动浏览器测试应覆盖锁屏、页面被回收与重新打开原始邀请；仅桌面浏览器模拟不能替代全部移动设备证据。具体 CLI/Agent 程序的兼容性按程序实测记录，不能仅因能启动一个命令就宣称全部兼容。

## 9. 公网入口、托管与 DNS

### 9.1 三种地址各自做什么

| 地址                               | 作用                                                | 谁需要配置                             |
| ---------------------------------- | --------------------------------------------------- | -------------------------------------- |
| `https://tailmouse.com/`           | 预留官网、下载与使用说明；不必有 `www`              | 产品站点运营方，具体官网发布另行安排   |
| `https://link.tailmouse.com/`      | TailMouse 浏览器客户端；受保护 Leash 短链接与有界解析 | 产品发布方绑定 R2、Worker、过期存储与 HTTPS |
| `https://tailcat.dev/derpmap.json` | 官方中继节点目录，不是 TailMouse 网页或固定会话地址 | Tailcat 默认模式读取，普通用户无需配置 |
| 所选 DERP 节点域名                 | 原生 Host 与浏览器之间的中继通道                    | 由 Tailcat 与邀请中的区域信息处理      |

```text
浏览器 -- HTTPS --> link.tailmouse.com 的网页与短链接边缘
                         下载 R2 中的网页、JavaScript、Wasm
                         仅解析受保护 Leash 的六位短码

本机 CLI <-- Tailcat --> 官方 DERP <-- Tailcat/Wasm --> 浏览器
             命令、环境、进程和有限输出仍由本机 Host 持有
```

两端主动建立所需出站连接。`link.tailmouse.com` 不把域名解析到用户电脑；短链接映射只把六位码解析为完整邀请，实际连接仍由浏览器按邀请通过 Tailcat 完成，服务不代理或分配终端流量。

**observed，2026-09-03：** [官方 map](https://tailcat.dev/derpmap.json)当前列出：

| 区域     | 节点域名         |
| -------- | ---------------- |
| 纽约     | `tc301a.ipn.dev` |
| 旧金山   | `tc302a.ipn.dev` |
| 法兰克福 | `tc303a.ipn.dev` |
| 东京     | `tc304a.ipn.dev` |

这些是查询时的公开节点，不是长期不变的部署配置。不把其 IP 或域名作为 `link.tailmouse.com` 的 A/CNAME 目标；默认自动选区，也不保证某个用户一定选择东京。当前浏览器只走中继，官方公开服务按尽力提供并限速。[上游说明与服务边界](https://github.com/tailscale/tailcat#readme)

### 9.2 子域名和分享链接

官方默认受保护 Leash 的分享链接为 `https://link.tailmouse.com/T6wxZ8` 形式：路径恰好六位、使用 `[0-9A-Za-z]` 且区分大小写。短码只定位服务端保存的完整邀请，不包含或替代独立访问码。网页解析后把邀请保留在当前页面内存并清理可见短路径，不把邀请写入浏览器持久存储或缓存。

服务可以在有效租约内明文保存完整邀请，因此产品必须明确披露 Cloudflare 运营边界。服务绝不接受或保存访问码。每条映射租约为 15 分钟；Host 每 5 分钟续租，浏览器读取不续租。Host 撤销、显式到期、结果保留结束或退出时立即请求强一致删除；Host 崩溃或断网时，停止续租后的当前租约到期立即停止解析，alarm 自动清理活动存储。即使 alarm 延迟，读取和续租也必须直接检查截止时间。

**存储边界核验，2026-09-07：** Cloudflare SQLite Durable Objects 提供最长过去 30 天的时间点恢复；公开文档未保证 `deleteAll()` 同时立即擦除所有恢复副本。因此“15 分钟”是短链接的活动租约与解析期限，不是云平台物理介质或恢复副本的擦除保证。TailMouse 不建立邀请归档、不提供恢复接口，运营不得恢复历史邀请存储；活动数据删除失败时保留后续 alarm 清理机会。访问码仍完全不进入 Cloudflare。

Escape、显式 `--no-password` 和非官方自托管入口继续使用 `/#/v1/<base64url-cbor>` 完整邀请。六位码只有约 35.7 bit，不能在缺少独立访问码时作为唯一授权凭据。任何短码创建失败均在子进程启动前明确失败，不静默回退成长链接。仅保留普通首页不能找回会话；页面清理地址后，需要重新打开原始短链接或完整邀请。

### 9.3 静态托管与解析步骤

**observed，2026-09-07：** `link.tailmouse.com` 已通过 Cloudflare R2 自定义域名发布经过清单验证的静态产物，`r2.dev` 已关闭，最低 TLS 1.2，原始 Wasm、Brotli/gzip、MIME、缓存与安全响应头已验证。Pages 的 25 MiB 单文件限制不再是当前发布路径。官网 `tailmouse.com` 与 `www` 留到 V3，不属于此入口。

短链接增量需要在同一官方域名前增加一个最小 Worker，并通过 R2 binding 返回原有精确静态对象；不能重新打包、截断或修改 Wasm。每个六位码使用独立、强一致且可设置 alarm 的存储实例。Workers KV 的最终一致性不满足立即删除，所以不作为这项敏感映射的存储。

**开发部署流程确认，2026-09-09：** 用户明确正式域名当前用于上线前开发/测试，尚非线上业务，以原地诊断、修复、按需重新部署并重测替代 2026-09-07 的失败立即回滚要求。失败不自动移除路由或恢复旧静态版本；必须保留失败结果，保持存储类及到期 alarm，不得因部署可访问就宣称验收完成。本地真实 Worker 验证与干净发布包仍须先于公网部署，配置不开放预览域名，API 仍只接受正式 origin。功能、安全和公网验收要求不变，新 CLI 正式交付前须全部验收通过。

开发部署与验收必须完成以下步骤，本地验证和发布包检查先于公网部署：

1. 从干净源码构建 Native、Web 和 Worker，验证 Tailcat v0.6 gitlink、静态清单、许可证、SBOM、覆盖率与完整 gate。
2. 在不使用 Cloudflare 账户凭据的本地真实 Worker/SQLite 运行时验证创建、解析、续租、即时删除、alarm、限流、错误统一、`no-store` 和日志脱敏，保留前一静态清单与路由/规则作为可核对的变更记录，不因测试失败自动恢复。
3. 在正式域名的开发/测试部署中发布已验证 Worker、SQLite Durable Object 配置、R2 binding、创建/读取限流及 15 分钟删除 alarm，并将 `link.tailmouse.com` 绑定到该 Worker；不新增预览域名或服务。
4. 使用合成邀请完成公网大小写、创建、解析、续租、即时删除和自然到期验收，复核所有静态对象的字节、编码、MIME、缓存、安全头、TLS、未知路径 404 和完整 fragment 流程；测试结束不得保留活跃映射。
5. 运行真实受保护 Leash 的短链接、二维码、独立访问码、重连和 Host 结束删除验收。全部通过后才正式交付新版 CLI；任一验证失败须记录并停止该次验收，在原部署定位、修复、按需重新部署后重测，不自动回滚，不把部分通过或开发部署描述成完整发布。

按 [静态自托管说明](../web-self-hosting.md)部署的 Nginx 或其他静态站点继续使用完整 fragment，不需要实现官方短链接 API，也不运行用户命令或 TailMouse 会话服务。使用子域名不要求新增 `www`，也不需要在 DNS 填写官方 DERP IP。

### 9.4 CLI 与公网发布的一致性

V2 默认网页地址为 `https://link.tailmouse.com/`。短链接正式发布后，以下显式参数与默认值等价，默认受保护 Leash 生成六位短链接。当前新源码已采用该行为，但服务尚待公网验收，不能把先前已验证的静态站点当作短链接 API 已上线的证据；上线前本地测试须显式使用已启动的本地静态地址。

```sh
tailmouse leash --web-base-url https://link.tailmouse.com/ -- bash
```

本例只指定网页地址，不改变 V2 默认随 Host 存活的共享期限、独立访问码认证或断线后保留任务的规则。正式发布必须同步默认地址、帮助、示例与官方构建，不让普通用户每次输入 `--web-base-url`；非官方自托管配置仍按原优先级生效并使用完整 fragment。网页与 native 产物必须满足认证及协议兼容要求；新网页不会为旧 Host 补上密码保护，也不能把 V1 的旧时限说明当作 V2 默认行为。

部署完成记录应包含 Worker/存储版本、R2 静态身份、正式路由、DNS、HTTPS、资源大小与编码、删除/过期验证、真实 Host/浏览器连通结果及核验日期。开发预览、公共 DNS 或本地构建都不足以单独证明完整公网体验可用。

### 9.5 Wasm 的职责与首次接入成本

**reported，2026-09-03：** 用户质疑大体积 Wasm 对首次打开的影响，并要求核实其必要性和缩减办法。

当前方案在浏览器中运行 Tailcat 的 Go/Wasm 客户端。它通过 WebSocket 连接 DERP，处理 Tailcat 建连、WireGuard 加解密和用户态网络栈，再把有序字节流交给 TailMouse 协议与 xterm。DERP 转发加密网络包，不会自动把它们转换成网页终端可显示的文本。目标 CLI 仍在 Host 执行，Wasm 不在手机上运行该 CLI。

当前架构不能直接删除 Wasm。若改成普通 JavaScript 终端加自有 WebSocket 服务，需要新的服务端连接方案；若在浏览器重写兼容 Tailcat 的轻客户端，则需要另行实现和维护协议兼容。这两种都属于新的架构选项，没有在本阶段接受为实施变更。

**observed，2026-09-03：** 当前本地同一份构建的大小如下；这些是产物测量，还不是公共站点下载实测：

| 产物        | 字节数     | 大小       |
| ----------- | ---------- | ---------- |
| 原始 Wasm   | 27,136,514 | 25.879 MiB |
| gzip 版本   | 6,284,332  | 5.993 MiB  |
| Brotli 版本 | 5,071,424  | 4.836 MiB  |

生产静态托管正确协商 gzip/Brotli 后，浏览器可下载压缩版本，再解压、编译和初始化；并非每次必须下载约 26 MiB。已有构建提供压缩产物和静态缓存，浏览器适配器使用流式实例化。但压缩不能消除编译、运行时内存和移动设备启动成本；缓存也不能替代首次打开的验收。上传平台的原文件限制与 HTTP 下载体积是两个分别验证的问题。

现有上游构建已经使用 `-ldflags=-s -w`，并通过 Wasm 专用 build tags 排除大量不需要的功能。因此，去调试信息和基础功能裁剪不是尚未使用的优化开关。后续可比较的办法包括：

| 办法                                     | 本阶段判断                                                                                         |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 正确交付 Brotli/gzip，缓存内容哈希资源   | 优先完成公网验证；代码已有基础，不承诺每台设备一定命中缓存                                         |
| Binaryen `wasm-opt` 的体积优化           | 值得在独立候选产物上评估；需比较原始和压缩大小，并验证运行兼容，不能预先承诺缩减比例               |
| 缩小浏览器入口，仅保留实际使用的拨号功能 | 可研究的编译裁剪方向；当前上游桥接还包含监听功能，共享依赖的实际可裁剪量未知，不直接修改外部子模块 |
| TinyGo 或改写轻客户端                    | 属于适配研究；语言、标准库与运行时兼容性需要证明，不能按简单示例推断 Tailcat 也能缩成几十 KiB      |

首次体验沿用当前浏览器规范中的暖缓存 UI 小于 3 秒、普通 4G 冷缓存小于 15 秒和压缩 Wasm 小于 8 MiB 的目标，并额外记录从打开邀请到终端真正可操作的时间。分别记录界面可输入、用户输入访问码的等待、Wasm 下载与初始化、Host 认证以及终端就绪；用户输入耗时不得混入网络或初始化指标。记录设备、浏览器、网络、缓存状态、实际传输量和各阶段耗时；没有公开站点实测前，不把这些目标表述为达成结果。

资料：[Go Wasm 体积说明](https://go.dev/wiki/WebAssembly#reducing-the-size-of-wasm-files)、[Binaryen](https://github.com/WebAssembly/binaryen#tools)、[TinyGo 优化](https://tinygo.org/docs/guides/optimizing-binaries/)、[TinyGo 兼容边界](https://tinygo.org/docs/reference/lang-support/)。均于 2026-09-03 核验；本次没有执行优化器或更换编译器。

## 11. 方案取舍与实施前确认点

| 方案                                         | 判断与原因                                                                               |
| -------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 只把四小时改成更长时间                       | 仍然存在用户必须提前猜测任务时长的问题                                                   |
| 只取消总 TTL                                 | 无法解决断线三十秒后会话结束的问题                                                       |
| 强制浏览器保活                               | 不符合用户锁屏、关闭网页和稍后查看的实际行为                                             |
| 将断线宽限延长到几小时                       | 仍把再次接入绑定到隐藏截止，不符合本阶段默认持续可接入的目标                             |
| 继续使用固定容量的最近输出缓存               | 本阶段采用；实现已有基础，资源随配置有明确边界                                           |
| 仅按输出行数限制缓存                         | 不作为唯一容量限制；超长行和终端改写使内存上限不明确                                     |
| 完整记录所有历史或恢复 Host 重启前状态       | 超出本次用户需求，留待出现实际使用证据后评估                                             |
| 以通用 CLI 为主入口，AI CLI 作为重要示例     | 本阶段采用；按实际终端兼容性验证，不要求按厂商接入                                       |
| R2 网页加官方 DERP                           | 本阶段采用且当前 macOS 路径已验证；短链接切换后仍须复核静态字节与真实公网接入             |
| 把网页域名指向官方 DERP                      | 不采用；中继不会因此托管 TailMouse 网页，也没有该域名的站点绑定                          |
| 自建终端流量中继                             | 不采用；Tailcat/DERP 已承担加密终端流量，不让短链接服务接触终端数据                       |
| 受保护 Leash 的六位短链接服务                | 本阶段采用；短码仅定位，独立访问码仍由 Host 验证；接受有限明文邀请存储与明确运营信任边界 |
| Workers KV 保存短链接                        | 不采用；最终一致删除不满足即时撤销                                                       |
| 强一致租约存储与到期 alarm                    | 本阶段采用；Host 正常结束立即删除，崩溃后由 15 分钟租约兜底                              |
| 等待上游 WebRTC 完成后才交付                 | 不采用；当前 CLI 体验先基于可用中继验收，直连收益单独验证                                |
| 长期共享仍仅凭链接访问                       | 不作为第二阶段 Leash 默认方案；链接泄露即交出权限，未满足用户要求                        |
| 独立随机访问码，由 Host 通过现有加密连接验证 | 本阶段采用；覆盖仅链接泄露，无需增加账号或业务服务器                                     |
| 发起方显式 `--no-password` 并给出 warning    | 作为用户明确要求的可选模式；保留默认保护，告知完整链接即授予共享权限；不作为自动兼容回退 |
| 仅在网页添加密码框，由前端决定是否展示终端   | 不采用；绕过网页即可跳过检查，Host 仍会泄露输出或执行控制                                |
| 访问码自动按几分钟或四小时过期               | 不采用为默认值；与稍后返回的目标冲突，访问码随共享有效期结束                             |

后续实现提案需要解决以下具体问题，但不得因此偷偷收窄本 PRD 的用户体验：

1. 为“结果保留到 Host 退出”选定明确的配置表达，同时保留现有 `--post-exit-ttl=0` 的立即结束含义。
2. 明确旧 Leash `--reconnect-grace` 及配置文件字段的迁移或弃用方式，避免静默改变显式配置。
3. 核实客户端是否需要新增能力声明才能准确表达 Host 的保留策略，并确认协议兼容范围。
4. 验证有限字节回放在目标 TUI 中的截断行为；如果需要额外屏幕恢复机制，应单独说明收益、成本与范围，不能未经设计直接引入终端模拟服务。
5. 保持已发布 R2 静态对象的精确身份，验证 Worker + R2 binding 切换不会改变文件大小、响应头、编码、缓存、TLS 或未知路径行为；开发/测试中失败则原地修复、按需重新部署并重测，不自动回滚或宣称完成。
6. 确定首批 Shell、TUI 和 AI CLI 的版本与平台实测矩阵；明确官方客户端接入主路径与现有 Escape 入口的呈现方式，不变更 Escape 已接受行为。
7. 确定访问码的字符集、长度、最低随机强度和安全验证方式，以及共享级失败预算、退避、有限冷却、未认证连接数量与资源上限，给出长期共享下的猜测风险依据。
8. 定义认证与显式无密码模式的消息、协议版本或能力声明、对本次共享和连接的绑定、准入及首次启动的先后关系；验证 Host 对模式的决定权、旧端拒绝降级、只读约束和撤销期间并发请求的处理。
9. 明确本地邀请与访问码的展示、分别复制及非交互调用的凭据交付方式，保持敏感材料不进入日志、参数或持久存储；不得为了方便复制将访问码重新合入邀请。
10. 验证六位 Base62 只作为受限速定位符；定义 15 分钟租约、5 分钟 Host 续租、管理凭据、创建碰撞上限、读取/创建限流、浏览器不续租、即时删除及 alarm 清理的可观察行为。

## 12. 交付顺序与完成定义

1. 完成并验收当前版本，保留原 PRD 及本阶段实施前的行为记录。
2. 基于本文件建立独立 OpenSpec 变更，重新核对最终代码，确认第 11 节的实现、托管与兼容事项。
3. 实现 Host 访问码认证与撤销、长期可再次接入、有限输出与结果保留，再完成浏览器和 CLI 的一致表达。
4. 完成通用 CLI 产品入口、R2 静态部署、短链接 Worker 与子域名路由，执行第 8 节的场景验收、已交付功能回归与仓库要求的发布检查。
5. 记录 observed / reported / inferred / unknown 的结果、平台和程序兼容边界，并用真实用户的“离开—返回”任务验证便利性。

完成标准：默认用一个命令生成 `link.tailmouse.com` 六位短链接、紧凑二维码和独立访问码，接收方通过 Host 认证后，用浏览器经官方 DERP 操作原机器上的终端；默认仅有短链接不能读取终端或触发操作，旧端不能降级绕过认证。短链接服务只在有限租约内明文保存完整邀请，不接收访问码，Host 结束即时删除，异常结束由 alarm 清理。发起方可显式使用 `--no-password` 省去访问码并继续使用完整 fragment，CLI 必须警告，浏览器标明无密码；其余权限与接入规则保持有效。两种模式都允许用户不调整默认时限即可离开后再次使用原始邀请，启用访问码时继续使用同一码；运行中的任务连续可操作，已完成的任务结果可查看；输出、认证尝试和连接资源有界；明确截止与本地撤销可靠生效；公共入口和目标 CLI 有实际验证；没有把尚未验证的能力写成已交付。
