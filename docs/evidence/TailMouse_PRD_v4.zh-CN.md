## 1. 版本承接与决策依据

### 1.1 V3 与 V4 的关系

V3 已定义 Native Leash 接收端及尝试直连。V4 将该能力作为必须具备的共同基础，并扩展同一共享下的文件与指定端口访问：

- 若 V3 Native 已交付，V4 复用该实现和仍适用的验收证据，补做新交互及组合场景；不开发第二套 Native Client。
- 若 V3 Native 尚未交付，V4 的实施计划必须包含它，不能假设现有版本已有 `tailmouse connect`。
- V3 的 N3-01 至 N3-12 和 AC3-01 至 AC3-30 继续作为 Native Leash 基线；本稿明确扩展 N3-01 的邀请类型以接收独立文件分享，并增加官方 Leash 短邀请解析、文件入口和端口入口。N3-03 的一个活跃远端继续用于 Leash；独立文件分享使用 N4-15 的独立有界准入。其他冲突必须在实施前逐项说明，不能静默放宽既有终端或认证要求。
- V3 官网选型保持原规划；V4 不以官网改版、Rust API、账号或新后台作为三项能力的前置条件。
- V2 短邀请服务继续负责有界邀请映射，不能借 V4 扩展成文件存储、网页代理或业务流量中转。它目前只接受受保护 Leash；独立文件／目录分享首发使用完整邀请及二维码，不默认修改现有短链 API。

## 2. 产品范围与成功标准

### 2.1 必须完成的用户工作

1. 一台电脑启动任务，另一台电脑在自己的终端接入；网络允许时实际尝试直连，不允许时经 DERP 工作。
2. 用户从手机或电脑向明确开放的目录上传材料，终端任务可以使用这些材料。
3. 用户从该目录下载任务成果；任务已经结束但共享仍有效时，也可以取回文件。
4. 用户在原生接收电脑访问 Host 明确开放的 TCP 服务，例如开发网页、API 或数据库。
5. 同一接收端可在终端、传输和端口访问之间操作；慢传输不能让退出、取消或终端交互永久失去响应。
6. 用户知道正在访问哪台 Host 的哪条共享、有哪些权限、当前操作是否完成，以及离开会保留或关闭什么。
7. 用户可只分享一个文件，接收方打开邀请后直接进入该文件的下载卡，不必理解终端或浏览其他文件。
8. 用户可只分享一个目录，接收方像浏览 Nginx 目录索引一样进入子目录、返回上级并选择文件下载；Host 不必安装 Nginx。

成功指标使用真实流程记录：接入步骤、首次可交互耗时、实际路径、文件完整性、服务访问结果、取消／撤销耗时及混合负载表现。减少步骤与性能改善是待验证结果，不是本文已观察到的产品优势。

### 2.2 平台与能力矩阵

| 能力               | Native Host                            | Native Client                               | Browser Client                                         |
| ------------------ | -------------------------------------- | ------------------------------------------- | ------------------------------------------------------ |
| 运行任务与保留结果 | 持有任务、PTY/ConPTY、有限输出         | 查看／操作同一任务                          | 查看／操作同一任务                                     |
| 尝试直连           | 复用 Tailcat 原生能力                  | 尝试 UDP 直连，DERP 回退                    | 当前 DERP-only                                         |
| 文件上传／下载     | 持有指定文件／目录，执行对象和读写限制 | 按分享类型直接进入文件界面或 Leash 本地菜单 | 按分享类型显示单文件卡、目录索引或 Leash 的 Files 页面 |
| 指定 TCP 服务      | 显式开放本机回环地址的服务             | 在接收电脑建立回环监听端口                  | 显示能力与原生接入说明，不建立本地端口                 |

Native 目标沿用 macOS 13+、Linux glibc、Windows 11，覆盖 amd64/arm64。Browser 目标沿用既有桌面浏览器与 iPhone Safari、Android Chrome。平台支持须逐项提供真实运行证据；目前 Linux/Windows 原生验收延期的事实不能被 V4 规划改写为通过。

### 2.3 首发不包含

SOCKS、出口节点、任意内网目标、UDP 端口转发、系统 VPN／路由表修改、LAN 公开监听、公网预览 URL、浏览器透明 TCP 代理、反向转发、Leash 多人终端协作、云端网盘、文件夹同步、递归目录传输、整目录打包、断点续传、自动重试写入、远程桌面、原生手机 App、桌面 GUI、账号或云端任务目录均不属于本稿范围。独立文件／目录分享允许有界的多个文件接收端，见 N4-15；这不扩展 Leash 的单远端规则。

Escape 保持原有体验，不增加 Native Escape 或文件／端口能力。共享 Shell 仍具有该进程的系统权限；文件根目录与端口白名单只约束新增接口，不构成对 Shell 的隔离沙箱。

### 2.4 单文件分享和目录索引的可行性

两种交互均可在现有 Native Host＋浏览器 Wasm／Native Client 方向上实现。Host 从本机读取授权文件，经 Tailcat 加密通道交给已认证接收端；网页负责展示文件卡、目录索引和下载状态。上游已有文件服务是复用依据，但浏览器适配、认证、目录展示和保存流程仍需开发与验证。

| 方式             | 用户看到什么                                                   | Host 开放什么                                        | 适用场景                             |
| ---------------- | -------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------ |
| 单文件分享       | 一个文件名、大小、修改时间和 Download 按钮                     | 仅启动时明确选定的普通文件，不开放所在目录或同级文件 | 发送 PDF、安装包、图片或构建产物     |
| 目录下载分享     | 类似 dir list 的文件／目录表格、当前位置、上级入口、逐文件下载 | 一个明确目录及其允许浏览的子目录，默认只读           | 分享一批资料，让接收方自行选择       |
| 接收文件目录     | 上传入口、目标说明和本次上传结果；write-only 时没有目录列表    | 一个明确目录的新增文件权限，不开放已有内容           | 手机把单个文件传给电脑，收取协作材料 |
| Leash 附带文件区 | 终端旁的 Files 入口                                            | 使用相同文件能力，但受这条 Leash 的单远端与代次约束  | 给运行中的程序送材料、取成果         |

目录索引是通过已认证通道实时获取的应用界面，不把 Host 目录上传到网页服务器，不要求公网入站端口或安装 Nginx。Host 必须在线且分享进程仍在运行；关闭窗口、休眠或网络失联可能使文件不可达。页面能打开不表示 Host 文件可下载。

首发不提供可直接交给 curl／wget 的普通 HTTP 文件 URL，不把目录中的 HTML 当作网站运行，不宣称 CDN／离线网盘能力。若未来要公网文件直链、HTTP Range 或无人值守托管，应另行定义认证、存储和部署边界。

目录列表主要复用小型元数据传输，风险较可控；主要待验证项是移动浏览器的大文件保存、内容完整性、路径约束、目录变化及多接收端资源公平性。超过 Browser 文件上限时保留元数据并显示“请使用原生端下载”，不能先传完整文件后才报无法保存。

## 3. 用户界面与基本操作约定

### 3.1 Host：一条命令建立一次共享

只使用终端时沿用 `tailmouse leash -- <command>`。文件和端口默认关闭，通过启动参数明确启用。以下是 **V4 拟新增参数，当前版本不能执行此完整示例**：

```sh
# Prepare a deliberate exchange directory on the host.
mkdir -p ./exchange

# Share one task, one file directory, and one named TCP service.
tailmouse leash --files-dir ./exchange --files-mode read-write --expose-tcp preview=127.0.0.1:3000 -- codex

# On the receiving computer; invitation and code are entered interactively.
tailmouse connect
```

前提是目标程序已在 Host 安装并配置，示例中的 TCP 服务由任务或用户另外启动，TailMouse 不替用户启动 HTTP 服务器。

拟定的 Host 参数约定：

| 参数                                       | 用户含义                                                                        |
| ------------------------------------------ | ------------------------------------------------------------------------------- |
| `--files-dir <path>`                       | 开放一个已存在的目录；相对路径按 Host 启动 cwd 解析，不自动开放整个项目或 home  |
| `--files-mode read-only`                   | 启用目录时的默认模式：浏览和下载，禁止上传                                      |
| `--files-mode write-only`                  | 接收新文件，禁止浏览和下载已有文件                                              |
| `--files-mode read-write`                  | 浏览、下载和上传新文件；首发仍禁止覆盖、删除、重命名已有文件                    |
| `--expose-tcp <name>=<loopback-ip>:<port>` | 可重复声明明确的 TCP 服务；仅允许 127.0.0.1 或 ::1，IPv6 采用带方括号的地址语法 |

Host 在创建邀请、启动任务或开放远端接口前检查目录、模式、参数重复、服务名称、地址与端口边界。配置错误直接给出可修正项；不忽略失败的参数并继续共享。服务尚未监听不算配置错误，因为任务可能在接入后才启动它。

创建成功后，在受控终端的分享卡中分开展示：目标程序、文件目录及权限、已声明服务、邀请／二维码、独立访问码、当前启动策略。本机绝对文件路径不发送给接收端。保护模式凭据仍不进入普通日志或重定向输出；保护模式没有可用控制终端时，在创建分享前失败，独立文件命令遵守相同规则。

默认继续等待合法接收端完成认证及准入，或 Host 按 Enter；最多启动一次任务。配置文件传输或端口不提前触发任务。

### 3.2 Native：终端与本地菜单

`tailmouse connect` 的用户流程固定为：

1. 检查交互终端可用；没有交互终端时在联网前失败。
2. 提示“粘贴邀请链接”，隐藏输入。接受完整邀请与受支持的官方短邀请，不要求用户从链接中手工提取 Tailcat 地址。
3. 分阶段显示解析、连接 Host、认证和接入结果。官方短邀请解析另列阶段；完整邀请不请求网页、不加载 Wasm。
4. 根据 Host 的真实模式提示隐藏输入访问码；按 Enter 明确发起认证。错误显示原因类别／冷却时间，保留重新输入入口，不后台连续猜测。
5. 完成认证及相应分享类型的准入后，Leash 显示权限与菜单提示并进入远程终端；单文件／目录分享直接进入文件界面，只有 Files、Connection、Leave，不申请 PTY、不显示假终端。Leash 默认启动策略可以在此启动尚未运行的任务。
6. `Ctrl+]` 打开 TailMouse 本地菜单；`Ctrl+C` 仍发送给远端终端。菜单包含 Terminal、Files、Ports、Connection、Leave。Terminate 与 Restart 沿用明确确认。
7. 连续输入两次 `Ctrl+]` 向远端发送一个字面的 `Ctrl+]`，不执行菜单动作。括号粘贴中的控制字节不能触发本地菜单或离开；最终解析时序在 OpenSpec 定义并验证。
8. 菜单中的文件路径、确认文字和端口配置只用于本地操作，不能落入远端 stdin；返回 Terminal 时恢复原终端呈现，不把提示文字混入程序输出。

菜单按 Host 权限开放操作；未启用的能力显示原因。菜单可以在后台传输或端口工作时打开，显示进度并允许取消。切换菜单不离开共享、不产生第二个远端、不暂停 Host 任务。完整 TUI 的进入／返回效果必须实测，不能靠重复播放原始输出假装恢复。

### 3.3 Browser：Terminal、Files、Connection

浏览器接收方打开原邀请，完成访问码输入并点击“连接”。获得准入后按分享类型路由：Leash 提供 Terminal、Files、Connection；单文件分享直接显示文件卡；目录分享直接显示目录索引或只写上传页，只有 Files、Connection。手机端可用明确标签切换，不依赖悬停或桌面右键。

- Terminal 保持现有终端与快捷按键。
- Files 在权限范围内显示目录、上传／下载入口、传输进度和取消操作；未启用时说明“Host 未共享文件”，不给无效上传按钮。
- Connection 显示任务状态、连接状态、真实路径、权限及“离开此设备”。已声明 TCP 服务显示“需要原生接收端”，提供接入步骤，不生成不可用的浏览器预览链接。

切换标签不重连、不重新认证。页面关闭或移动系统挂起可能中断网络；界面不得承诺浏览器后台继续上传、永久保持端口或恢复未完成传输。

### 3.4 权限展示

接入后的权限摘要分别列出“终端查看／输入／进程控制”“文件浏览／上传／下载”“可访问的 TCP 服务”。只读终端不等于整条共享只读：上传或访问数据库端口可能改变 Host 数据，只有 Host 明确开放的独立能力才能使用。

默认要求独立访问码。Host 显式选择既有 `--no-password` 时，分享卡及接收界面必须明确列出链接持有人可获得的全部能力；不能只提示终端权限。该模式继续使用完整邀请，不能借官方短邀请绕过受保护模式要求。

### 3.5 独立文件分享：Host 创建入口

以下是 **V4 拟新增命令，当前版本尚不支持**。命令选择本身就是明确的共享操作，不再要求启动一个 Shell 或 Leash 任务。

```sh
# Share exactly one file for download.
tailmouse share-file ./report.pdf

# Share a browsable directory; read-only is the default.
tailmouse share-dir ./public

# Receive new files without disclosing existing directory contents.
tailmouse share-dir ./inbox --files-mode write-only

# Allow directory browsing, download, and upload of new files.
tailmouse share-dir ./exchange --files-mode read-write
```

`share-file` 只授予单文件下载，不接受目录、上传模式或端口参数。`share-dir` 检查目录存在及所需权限；默认 read-only，允许显式 write-only／read-write。两者默认产生独立访问码、完整邀请和二维码；本机分享卡明确显示对象、权限以及“保持此进程运行，接收方才可访问”。

分享进程保持前台运行，默认有效至 Host 退出，用户可显式设置既有语义的 `--ttl`。Host Ctrl+C 结束分享，关闭各接收端；接收端 Leave 只退出自己的连接。下载一次不自动销毁分享，其他获准接收端可再次下载。无子进程，不提供 Interrupt／Terminate／Restart 或任务退出结果。

独立文件分享按相同凭据规则支持显式 `--no-password`；界面明确指出持有邀请即可访问所选对象。只读目录也可能包含敏感内容，Host 创建时显示实际目录和子目录范围；首发默认排除隐藏文件／隐藏目录、系统特殊项、符号链接及 TailMouse 临时文件，接口直接请求也不能绕过。明确选择一个隐藏普通文件使用 `share-file` 属于另一项具体授权。

### 3.6 接收方的目录索引页面

认证和准入前不显示文件名、大小、目录树或完整本机路径。目录分享进入后，页面按如下信息组织：

```text
Shared files                         Connected / Relay
Location: /reports/                  Refresh

Name                 Size          Modified          Action
..                   --            --                Up
images/              --            2026-09-07        Open
summary.pdf          2.4 MiB       2026-09-07        Download
archive.zip          120 MiB       2026-09-07        Use Native

Load more
```

- 表格显示类型、文件名、大小、修改时间和明确动作；时间使用接收端本地时区，并标明时区。小屏改为逐项列表，信息和操作不减少。
- 点击目录进入该目录；面包屑和 Up 只在共享根内移动，到根后不提供更上级入口。路径导航保留在页面内存，不把 Host 文件路径编码为公开站点路由或恢复记录。
- 每批按 Host 有界枚举顺序加载，首发不提供全目录排序、全局搜索或快照分页。刷新清空当前列表重新读取；Host 文件增删后可能改变下一批结果，下载前必须重检所选对象。
- 点击普通文件的 Download 才开始 U4-04 的确认／保存流程；点击目录不打包下载。HTML、脚本及文档不在 TailMouse origin 内联执行，不提供缩略图／内容预览。
- 空目录显示“此目录暂无可下载文件”；文件已删除、权限改变、目录不可读或 Host 离线显示对应错误和刷新／重试入口。
- read-only 不显示上传按钮；read-write 显示“上传到当前目录”；write-only 不显示已有列表，只允许上传到 Host 指定接收根，不提供可探测已有子目录的路径导航。
- 分享的是实时目录，不是不可变快照；普通新增文件刷新后可见。已经下载的副本不随 Host 删除或撤销而消失。

## 4. 端到端用户旅程

### U4-01：从另一台电脑接手正在运行的任务

**前提：** A 有目标 CLI 和 TailMouse；B 已安装包含 Native 接收端的同一兼容发行版；A 的共享仍有效。目标 CLI 无需安装在 B。

**流程：** A 启动 Leash 并单独交付邀请和访问码 → B 运行 `tailmouse connect` → 隐藏粘贴邀请与访问码 → 认证并取得名额 → 看到 A 的当前任务或保留结果 → 输入和 resize 在 A 生效 → B 打开本地菜单选择 Leave。

**预期结果：** B 的终端恢复本地状态，没有残留输入执行到本机 Shell；默认情况下 A 的任务继续运行。B 稍后用原邀请再次接入，接回同一任务而非创建副本。Direct／Relay 的变化不改变权限。

**失败分支：** 邀请错误、解析过期、错码、冷却、Host 不可达、会话忙碌分别有明确结果。失败不启动新任务，不踢走已接入者；用户选择改正、重试或退出。

### U4-02：用手机上传材料并交给终端程序

**前提：** A 显式开启上传目录；手机已连接。上传文件低于浏览器支持上限。

**流程：** 手机切换 Files → 点击“上传文件” → 系统文件选择器选取一个文件 → 回到页面看到文件名、大小、目标相对路径及“不覆盖已有文件”提示 → 用户确认上传 → 显示进度／取消 → Host 校验并提交后显示“已上传到共享目录” → 用户返回 Terminal，把该相对文件位置告知程序。

**预期结果：** 只有最后一步确认才开始发送；文件选择器取消不创建传输。上传不会自动把提示词或命令发送给程序，也不会执行文件。任务可使用完成后的文件，未完成文件不以最终名称出现。

**失败分支：** 无权限或过大时在传输前拒绝；同名冲突要求用户输入新名称，不提供覆盖按钮；磁盘满、权限变化、断网或取消显示失败／中断，清理本次未提交临时文件。页面关闭后的未完成上传不在重开时自动续传。

### U4-03：从 Native 上传材料并继续操作终端

**前提：** B 已接入 A，Host 允许上传。

**流程：** B 按 `Ctrl+]` → Files → Upload → 输入本地文件路径 → 显示规范化的本地来源、目标相对路径、大小和冲突策略 → 用户确认 → 传输开始 → 用户返回 Terminal 继续工作 → 再打开 Files 查看结果或取消。

**预期结果：** 本地路径按 B 的文件系统解析；Host 只接收授权目录内的相对目标路径。路径输入不是 Shell 命令，不展开命令替换。进度不混入远端 TUI。确认成功须同时满足完整性校验和 Host 最终提交。

**失败分支：** 本地文件不存在、不可读、变更或目标重名时，显示对应操作结果；不替换成其他文件、不自动重发。失败的文件操作不关闭仍健康的终端连接。

### U4-04：任务结束后取回成果

**前提：** Host 允许下载，共享仍处于运行或结果保留阶段，成果已位于共享目录。

**流程：** 用户重新认证接入 → 看到任务已结束及实际退出结果 → 进入 Files → 刷新目录 → 选择一个文件并查看大小 → 点击 Download／下载 → Native 选择本地保存路径，Browser 调用系统下载入口 → 显示传输完成与后续保存状态。

**预期结果：** 下载不重启任务。Native 校验完成后以不覆盖方式提交本地文件。Browser 区分“传输已校验／已交给浏览器保存”与“已确认保存”：若系统不提供落盘结果，不显示已经保存到某路径。

**失败分支：** 本地重名要求另选路径；源文件变化或消失则失败；Host 结束共享后不能继续下载。断网发生在提交确认前后、接收端不能判断结果时，显示“结果待核对”，不得把未收到确认解释为肯定未写入并自动重试。

### U4-05：访问远端开发网页或数据库

**前提：** A 已声明 `preview=127.0.0.1:3000`；B 原生接入并取得端口权限。A 的服务可以在共享建立后启动。

**流程：** B 打开 Ports → 选择 Host 提供的 preview，不可填写任意远端地址 → 输入 B 的本地端口，例如 18080 → 确认映射 → 看到“本地监听已建立”及 `127.0.0.1:18080` → 用户自行用浏览器打开对应 HTTP 地址或让数据库客户端连接该本地端口。

**预期结果：** A 的应用协议保持原样，TCP 字节通过 Tailcat 传输；本地监听成功不表示 A 服务健康。每条实际连接分别显示成功或目标不可达。用户知道 localhost 指接收电脑 B；不会自动打开网页或伪造服务健康状态。

**失败分支：** 本地端口占用时要求更换，不杀死占用进程、不自动换端口；A 服务未启动／停止时，该连接明确失败，映射保持可供用户启动服务后再次访问；未授权服务直接拒绝，不尝试其他目标。

**结束：** Ports 中 Stop 关闭该监听及已有连接，其他映射和终端可继续。Leave、失效连接清理或 Host 撤销关闭全部本地转发；重新接入后需重新启用映射。

### U4-06：手机切换到电脑，完成完整远程工作

**前提：** A 使用带文件与 preview 服务的共享；用户持有原邀请和访问码。

**流程：** 手机接入 → 上传输入材料 → 在 Terminal 启动处理 → 手机点击“离开此设备” → B 原生接入原共享 → 操作同一任务并启动开发服务 → Ports 映射 preview → B 浏览器查看效果 → Files 下载成果 → B Leave → A 本地关闭共享。

**预期结果：** 全程只创建一个 Host 任务；手机和 B 顺序占用一个远端名额。切换前正在传输的文件需由用户等其完成或取消，不能迁移到另一设备。共享关闭后，原邀请、文件操作和端口访问均失效；已经完成下载／上传的文件保留，不被撤销操作追溯删除。

### U4-07：任务保留与显式关闭

Connection 和 Native 菜单把三件事分开：

| 用户动作                  | 用户看到的含义             | 结果                                                                               |
| ------------------------- | -------------------------- | ---------------------------------------------------------------------------------- |
| 返回 Terminal／切换 Files | 继续同一次接入             | 不断开、不重启，活动传输和映射继续                                                 |
| Leave／离开此设备         | 结束本机接入               | 若有活动文件或端口连接，确认框列出将中断的操作；确认后关闭它们，默认保留 Host 任务 |
| Terminate                 | 停止远端任务               | 需要现有权限与确认，进入既有结果保留策略；共享未结束时仍可下载成果                 |
| Restart                   | 使用 Host 原命令重启任务   | 确认框列出需先取消的活动传输与端口连接；新代次不接收旧操作或重放网络数据           |
| Host 本地结束共享         | 撤销这条共享的全部远端访问 | 关闭会话、传输与转发；任务清理继续遵守既有 Host 关闭规则                           |

没有活动传输或端口连接的 Leave 不增加无意义的二次确认。网络异常退出可能没有确认机会，清理行为相同。Host 显式配置的到期／断开终止策略继续生效，并在接入后显示，不能统一宣传“离开一定不终止任务”。

### U4-08：把一个文件分享给对方

**前提：** Host 选择一个已完成且可读的文件，接收方使用 Browser 或 Native。

**流程：** Host 执行 `tailmouse share-file ./report.pdf` → 检查成功后显示对象、完整邀请／二维码、独立访问码 → 接收方打开邀请并认证 → 直接看到该文件的名称、大小、修改时间和 Download → 明确点击下载 → 选择／接收系统保存 → 校验完成并如实显示保存状态 → 接收方离开，Host 继续分享或 Ctrl+C 结束。

**预期结果：** 无需启动终端任务，不向接收方公开父目录或其他文件，不自动下载或执行。相同链接可在 Host 在线时再次使用。单文件对象被替换、删除或检测到变化后显示不可用，不因为路径相同就自动分享另一个文件。

**失败分支：** Host 初始文件无效／超上限时在创建分享前失败；Browser 不支持该大小时提示使用 Native，尚未传输文件内容；错码／超额接入／Host 断网有明确结果。中断与未知保存结果沿用统一文件状态，不承诺断点续传。

### U4-09：像 Nginx dir list 一样挑选下载

**前提：** Host 执行 `tailmouse share-dir ./public`，目录包含文件、子目录与超过一批的条目。

**流程：** 接收方打开邀请并认证 → 直接进入目录索引 → 查看文件名／大小／时间 → 打开子目录 → Download 选中的文件 → 返回上级 → 加载更多或刷新 → 选择另一个文件下载 → Leave。

**预期结果：** 不出现终端或上传入口，目录访问不越过共享根；不会下载未选择的文件或自动打包目录。Host 后续放入普通文件后刷新可见，删除后访问明确失败。两个接收方可在独立租约与并发额度内浏览和下载，彼此离开不终止对方。

**失败分支：** 名称包含 HTML／控制字符按纯文本显示；隐藏项、链接与直接构造的越界请求均拒绝。根目录被替换后分享不可用，不能悄悄切换到新对象。Host 关闭后旧网页显示失联，点击下载不能假装仍有云端副本。

### U4-10：只把一个文件上传给对方

**前提：** 接收文件的一方在电脑上运行 `tailmouse share-dir ./inbox --files-mode write-only`，分享邀请与独立访问码。

**流程：** 发送方打开邀请并认证 → 直接看到“向此接收目录上传文件”，没有已有文件列表 → 选择一个文件 → 确认名称、大小及不覆盖规则 → 上传 → Host 提交成功后显示完成 → Host 在 inbox 查看文件。

**预期结果：** 上传不依赖 Leash；发送方不能浏览或下载接收方原有文件。名称冲突只要求换名，不返回已有文件的大小、时间或内容。成功后可再明确选择下一个文件，不能无限后台排队。

## 5. 核心产品要求

### N4-01：原生终端能力完整继承

Native 接收端复用同一个 `tailmouse` 可执行文件，支持 V3 的交互终端、Unicode、粘贴、resize、只读、进程控制、本地离开、终端恢复、有限历史和结果展示。OSC 52 等本机副作用边界不能因增加文件功能而撤销；下载文件必须走明确的 Files 操作，不能由远端控制序列触发。

### N4-02：邀请输入和短邀请解析

Native 隐藏输入支持完整邀请与严格匹配官方 HTTPS origin 的短邀请。完整邀请仅在内存解析；官方短邀请只调用受支持的固定解析 API，不请求任意主机、不跟随跨域重定向、不打开浏览器。解析失败允许用户改用 Host 明确分享的完整邀请，不自动尝试其他网址。

短邀请服务永不接收访问码；解析成功不等于 Host 认证成功。V4 协议／邀请如需新字段，必须先定义与现有 V2 API 的版本兼容，不能把新格式直接送入仅接受旧格式的接口。完整邀请在静态站点不可用而 Host／必要网络可达时仍可原生接入。

### N4-03：直连尝试与回退

Native 复用 Tailcat 原生拨号及路径发现，先通过 DERP 建连，再尝试加密 UDP 直连；无法直连时使用所选 DERP。官方或自托管中继配置从 Host 邀请继承，不要求接收方重复配置。

界面将当前接收端的连接状态与 Direct／Relay／Unknown 分开，不把另一接收端的直连探测套用于本端。探测结果标注观测时间和适用范围，过期回到 Unknown；低 RTT、同 LAN、Native 类型或一次探测均不能替代业务路径证据。路径变化不重新认证或重放数据；底层流失效时走断线清理与用户主动重新接入。

### N4-04：按分享类型准入、多个受控操作

同一 Leash 共享的 Browser 和 Native 合计一个活跃远端；只读接入也占用名额。同一已接入端可以有终端、文件传输和多条 TCP 连接，但都绑定这一次准入及当前任务代次，不因多开数据流获得第二身份或绕过忙碌限制。

上述单远端／任务代次规则用于 Leash。独立文件／目录分享按 N4-15 提供有界的文件接收端租约，没有任务代次，不创建虚假进程状态。两类分享使用明确类型，不能用文件接收端身份取得 Leash 终端或端口权限。

所有附加通道必须在 Host 检查认证绑定、准入有效性、能力、目标及资源额度之后，才能读取目录、创建文件或拨号目标。普通 Tailcat 客户端持有地址不能直接绕过 TMOUSE 访问新增接口。

### N4-05：最小文件权限与目录浏览

Leash 文件权限默认关闭；开启后只允许一个明确目录。独立 share-file 仅授权一个选定文件；share-dir 明确授权一个目录，默认 read-only。接收端看到共享根及相对路径，不看到 Host 的完整本机路径。read-only 允许分批浏览、刷新和下载；write-only 只提供上传及本次上传结果，不泄露已有文件列表或详细冲突元数据；read-write 合并前两者，不授予删除、覆盖或权限修改。

首发不自动创建远端子目录；可浏览目录的上传用户能选择根或已存在且有权访问的子目录，只写用户只能上传至指定接收根。目录列表按需分批读取，不递归预扫整个目录；文件名按文本展示，不解释为 HTML、终端控制序列或可执行操作。目录索引界面与条目处理遵守第 3.6 节，隐藏项和临时项的排除也适用于直接文件请求；目录模式的上传目标使用被排除的隐藏／保留名称时明确拒绝，不能上传成功后又让该文件不可见。

### N4-06：上传确认和不可覆盖提交

上传必须由用户选定来源和相对目标后确认；显示大小及目标目录。先拒绝超限、无权限及不支持的文件类型，再写入仅属于本次操作的临时文件。收到完整数据并通过大小／校验值检查后，以不覆盖方式提交最终文件；只有 Host 确认提交才显示上传成功。

同名竞争也不能覆盖已有文件。临时名不含邀请、访问码或管理凭据，不以最终名称暴露半成品。正常取消、失败和撤销清理本次未提交文件；崩溃可能遗留临时文件，必须说明识别和人工清理方式，不新增清理守护进程或扫描删除其他文件。

### N4-07：下载确认和完整性

每次下载由用户明确选择单个普通文件。Native 本地路径采用不覆盖提交；Browser 在支持上限内提供标准系统保存流程。传输使用明确大小及端到端内容校验值（首发建议 SHA-256），检测截断和内容错误；不得只按发送字节数判定完成。

检测到源文件在传输中变化时拒绝声称稳定成果；本阶段不提供文件系统快照，也不保证获得正在写入文件的某个原子版本。目录刷新由用户触发，不建立文件监控服务。

### N4-08：文件边界与取消

拒绝目录越界、绝对／设备路径、路径穿越、符号链接和 Windows reparse point 逃逸、替换竞态及特殊文件；读取、列目录、临时写入和最终提交使用一致根边界。平台间非法名称／大小写冲突给出明确错误，不静默改名。

取消只针对该操作；失败不关闭健康终端或其他接收端。失去父租约、撤销或 Leash 代次更换后拒绝旧块与旧提交。没有断点续传或后台自动重试；提交结果未知时由用户核对目标，不自动重发。

### N4-09：浏览器保存与隐私边界

选择文件、开始上传、保存下载均需要明确用户动作；不自动读取剪贴板或扫描设备目录，不上传文件的本机完整路径。文件内容与目录结果不进入 TailMouse 的 Service Worker、Cache API、IndexedDB、local/session storage 或遥测。

用户明确上传／下载产生的目标文件是本功能的预期落盘结果；不得把“凭据不持久化”误写成文件也不能保存。系统下载记录由浏览器负责，TailMouse 只报告其实际可知的完成状态。

### N4-10：指定目标的 TCP 转发

Host 启动时以唯一名称声明一个或多个回环 IP 与 TCP 端口。Native 只能选择这些名称，不能请求任意地址、远端局域网、公网目标、DNS 名称、Unix socket 或 UDP。

每条 TCP 连接单独检查共享、准入、能力和映射，不因为本地监听曾经成功就永久授权。转发是双向字节流，支持正常半关闭与错误传播，不解析或重放 HTTP／数据库请求，也不代替目标服务自身的认证。

### N4-11：本地端口的建立、状态与停止

Native 只监听接收电脑的回环地址。端口占用、权限不足、无权限目标明确失败，不自动改绑 LAN 地址、不请求管理员权限。菜单显示服务名称、本地地址、监听状态、活动连接数及最近非敏感错误。

建立本地监听、某次 TCP 连接成功、应用协议可用是三种不同事实。只有实际流量证明后才报告相应成功。停止映射、离开或父连接失效时关闭监听和已有连接，不留下后台代理；新接入不自动恢复旧映射。

同一接收电脑上的其他本地进程也可能访问回环监听，不能把 localhost 描述为进程级身份隔离。用户可以随时 Stop，不自动公开到其他设备。

### N4-12：终端、文件与端口的组合交互

Files 和 Ports 在 Native 本地菜单及 Browser 对应入口中操作，保持一条可发现的返回终端路径。所有确认、路径输入和进度属于客户端界面，不得发送为终端输入。

大文件、慢终端或多个 TCP 连接不能无限占用内存、阻塞认证／取消／撤销或饿死终端控制。达到额度时拒绝新操作并显示额度原因；不建立无限队列，不静默丢失文件或 TCP 字节。若通道不能继续完整传输，明确失败并清理该操作。

### N4-13：共享、任务与操作生命周期

Leash 的文件权限与端口声明归属于 Host 共享，实际操作归属于当前远端及任务代次。浏览器或 Native 离开时关闭操作并释放名额；Host 任务仍遵守 V2 原有策略。独立文件／目录分享由 N4-15 定义无子进程生命周期，不能套用 Leash 的 post-exit 或 Restart 规则。

普通子进程退出不自行撤销文件权限和端口声明：在 Host 仍保留共享时可下载成果，也可访问仍实际存在的显式服务；目标随任务退出而停止时报告不可达。共享到期、保留期结束或 Host 撤销则关闭全部新增能力。

Restart 在创建新代次前取消旧传输、关闭本地转发及现有连接；文件根与服务声明保持原 Host 配置，新操作须由用户重新发起。完成文件不因 Restart 或撤销被删除，也不承诺回滚文件操作或已经到达目标服务的请求。

### N4-14：凭据、日志与版本一致性

Host／Native／Browser 中的邀请、访问码、认证证明、附加通道授权材料仅进入必要内存及明确分享面，不进入命令参数、环境、文件、日志或可复制的诊断包。唯一既有服务端例外是 V2 已接受的受保护 Leash 短邀请映射：官方 Cloudflare 边缘可按既定有界租约暂存完整邀请明文，但不接收访问码或认证证明；活跃映射删除不等于已证明清除提供商恢复副本。本稿不将该例外扩展到独立文件分享或新增通道授权材料。Native 菜单和系统文件选择是明确文件交互，不是新增凭据存储入口。

文件内容、完整路径、用户文件名、终端内容和被代理请求不写入默认诊断；进度使用操作标识、大小、状态和错误类别。分享卡及 Files 用户界面按已授权用途显示必要名称。

新旧 Host／Native／Browser 先协商版本和能力。缺少能力时明确显示不支持；请求文件或端口不得降级成未经认证的上游服务。兼容终端的旧版本是否可以只用终端，由明确矩阵决定，不自动宣称兼容。

### N4-15：独立文件分享和有界多接收端

share-file 与 share-dir 运行在同一 `tailmouse` 可执行文件内，创建明确类型的临时文件分享，不创建 PTY、任务结果、后台服务或端口授权。默认直到前台 Host 退出有效，可显式设置总 TTL。完整邀请可重复使用；首发不使用仅支持 Leash 的 V2 短链接映射，不自动注册新的云端接口。

独立文件分享首发建议每条分享最多 4 个已准入接收端，每个都重新完成 Host 认证并取得自己的内存租约。认证失败／冷却预算按整条分享累计，未认证资源有硬上限，不能用并发连接重置猜测预算。超过接收端额度显示忙碌，不驱逐现有接收端；不新增用户账号、成员列表或身份管理。

接收端只能取消自己的传输、关闭自己的连接。Host Ctrl+C、总 TTL 到期或本地撤销结束全部租约和未完成操作；一个接收方离开或崩溃只清理其操作，其他接收方不受影响。传输额度同时具有每端与全分享上限，达到上限明确拒绝，不能让一个无限请求者耗尽 Host 资源。

### N4-16：单文件对象与目录索引的一致性

单文件分享仅允许读取启动时明确选定的对象；不能通过修改文件名参数读取同级文件，也不提供父目录列表。后续请求检测对象被删除／替换时失败，不沿同一路径自动分享另一个文件；传输中变化仍按 N4-07 处理，不承诺文件快照。

目录分享固定授权根及其被允许的子目录，Host 内普通文件变化由接收端刷新可见；根对象被替换、变成链接或权限失效时停止访问。列表数据只是当时观察，真正下载／上传时重检对象、权限与边界，不能把曾列出过的名称当作永久授权。

目录索引不解释 index.html，不以内联方式执行下载内容。选择哪个文件、保存到哪里、上传到哪里均保持明确用户操作。只有明确增加上传权限，目录页才出现上传入口；“像 dir list”不能默认为远端文件管理器。

## 6. 默认值、上限和状态定义

以下为首发建议值，必须在实施前结合真实平台验证并冻结；失败时调整产品边界和验收，不靠无界缓存实现。

| 项目              | 首发建议                                                                                           |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| 文件对象          | Leash 可选 1 个目录，默认关闭；独立分享为 1 个文件或 1 个目录，目录默认 read-only                  |
| 文件传输方式      | 单个普通文件，禁止覆盖；不做递归传输／压缩／同步／续传                                             |
| 单文件上限        | Native 1 GiB；Browser 64 MiB，上传和下载均在开始前展示并检查                                       |
| 接收端数量        | Leash 合计 1 个；独立文件／目录分享最多 4 个已认证端                                               |
| 活动传输          | 每端最多 1 个上传＋1 个下载；Leash 全分享最多 2 个，独立文件分享全分享最多 4 个；不设后台等待队列  |
| Native 文件缓冲   | 每进程 TailMouse 自有文件在途和排队缓冲合计不超过 8 MiB，不随接收端或文件大小增长                  |
| Browser 文件内存  | 上传分块；下载允许最多 64 MiB 的明确有界保存缓冲，其他传输缓冲合计不超过 8 MiB；运行时开销单独测量 |
| 目录读取          | 每批最多 100 项，响应大小必须有硬上限；不扫描完整目录以伪装分页；不提供首发全局排序／搜索          |
| 端口映射          | 每条 Leash 最多声明并启用 8 个名称；仅 TCP、Host 回环目标、Client 回环监听；独立文件分享不开放端口 |
| 活动转发连接      | 每条共享合计最多 8 条，超额连接拒绝，不建立无界待连接队列                                          |
| TCP 自有缓冲      | 每方向每连接不超过 256 KiB，全共享不超过 4 MiB，计入在途数据                                       |
| Native 接入超时   | 沿用 V3 60 秒连接基线，人工输入等待单独计算；短邀请解析另有 10 秒预算                              |
| 单次 TCP 目标拨号 | 最多 10 秒，失败明确返回；不暗中遍历其他地址                                                       |
| 文件无进展等待    | 60 秒无有效进展则明确失败，不以总文件耗时替代空闲超时                                              |
| 取消／停止反馈    | 客户端在 1 秒内显示正在取消／停止；健康本地环境中的受控操作 5 秒内完成清理，不能未确认便显示完成   |
| 父连接失效检测    | 沿用已交付活性期限，当前为 30 秒有效 PONG 期限；检测后清理所有子操作，不另建永久租约               |
| 路径探测展示      | 标注最近探测时间；首发建议超过 10 秒未更新即 Unknown，探测不等于全部业务流路径证明                 |

文件进度使用 `等待确认 → 传输中 → 校验中 → 提交／交付保存 → 完成`，另有 `取消中／已取消／失败／结果待核对`。完成后不继续展示可取消；收到取消时若已提交，显示已完成，不能误报已回滚。

端口状态使用 `未启用 → 本地监听中 → 停止中 → 已停止`，目标连接结果独立显示。初次目标失败不把整个终端标成离线；父连接丢失则关闭监听，不保留表面可用的代理。

## 8. 实施设计必须解决的问题

本稿不固定线上消息布局、数据流数量或新依赖。进入实现前，独立 OpenSpec 必须给出以下具体设计，并证明它们满足上面的用户流程：

1. Native 接入、菜单键位、粘贴识别、输出恢复及本地退出码；菜单不能破坏目标 TUI 或吞掉未说明的按键。
2. Host、Browser、Native 和短邀请 API 的版本／能力协商，V3 Native 的继承清单，Leash／单文件／目录的明确类型，以及旧端仅使用终端时的兼容边界；独立文件邀请不误用现有 Leash-only API。
3. 附加文件／TCP 通道如何绑定已认证远端、共享和代次，防止原始上游入口绕过应用认证；绑定材料的重放、撤销及资源约束。
4. 文件是否复用上游受目录约束的服务或采用窄应用协议，尤其是浏览器如何接入；不能因为上游有 SFTP 就声称浏览器天然支持。
5. 跨平台单文件身份／目录根约束、不覆盖提交、读写变化检测、完整性校验、未知提交结果以及无后台清理服务时的残留说明。
6. Native 与真实移动浏览器在建议文件上限下的内存和保存能力，逐平台列出实际限制；不在超限时偷偷创建磁盘缓存或外部上传服务。
7. TCP 的拨号、回环绑定、半关闭、并发额度、停止和父会话联动；文件／TCP 与终端之间的有界调度，避免批量数据饿死控制交互。
8. 每项超时／限额的最终值与可观测证据，路径探测和真实业务路径证明的区别，真实直连与 DERP 回退的测试方法。
9. 目录有界枚举与导航、隐藏项过滤、多接收端租约与公平资源上限；共享级猜测预算复用，但不得借文件接收端多名额绕过 Leash 单远端限制。

复用既有 Go 可执行文件、Web 客户端及 Tailcat 适配边界。没有当前验收需求的新进程、工作区、通用代理框架或网络服务不得仅为“以后扩展”加入。若必须添加依赖，先说明现有公开 API 和标准库为什么无法满足具体场景。Tailcat 源码与 gitlink 的变化需要独立明确授权，V4 PRD 本身不授权更新上游。
